# 毕业设计选题细化讨论稿实施计划

## Summary

在不修改现有 `prototype.md` 的前提下，新建：

`MasterGraduationProject/Design/design_prototype/毕业设计选题细化与研究方案讨论稿.md`

文档定位为下一轮导师沟通使用的研究方案讨论稿，不直接冒充开题报告定稿。它将把 `prototype.md` 中“缓存管理 → 算力管理 → 多租户负载均衡”的三个聚焦点细化为一条可实现、可验证的统一闭环，并同时给出：

1. 一套完整推荐方案；
2. 4 个月、2–4 张 GPU 约束下的最小可行裁剪；
3. 时间和后端能力允许时的高风险增强项；
4. 需要导师拍板的少量关键问题。

成功标准是：每个研究点均明确研究对象、输入与输出、状态/接口、核心算法、形式化目标、对照基线、评价指标、风险与降级方案；三个研究点之间存在明确的数据依赖与消融关系，而不是并列罗列功能。

## Current State Analysis

### 1. 当前原型的有效主线

`prototype.md` 第 97–121 行已经给出导师讨论后的主线：

- 缓存管理回答“保留什么”；
- 算力管理回答“配置多少资源”；
- 负载均衡回答“先服务谁、请求送到哪里、何时放弃缓存亲和性”。

这条主线比初稿的“时延预测 → 语义短路 → 缓存替换”更适合作为系统论文框架，但目前仍停留在聚焦点层面。

### 2. 需要在新文档中解决的缺口

1. “上下文、RAG 知识、历史回答、前缀 KV”混用“语义库/缓存”概念，缺少统一状态模式、权威数据源、复用边界与失效传播关系。
2. 现有缓存替换方案是 LightGBM 分数与 Count-Min Sketch 分数的固定加权，尚未解释冷启动、样本增多后的置信度变化以及四类异构状态如何比较。
3. 算力管理只提出调节并行度和批次，没有说明缓存预算、质量风险、重配置成本如何进入同一个优化问题。
4. 调度层只有 Session ID 一致性哈希，尚未解决缓存亲和性、队列负载、异构 SLO 和租户公平性之间的冲突。
5. 现有工作已经分别覆盖答案级语义缓存、工具/RAG 结果缓存、跨轮 KV 剪枝、引擎内分层 KV、SLO 调度和 locality-aware fairness；不能把任一单项机制直接包装为创新。
6. Flink checkpoint 只能保证 Flink 管理的状态，不能保证外部 vLLM KV 张量和在途推理调用天然 exactly-once；必须明确控制面与数据面边界。

### 3. 可复用的现有材料

- `Design/缓存内容深度探索_综合分析_v2.md`：四类缓存边界、语义状态与 KV 状态的张力、Flink 控制面边界。
- `Design/prefix_kv_cache_exploration.md`：前缀 KV 分层、复用条件、失效与在线路由候选。
- `Paper/paper_ interpretation/vCache调研报告.md`：答案复用的错误率预算与逐条目阈值。
- `Paper/paper_ interpretation/Cortex调研报告.md`：只读知识结果的语义验证、时效性与缓存管理。
- `Paper/paper_ interpretation/IntentKV调研报告.md`：跨轮 KV 留存的已有边界与动态预算空白。
- `Paper/paper_ interpretation/JITServe调研报告.md`：不确定信息下的 SLO goodput、运行时精化与调度基线。
- `Paper/paper_ interpretation/Strata_OSDI26_精读报告.md`：cache-aware scheduling、delay hit 及引擎内/控制面分工。

## Proposed Changes

### 新建文档的结构

#### 1. 文档定位与结论速览

- 说明这是导师讨论稿，列出已确认约束和推荐结论。
- 给出 2–3 个题目候选，推荐题目围绕“多租户 Agent、流式状态、缓存与 SLO 联合控制”，但保留当前导师拟题作为宽口径标题。
- 用一段话讲清母题：Agent 的跨轮/跨会话状态同时带来复用收益、内存成本与路由亲和性，多租户异构 SLO 又要求负载分散和公平服务，因此需要跨层联合控制。

#### 2. 研究边界与系统模型

- 系统实体：租户、会话、轮次请求、Flink 算子、推理 worker、四类可复用状态。
- RAG 限定为管线内的只读知识检索阶段，不包含任意 Agent 工具执行。
- vLLM 为主后端，不修改引擎内核；Flink 保存状态内容或控制元数据，不保存/搬运 GPU KV 张量。
- 原始 transcript 与知识源是权威数据源；摘要、embedding、回答和 KV 均是可重建派生状态。
- 定义每租户 SLO 元组：
  - TTFT 与单轮端到端时延目标；
  - 时延违约预算；
  - 质量/错误预算；
  - 租户权重与最低服务份额。
- 会话级指标采用“系统主动处理时间”，排除用户思考/外部等待时间，避免把系统不可控空闲期计入 JCT。

#### 3. 四层可复用状态的统一抽象

- 会话语义状态：原始上下文的冻结摘要块、结构化事实/偏好/约束及 supersession 链。
- RAG 知识状态：文档 chunk、embedding、版本、租户权限与 freshness。
- 历史回答状态：query-response、语义向量、验证记录、依赖版本与复用阈值。
- 前缀计算状态：精确 prompt hash、模型/tokenizer 版本、token/block 长度、持有 worker 与 generation epoch。
- 定义统一 `ReusableStateMeta`：
  - 身份与作用域；
  - 大小、位置和容量类型；
  - 内容哈希、版本、依赖；
  - 访问统计与复用概率；
  - 可避免的 GPU/时延成本；
  - 管理、刷新、重建和迁移成本；
  - 质量风险与 freshness；
  - 当前生命周期状态。
- 明确四层共享元数据与价值估计，但动作集合分类定义，避免设计四套独立算法。
- 给出依赖失效图：摘要或知识版本变化会使相关回答和精确 KV 失效；模型/tokenizer/prompt 模板变化会使回答与 KV 失效；ACL 不允许跨租户越权复用。

#### 4. 总体架构与闭环数据流

- 画出 Flink 控制面、CPU/状态后端、知识服务和 vLLM 数据面的分层架构。
- 给出单请求路径：
  - 读取租户/会话状态；
  - 检查派生状态版本；
  - 执行上下文/RAG/回答层复用；
  - 构造精确 prompt；
  - 查询 KV 驻留目录并路由；
  - 推理完成后更新四层状态与观测。
- 划分两个时间尺度：
  - 慢环：周期性或漂移触发的缓存预算、并行度和批次配置；
  - 快环：逐请求的租户排序、复用动作、worker 路由和准入。
- 明确三个研究点的接口：研究点 1 输出各层“预算—收益—风险”曲线，研究点 2 输出全局配置，研究点 3 执行并反馈观测。

#### 5. 研究点一：跨层状态价值建模与联合生命周期管理

- 研究问题：四类状态在不同复用范围、成本介质和质量风险下，如何用统一框架决定保留、压缩、刷新、验证、淘汰或重建。
- 冷启动阶段使用内容、会话阶段、租户、大小、访问间隔等静态/弱历史特征估计复用概率；样本积累后引入衰减频率、访问间隔分布与 Count-Min Sketch 趋势。
- 不采用固定权重相加，改为随样本量/置信度变化的融合：冷启动偏预测模型，暖态逐步增加在线统计权重。
- 先用质量、权限、版本和 freshness 做硬门控，再按期望可避免成本、管理成本与容量占用计算边际价值密度；不同存储介质使用独立容量约束，不能把 HBM、CPU 内存和状态后端容量直接混成一个总量。
- 给出四类动作：
  - 会话语义状态：冻结、压缩、降级、重建；
  - RAG 状态：缓存、刷新、淘汰；
  - 回答状态：直接复用、验证后复用、回源推理；
  - KV 状态：本地保留、外部层级保留（若后端支持）、重算。
- 保留单次最大替换比例、滞后阈值和最短驻留时间作为稳定性机制，并给出算法草图和复杂度。
- 输出每层在候选预算下的命中、时延/GPU 节省、管理税和质量风险曲线，供研究点二使用。

#### 6. 研究点二：面向异构 SLO 的缓存—算力联合配置

- 时延模型拆为状态查找/验证、RAG、排队、prefill、decode 和重配置影响；缓存命中与未命中采用条件分支建模。
- 预测特征包含 prompt/RAG/上下文长度、命中层级、命中前缀长度、batch、并行度、队列工作量和 worker cache residency。
- 配置变量至少包括：
  - Flink/推理并行度 `p`；
  - batch size `b`；
  - 四层预算 `B_ctx/B_rag/B_resp/B_kv`；
  - 回答复用阈值或错误预算；
  - 上下文压缩 fidelity 档位。
- 目标为最小化 GPU、内存、状态管理和重配置成本；时延 SLO、质量预算、公平最低份额、容量和队列稳定性均作为约束，不把不同量纲直接相减。
- 先由研究点一生成离散收益曲线，再复用现有 MCKP/枚举基础选择每层一个 operating point 与 `(p,b)`；MILP 作为形式化表达和对照，不把求解器复杂度变成论文主贡献。
- 加入重配置成本、滞后和冷却时间，避免频繁扩缩容；无可行配置时输出过载信号给研究点三的准入/降级策略。

#### 7. 研究点三：缓存感知的多租户公平调度

- 采用两级调度：
  - 租户级：结合剩余 SLO slack、weighted deficit 和最低服务份额，决定先服务哪个租户；
  - worker 级：估计请求在每个 worker 上的完整完成时间，比较本地命中等待、远端层级加载和异地重算。
- 给出“何时放弃缓存亲和性”的显式规则：当命中 worker 的排队/加载完成时间不再优于其他 worker 的排队+重算时间，或继续等待会违反租户最低份额/时延预算时，允许打破亲和。
- 会话稳态路由使用 rendezvous/一致性哈希减少迁移；扩缩容和 worker generation 变化后重新校验 KV 元数据，禁止相信陈旧驻留记录。
- 组批只在有界等待内偏好相同 worker/共享前缀请求，防止容易命中的租户长期挤压其他租户。
- 所有 worker 都无法满足 SLO 时，按租户策略执行快速失败、降级复用或排队，并单独统计拒绝率，不能把拒绝请求从 SLO 分母中静默删除。
- 将 DLPM/D²LPM、JITServe 和普通 WDRR/FCFS 作为边界基线，创新点限定为 Agent 会话级四层状态、质量预算和慢/快环联合控制。

#### 8. 形式化问题与算法接口

- 给出紧凑符号表和总体优化目标。
- 定义三个核心接口：
  - `StateValueEstimator -> LayerBenefitCurve[]`
  - `JointPlanner -> (p, b, budgets, thresholds, fidelity)`
  - `TenantScheduler/WorkerRouter -> (admission, reuse_action, worker_id)`
- 给出跨语义层错误预算的保守聚合方式；动态分配子预算列为增强项，基础版采用固定层级子预算并监控总错误率。
- 给出伪代码级流程，保证执行者不需要再决定请求处理顺序、状态更新时机或失败回退。

#### 9. 实验设计

- 研究问题：
  - RQ1：统一状态价值模型是否优于四层独立 LRU/LFU/静态阈值；
  - RQ2：联合配置是否比只调 `(p,b)` 或只调缓存预算更省资源并满足 SLO；
  - RQ3：两级调度是否在缓存亲和、尾延迟和租户公平之间取得更优折中；
  - RQ4：故障、扩缩容、漂移和知识版本更新时系统是否正确退化与恢复。
- 工作负载：
  - 采用已核验公开 Agent/多轮 trace 与规则式会话合成器双轨；
  - 从已核验的长对话记忆、RAG/QA、语义缓存数据集中选择可拼接的任务；
  - 为请求注入三档租户 SLO、不同 locality/Zipf 偏斜、突发负载、知识更新和分布漂移；
  - 只使用有一手来源且能在当前资源下复现的数据集，文档中不写未经核验的具体数字。
- 必选基线：
  - No-cache/FCFS；
  - 四层独立 LRU/LFU + 固定预算；
  - vLLM APC/默认路由；
  - vCache-style 回答复用；
  - Cortex-style 只读知识缓存（按可复现机制重实现，不宣称复跑原论文）；
  - WDRR/EDF、JITServe-style、DLPM-style locality+fairness；
  - Oracle。
- 消融：
  - 去统一价值模型；
  - 去联合配置；
  - 去公平约束；
  - 去缓存亲和；
  - 去质量/版本门控；
  - 固定冷/暖权重；
  - 去重配置稳定机制。
- 指标：
  - P50/P95/P99 TTFT 与单轮 E2E；
  - SLO goodput、违约率、拒绝率；
  - 任务质量、错误复用、陈旧命中；
  - 四层命中及各自贡献；
  - GPU-hours、显存/CPU/状态容量、重算 token；
  - Jain index、各租户 slowdown、最长等待；
  - checkpoint、恢复、rescale 和控制器开销。
- 报告置信区间和多次随机运行，避免只展示单次命中率。

#### 10. 相关工作边界与创新点

- 对 vCache、Cortex、IntentKV、Strata、JITServe、Continuum、DLPM/D²LPM、OpScale 分别写“已解决什么、本课题不能重复什么、可主张的新增问题”。
- 创新点只写成待实验验证的研究主张：
  1. 四层派生状态的统一依赖与生命周期框架；
  2. 质量和公平约束下的缓存—算力联合配置；
  3. Agent 会话级跨层状态感知的两级调度与亲和放弃机制。
- 不使用“首个/首次”表述，除非有系统综述级证据。

#### 11. 可行性分级与导师决策项

- 最小可行版本：
  - 四层均进入统一元数据和收益曲线；
  - 每层采用可复现的基础策略；
  - 离散联合规划；
  - WDRR + 完成时间驱动的 worker 路由；
  - vLLM 黑盒运行，不做 KV 传输或引擎改造。
- 推荐完整版本：
  - 冷/暖自适应复用估计；
  - 质量/版本依赖门控；
  - 漂移触发重规划；
  - 故障/扩缩容实验。
- 高风险增强：
  - 动态分配跨层质量错误预算；
  - 外部 KV 池迁移/预热；
  - SGLang 泛化；
  - 学习型调度。
- 文末列出导师只需决定的事项：题目宽窄、三点贡献权重、是否要求后端泛化、是否将动态质量预算纳入正式贡献。

## Assumptions & Decisions

1. 文档语言为中文，风格为严谨的学术讨论稿，篇幅按内容完整性控制，预计约 1.2–2 万字。
2. 目标读者是导师和后续实施者；正文既解释研究动机，也提供足以实施的形式化与算法草图。
3. 四类缓存全部纳入，但采用“统一模型 + 分类动作”，不设计四套互不相关的算法。
4. RAG 是只读知识检索阶段，不包含任意 Agent 工具调用。
5. SLO 同时包含时延、质量和公平性。
6. 延续现有边界：4 个月、2–4 张 GPU、Flink 控制面、vLLM 主后端、不改引擎内核。
7. Flink checkpoint 只对其管理的内容和元数据提供语义；外部 KV 与异步推理需要 epoch、幂等键和恢复协议。
8. 不修改 `prototype.md`，所有新增内容写入独立讨论稿。
9. 所有定量结论优先引用论文原文、官方文档或仓库内已经完成一手核验的调研报告；无法核验的内容标为待验证，不补造数字。

## Verification

1. **结构完整性检查**：为三个研究点逐项核对“问题、对象、输入、输出、方法、公式、算法流程、基线、指标、风险、降级方案”。
2. **闭环检查**：确认研究点一的输出能够直接进入研究点二，研究点二的输出能够直接约束研究点三，研究点三的观测能够反馈前两点。
3. **范围检查**：确认工具调用、引擎内 KV 剪枝、CUDA I/O 和任意未获支持的后端改造未被写入必做范围。
4. **状态语义检查**：逐类核对权威数据源、复用边界、版本/ACL、失效传播、恢复路径与可淘汰性。
5. **公式量纲检查**：质量风险、时延、GPU 成本和公平性采用约束或归一化后目标，不直接进行无量纲混算。
6. **相关工作检查**：逐项核对 vCache、Cortex、IntentKV、Strata、JITServe、Continuum、DLPM/D²LPM 与 OpScale 的边界，避免过强差异化表述。
7. **事实与引用检查**：验证文内链接、论文身份、会议/版本和数字来源；无法确认的数字删除或显式标记。
8. **术语一致性检查**：统一使用“会话语义状态、RAG 知识状态、历史回答状态、前缀计算状态、控制面、数据面、质量预算、缓存亲和性”等术语。
9. **Markdown 检查**：检查标题层级、表格、公式、代码块和链接格式，确保新文档可直接阅读。
10. **变更范围检查**：最终 `git diff` 应只包含新讨论稿，不改动用户已有的 `prototype.md` 与调研材料。
