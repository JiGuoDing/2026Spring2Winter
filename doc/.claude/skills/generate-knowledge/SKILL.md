# generate-knowledge

向 `doc/` 目录下的面试题 Markdown 文档中新增高质量问答条目。

## 参数

用户可以通过 `$ARGUMENTS` 传入问题文本。也可以在触发后由你主动询问。

## 执行流程

### 1. 确定目标文档

根据问题主题，映射到对应文件（均在 `/home/jgd/workplace/2026Spring2Winter/doc/` 下）：

| 关键词 | 文件 |
|-------|------|
| Flink、流处理、Checkpoint、Watermark、State、窗口 | `Flink面试题.md` |
| Redis、缓存、分布式锁、AOF/RDB、哨兵、Cluster | `Redis面试题.md` |
| MySQL、SQL、索引、事务、InnoDB、B+Tree、锁 | `MySQL面试题.md` |
| Golang、Go、goroutine、channel、GC、GMP | `golang面试题.md` |
| Ray、Ray Data、Ray Serve、Ray Core | `Ray面试题.md` |
| Kubernetes、Docker、容器、微服务、服务网格 | `云原生面试题.md` |
| 大数据、Spark、Hadoop、Hive、Kafka、HBase | `大数据面试题.md` |
| LLM、大模型、Agent、RAG、RLHF、Transformer、Prompt | `大模型面试题.md` |
| 操作系统、网络、数据结构、算法、计组 | `计算机基础.md` |

如主题跨领域或不明确，向用户确认目标文件。

### 2. 读取文档 prompt 和结构

读取目标文件的前若干行，提取 `prompt:` 部分——它定义了你必须遵守的专家角色、深度标准、格式要求。

然后扫描全文的 `##` 和 `###` 标题，掌握现有分类体系和编号惯例。

### 3. 确定插入位置

- 优先将新问题归入语义最匹配的现有 `##` 分类
- 若无合适分类，在文档末尾新建 `##` 分类
- 在同一分类内，按从基础到进阶的逻辑排列
- 编号沿用文档已有的惯例（如 `### 2.3`、`### 3.1`）

### 4. 生成回答

**你必须严格遵守第 2 步读取到的 prompt 中的全部约束。** 在此基础上，默认遵循以下标准：

**深度要求：**
- 不能仅讲表面用法，必须深挖底层原理、内核机制、设计思想
- 涉及数据结构时分析时间复杂度，涉及算法时解释为什么这样设计
- 对每个概念给出精确的技术定义

**结构要求：**
- Markdown 格式，括号统一用英文 `()`
- 善用层级标题、对比表格、代码块（带注释）、ASCII 图表组织信息
- 代码示例使用该领域主流语言，注释详细

**风格对齐：**
- 观察文档已有回答的行文风格并严格对齐。例如：
  - 是否先用一句话总结再展开？
  - 是否使用"你"指代读者？
  - 对比时是否偏好表格还是列表？
  - 代码块是否标注语言类型？
- 你新写的回答应与已有回答浑然一体，读者分辨不出是后来添加的

**尾部标配：**
1. **知识扩展** —— 列出 2-5 个关联知识点，每个一句话说明关联关系
2. **完整口头回答** —— 一段连贯、缜密、可直接用于面试回答的完整表述，不冗长不遗漏

**最终总结：**
- 在最后你需要生成一段完整的可以用于在面试中直接回答面试官的回答，语言要言简意赅并且逻辑连贯缜密，确保能正确且全面地回答面试官的问题。

### 5. 插入文档

用 Edit 工具在确定的位置精确插入 `### N.x 问题标题` 及完整回答体。确保与前后内容有适当空行。

### 6. 自检

插入后读取修改区域上下文，确认编号不冲突、格式一致、内容完整。

## 示例

用户输入：
```
/generate-knowledge Flink 中 Watermark 是如何解决数据乱序问题的？
```

你的执行：
1. 主题是 Flink → 目标文件 `Flink面试题.md`
2. 读取文档 prompt："你是一个 Flink 及流处理系统方面的专家..."
3. 扫描结构，发现已有 `## 2. 时间语义与 Watermark` 分类
4. 在此分类下按序插入 `### 2.x Watermark 如何解决数据乱序问题`
5. 生成回答：先解释乱序成因 → Watermark 的定义与机制 → 三种 Watermark 生成策略 → 代码示例 → 知识扩展（Event Time vs Processing Time、Checkpoint 关联）→ 完整口头回答
6. 用 Edit 插入，回读验证
