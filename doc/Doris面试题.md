## 1. Doris 基础

### 1.1 什么是 Apache Doris？它主要解决什么问题？

Apache Doris 是一个基于 MPP 架构的实时分析型数据库，主要面向 OLAP 场景，用来支撑大规模数据上的低延迟查询、实时报表、Ad-hoc 分析、用户画像、数据服务和实时数仓等业务。

面试里可以先用一句话概括：Doris 是一个把数据存储、实时导入、分布式计算和 SQL 分析能力集成在一起的 OLAP 数据库，目标是让用户用接近 MySQL 的方式，完成大数据量下的快速分析查询。

#### 一、Doris 的核心定位

Doris 不是传统 OLTP 数据库，它不适合承担高并发事务写入、复杂事务处理、行级强事务更新这类业务库职责。它更适合面向分析查询，也就是 OLAP (Online Analytical Processing) 场景。

典型特点包括：

1. 支持海量数据的聚合、过滤、Join 和明细查询。
2. 支持秒级或准实时数据导入。
3. 支持标准 SQL 和 MySQL 协议，方便 BI 工具和应用系统接入。
4. 内部使用列式存储、分布式执行、向量化执行等机制提升查询性能。

#### 二、Doris 主要解决的问题

在数据平台中，Doris 经常用于解决以下问题：

1. 报表查询慢：传统 Hive 或离线数仓查询延迟较高，不适合交互式分析。
2. 实时分析难：业务希望数据写入后尽快可查，比如实时大盘、实时指标、实时风控。
3. 数据服务复杂：如果每个查询都依赖 Spark、Hive 或 Presto，响应时间和并发能力可能不足。
4. 架构链路长：传统 Lambda 架构可能需要同时维护离线链路和实时链路，Doris 可以在部分场景中简化分析链路。

#### 三、Doris 的典型使用场景

- 实时 BI 看板：订单、支付、流量、广告等指标秒级更新。
- 用户行为分析：按用户、渠道、活动、时间等维度做多维分析。
- 明细查询：在大宽表中按条件快速过滤和查询。
- 数据服务：为业务系统提供低延迟聚合查询接口。
- 日志分析：对日志、埋点、监控数据做检索和聚合分析。
- 湖仓分析：通过外部表或 Catalog 查询 Hive、Iceberg、Hudi、Paimon 等数据源。

#### 四、面试时可以怎么总结

可以这样回答：Apache Doris 是一个面向 OLAP 场景的实时分析型数据库，底层采用 MPP 架构、列式存储和向量化执行，能够在大规模数据上提供低延迟、高并发的 SQL 查询能力。它常用于实时数仓、BI 报表、Ad-hoc 查询、用户画像和数据服务场景，解决传统离线数仓查询延迟高、实时分析链路复杂、数据服务响应慢等问题。

#### 知识扩展

- OLAP：Doris 的核心使用场景，面向分析查询而不是事务处理
- MPP：Doris 分布式并行计算的基础
- 列式存储：提升聚合和过滤查询效率
- 实时数仓：Doris 常作为实时明细层、汇总层或服务层
- MySQL 协议：降低客户端、BI 工具和应用接入成本

### 1.2 Doris 的整体架构是怎样的？FE 和 BE 分别负责什么？

Doris 的经典架构由 FE (Frontend) 和 BE (Backend) 两类进程组成。FE 主要负责元数据管理、SQL 解析、查询规划和集群管理，BE 主要负责数据存储、数据导入和查询执行。

可以把 Doris 理解成一个分布式数据库系统：FE 像“大脑”，负责接收请求和生成执行计划；BE 像“执行节点”，负责保存数据并并行完成计算。

#### 一、FE 的职责

FE 主要负责控制面和查询入口，常见职责包括：

1. 接收客户端连接，兼容 MySQL 协议。
2. 解析 SQL，进行语义分析和权限校验。
3. 管理元数据，例如库、表、分区、Tablet、副本、用户权限等。
4. 生成查询执行计划，并把计划下发给 BE。
5. 管理集群节点，包括 BE 上下线、心跳检测和副本调度。

生产环境中通常会部署多个 FE 节点保证高可用。FE 角色通常包括 Master、Follower 和 Observer。Master 负责元数据写入和调度决策，Follower 参与元数据高可用，Observer 主要用于扩展读能力。

#### 二、BE 的职责

BE 主要负责数据面和执行面，常见职责包括：

1. 存储实际数据，数据会切分成多个 Tablet 分布在不同 BE 上。
2. 执行数据导入任务，把外部数据写入 Doris 存储引擎。
3. 执行查询计划中的 Scan、Filter、Aggregate、Join、Sort 等算子。
4. 维护副本数据，参与数据均衡、Compaction 和故障恢复。
5. 向 FE 汇报心跳、磁盘、负载、Tablet 状态等信息。

#### 三、一次查询的大致流程

一次 SQL 查询通常会经历以下流程：

1. 客户端通过 MySQL 协议连接 FE。
2. FE 解析 SQL，做语义校验和权限校验。
3. FE 根据元数据、统计信息和优化规则生成分布式执行计划。
4. FE 将执行计划拆分并下发给相关 BE。
5. 多个 BE 并行读取本地 Tablet 数据，并执行过滤、聚合、Join 等计算。
6. 中间结果在 BE 之间进行 Exchange 或 Shuffle。
7. 最终结果汇总后返回给客户端。

#### 四、面试时可以怎么总结

可以这样回答：Doris 的架构主要由 FE 和 BE 组成。FE 负责接入、元数据、SQL 解析、查询规划和集群管理，BE 负责数据存储、数据导入和查询执行。用户提交 SQL 后，FE 会生成分布式执行计划并下发到多个 BE，BE 并行扫描和计算数据，最后把结果返回。这样的架构让 Doris 能够同时具备分布式扩展能力和较低的查询延迟。

#### 知识扩展

- FE 高可用：通过 Master、Follower、Observer 角色保证元数据和查询入口可用性
- BE 扩展：通过增加 BE 节点提升存储容量和计算能力
- Tablet：Doris 数据分片和调度的基本单位
- 副本机制：通过多副本提升可用性和容错能力
- MPP 执行：多个 BE 并行执行查询计划

### 1.3 Doris 有哪些核心功能？

Doris 的核心功能可以从数据写入、数据建模、查询分析、性能加速、生态集成和运维管理几个方面理解。

#### 一、数据导入能力

Doris 支持多种导入方式，适配不同数据来源和实时性要求。

常见方式包括：

- Stream Load：适合通过 HTTP 导入本地文件或程序实时写入的数据。
- Broker Load：适合从 HDFS、对象存储等外部存储批量导入。
- Routine Load：适合持续消费 Kafka 数据，实现实时导入。
- Insert Into：适合通过 SQL 写入少量数据或查询结果写入。
- Flink Doris Connector：适合把 Flink 实时计算结果写入 Doris。

面试中可以强调：Doris 既能支持批量导入，也能支持实时导入，因此常用于实时数仓的服务层或分析层。

#### 二、数据模型能力

Doris 常见的数据模型包括：

1. Duplicate Key 模型：保留明细数据，适合日志、订单明细、行为明细等场景。
2. Aggregate Key 模型：写入时或 Compaction 时按 Key 聚合，适合固定维度的预聚合场景。
3. Unique Key 模型：按主键保留最新记录，适合订单状态、用户状态、维表更新等场景。

不同模型决定了数据写入后的存储语义，也会影响查询性能和更新能力。

#### 三、查询分析能力

Doris 支持标准 SQL，常见分析能力包括：

- 多表 Join
- 聚合统计
- 窗口函数
- 子查询
- 明细过滤
- 排序分页
- 物化视图加速
- 外部数据源联邦查询

由于 Doris 兼容 MySQL 协议，很多 BI 工具、报表工具和数据应用可以直接连接 Doris。

#### 四、性能优化能力

Doris 内置了多种性能优化机制，例如：

1. 列式存储：只读取查询需要的列，减少 IO。
2. 分区分桶：减少扫描范围，并提升并行度。
3. 索引：通过前缀索引、BloomFilter、Bitmap、倒排索引等加速过滤。
4. 向量化执行：按列批量处理数据，提升 CPU 执行效率。
5. Runtime Filter：在 Join 场景中提前过滤无关数据。
6. 物化视图：预先计算常用聚合或维度组合，减少现场计算成本。

#### 五、生态集成能力

Doris 可以和常见大数据生态集成，例如：

- Kafka：通过 Routine Load 消费实时数据。
- Flink：通过 Connector 写入 Doris 或读取 Doris。
- Spark：用于离线加工后写入 Doris。
- Hive、Iceberg、Hudi、Paimon：通过 Catalog 或外部表进行湖仓查询。
- BI 工具：通过 MySQL 协议连接 Doris。

#### 六、面试时可以怎么总结

可以这样回答：Doris 的核心功能包括实时和批量数据导入、三类主要数据模型、标准 SQL 查询、分布式 OLAP 分析、物化视图和索引加速，以及与 Kafka、Flink、Hive、Iceberg 等生态的集成。它既能承接实时数据写入，也能支撑低延迟查询，所以在实时数仓和数据服务场景中比较常见。

#### 知识扩展

- Stream Load：常用于实时接口写入或小批量导入
- Routine Load：常用于 Kafka 实时消费
- Unique Key：常用于需要主键更新的分析表
- 物化视图：适合加速固定查询模式
- Catalog：用于连接外部数据源，支撑湖仓联邦查询

### 1.4 Doris 有哪些核心特性？为什么查询速度比较快？

Doris 查询速度快，核心原因不是某一个单点优化，而是架构、存储、执行和优化器多层能力共同作用的结果。

#### 一、MPP 分布式执行

MPP (Massively Parallel Processing) 是 Doris 的重要架构基础。查询会被拆分成多个执行片段，在多个 BE 节点上并行执行。

例如一张大表被切分成多个 Tablet，分布在不同 BE 上。查询时多个 BE 可以同时扫描自己本地的数据，再通过分布式聚合或 Shuffle Join 汇总结果。

这种方式可以充分利用集群中多台机器的 CPU、内存和磁盘资源。

#### 二、列式存储

Doris 使用列式存储。对于分析查询来说，通常只需要访问少量字段，比如查询订单金额、下单时间和渠道，而不需要读取整行所有字段。

列式存储的优势包括：

1. 只读取需要的列，减少磁盘 IO。
2. 同类型数据连续存储，压缩效果更好。
3. 更适合向量化执行和批量计算。

#### 三、分区和分桶

分区和分桶是 Doris 表设计中非常重要的性能手段。

分区通常按时间或业务范围切分数据，比如按天、按月分区。查询如果带有分区条件，就可以裁剪不相关分区。

分桶通常按某个 Key 做 Hash 分布，把一个分区内的数据拆成多个 Tablet。这样既能让数据均匀分布，也能提升并行扫描能力。

#### 四、索引和数据裁剪

Doris 支持多种索引和裁剪能力，例如：

- 前缀索引：利用排序 Key 加速范围过滤。
- Min/Max 索引：跳过不可能命中的数据块。
- BloomFilter 索引：适合高基数字段的等值过滤。
- Bitmap 索引：适合低基数字段的组合过滤。
- 倒排索引：适合文本检索、日志检索和半结构化字段过滤。

这些能力可以减少实际扫描的数据量。

#### 五、向量化执行和 Pipeline 执行

向量化执行是指 Doris 不按一行一行处理数据，而是按列批量处理一批数据。这样可以减少函数调用开销，提高 CPU Cache 命中率，并更好地利用 SIMD 等 CPU 能力。

Pipeline 执行引擎则可以让多个执行算子以流水线方式运行，减少阻塞，更充分地利用多核 CPU。

#### 六、物化视图和预聚合

对于一些固定维度、固定指标的查询，如果每次都扫描明细表现场聚合，成本会比较高。Doris 可以通过 Rollup 或物化视图提前保存聚合结果或不同维度组合的数据。

查询命中物化视图后，可以直接读取更少、更合适的数据，从而提升响应速度。

#### 七、面试时可以怎么总结

可以这样回答：Doris 查询快主要依赖几方面能力：首先是 MPP 架构，可以让多个 BE 并行扫描和计算；其次是列式存储，可以减少 IO 并提升压缩效率；再加上分区分桶、索引和数据裁剪，可以减少实际扫描的数据量；执行层还有向量化执行、Pipeline 引擎和 Runtime Filter 等优化；对于固定查询模式，还可以通过物化视图或预聚合进一步加速。所以 Doris 的性能来自存储、计算和优化器的整体协同。

#### 知识扩展

- Runtime Filter：Join 时把构建侧过滤条件下推到扫描侧，减少无效数据读取
- CBO：基于统计信息选择更优执行计划
- Compaction：合并小文件或版本，优化存储和读取效率
- Rollup：单表预聚合或调整列排序以加速查询
- 分桶 Key：影响数据分布、查询并行度和 Join 性能
