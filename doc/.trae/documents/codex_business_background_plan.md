### 参考材料形成的事实基础

- Coding Agent 不只是生成代码，还会在任务上下文中读取文件、调用工具、执行命令、修改代码并根据运行结果迭代。
- Codex CLI 是 OpenAI 可在本地终端运行的 Coding Agent，可在用户授权范围内读取、修改和运行所选工作区中的代码。
- 当前数仓研发所需的需求记录、指标口径、元数据血缘、任务代码和执行验证能力分布在多个平台，平台内嵌 Agent 往往受限于单个平台提供的上下文与工具。
- 本地路线的核心价值是把代码仓库、知识资产、CLI、Skill、脚本、Git 和验证能力组织在同一执行环境中，形成“需求理解 → 影响分析 → 代码修改 → 调试验收 → 经验沉淀”的连续链路。
- 平台与本地不是完全替代关系：单任务、轻量 SQL 修改或临时查询仍适合平台；多任务联动、跨平台取数、全链路改造及需要版本管理和确定性验证的任务更适合本地 Codex。
- LocWise 文档仅用于吸收“将平台接口封装为 Agent 可调用 Skill”的通用思路，正文不点名 LocWise。

## Proposed Changes

### 1. 重写“业务背景”正文

修改对象：目标飞书文档中标题块 `UmYmdzcSBoVrATxSiEKcfJVknqd` 下的现有占位段落。

拟写为约 600 字、4 个自然段：

1. **概念与趋势**
   - 从大模型由“回答问题、生成片段”走向“理解任务并持续执行”切入。
   - 定义 Coding Agent：以模型为推理核心，在开发环境中读取上下文、调用工具、修改代码并通过反馈迭代完成任务。
   - 定义本项目中的 Codex：以本地终端和工作区为执行载体的 Coding Agent。

2. **数仓研发的环境现状**
   - 按真实工作路径描述需求意图、指标口径、数据资产、加工任务与验证能力分散在多个系统。
   - 说明平台内嵌 Agent 通常只能获得当前页面或单个任务的有限上下文，跨任务开发仍需人工切换平台、补齐资料和核对上下游，容易造成上下文中断、口径不一致与重复操作。

3. **本地 Codex 的全景工作方式**
   - 以本地工作区为统一执行环境，通过 CLI 和 Skill 接入内部平台能力，将知识、代码和工具同时置于 Agent 可读取、可调用的范围。
   - 用一条完整链路概括全景：“需求理解 → 资产与血缘检索 → 方案与代码生成 → 调试验收 → 经验回流”。
   - 强调本地的关键变化不是把网页操作搬到终端，而是让跨平台上下文、工具调用、版本管理和验证反馈能够在同一任务中连续衔接。

4. **平台与本地的场景分层及项目必要性**
   - 明确平台仍适合单任务、低复杂度、即时处理场景。
   - 本地更适合多任务联动、长链路改造、脚本化处理和需要严格验证的场景。
   - 收束到项目目标：探索一套统一、低成本、可扩展且安全可控的数仓本地 Coding 环境，为后续端到端开发和能力沉淀建立可复用基础。
