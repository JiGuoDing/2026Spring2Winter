## 1. 项目背景（必须知道的八件事）

### 1.1 客户与产品

- 客户：**中国华电集团体系**，具体对接方是**国电南京自动化股份有限公司（国电南自）**。
- 产品：**华电睿思数智底座**。客户给的原始材料是《华电睿思数智底座产品及方案介绍》159 页**扫描版 PDF（无文本层，只能逐页看图）**。
- 集团管控模式：**总部—区域/省公司—基层企业三级管控**。这是后面所有判断的根源：租户边界和组织边界不一致。

### 1.2 平台现状（客户已有什么）

已在 **31 个省级区域、近 700 个场站**投运。七大能力板块：应用构建、应用集成、数据集成、时序数据、大数据、大模型工具链、多租户管理；另有统一门户、统一待办、统一身份与用户中心、微服务/API 网关、全栈运维。

数据面底子是好的：**每类能力各自独立数据库实例（8 个库）+ 独立中间件实例**。这一点直接决定了工作量估算——不用做"共享库改独立库"的大改造。

### 1.3 核心判断（整套方案的出发点，别改）

> **现状是"配置驱动"，不是"治理驱动"：创建能做，判定准则没有；资源能分配，配额与计量没有；身份中心有了，跨租户权限边界仍是空白。**

三个缺口（对外统一这么讲）：

| # | 缺口 | 具体表现 |
|---|---|---|
| 1 | 有租户创建，没有判据 | 六类配置模板齐备，但"什么业务该独立部署、给多少资源"全靠人拍 |
| 2 | 有资源分配，没有配额与计量 | 配额只有上限值，无三层执行点、无用量回流 |
| 3 | 有身份中心，没有跨租户权限边界 | 每租户同步全量组织架构 → 可见范围形同虚设；跨租户认证有、三道闸没有 |

### 1.4 建议架构（一句话版本）

> **以"安全分区为第一约束、以信任等级定隔离强度、以控制面为改造重心"的分级多租户架构。**

展开成四句：
1. 全部平台资源（含 L3 独立集群）只部署在**管理信息区（安全Ⅲ区）**；生产控制区数据**单向**进入，平台不回写控制类指令。
2. 租户按 **L0–L3 四档**隔离，用 **B/D/R/S 四维各 1–5 分打分（T=4–20）** 定档，另设 **5 条一票否决**。
3. 身份以**集团 4A 为唯一权威源**，平台只做 **SP 联邦**，不建第二套主身份库。
4. 改造重心在**控制面（L2）**：必改 5 项 / 轻改 3 项 / 不动 2 项。

### 1.5 关键数字（对外只用这一套）

| 指标 | 值 | 说明 |
|---|---|---|
| 租户规模 | **约 900 个** | 假设：一级 ≤50、业态二级 ≤20、厂站二级 ≤800 |
| 隔离分档 | **L0 / L1 / L2 / L3** | 边界：T≤6→L0，7–9→L1，10–13→L2，≥14→L3 |
| 打分 | **B/D/R/S，各 1–5，T=4–20** | B 业务类型 / D 数据敏感度 / R 监管要求 / S SLA |
| 一票否决 | **5 条** | 触发即 L3，不再看总分 |
| 默认档 | **约 80% 的二级租户落 L1** | 注意：不是"80% 租户"，是"80% 的二级租户" |
| 资源成本 | **当量 45%–55%** | 以"全量 L2 方案"为 100% |
| L3 集群 | **≤ 5 个** | 独立集群成本太高，必须设上限 |

### 4.1 必须守住的表述

| 场景 | 唯一正确写法 | 常见错误 |

### 4.2 禁用词（`tools/wording_scan.py` 会扫出来）

**硬禁（BAN，必须清零）**：`III 区`（半角罗马数字）、`110 人月`、`80% 租户`、`省一半`、`三区`、`一至四级隔离`、`平台部署在生产控制区`。

**软禁（soft，逐条判断）**：
- `14 号令` —— **只允许**出现在"沿革说明 / 术语对照表 / 参考来源"里（例如"2014 年第 14 号令已废止"），**不得**作为现行依据引用。正文里这类命中是正确的，别删。
- `四级隔离` —— `L0–L3 四级隔离` 是正确用法，正则只拦"一至四级隔离"这类错误说法。

- `我们公司`、`甲方`、`乙方` —— 自称统一为我方 / 客户。
- `首先/其次/综上所述/由此可见/不难看出/值得注意的是` —— 模板化连接词，能删就删。

## 8. 已经踩过的坑（照抄结论，不要重新试错）

### 8.1 SVG 中文渲染成方块 `□`

**现象**：`<text>` 内容中文全变 `□`。
**根因**：该渲染器在文本以拉丁字母/数字开头时字体回退失败。
**解法**：**所有** `<text>` 显式加 `fontFamily='Microsoft YaHei'`（纯中文不加也正常，但统一加最安全）。
**校验**：`grep -c "<text"` 与 `grep -c "fontFamily"` 数量必须相等。

### 8.2 `<tspan>` 丢内容

该渲染器**不支持 `<tspan>`**，用了直接丢文字。只能用独立 `<text>` 元素 + 手动算 y。
若已误用：`re.sub(r"<tspan[^>]*>([^<]*)</tspan>", r"\1", s)` 还原成纯文本。

### 8.3 表格单元格里的 `&lt;` 不解码

- JSX **文本节点**里 `&lt;` 会被解码（反而要写成 `&lt;`）。
- **表格单元格**里不会被解码，`&lt; 5 min` 会显示成字面量 → 单元格内直接写 `<`。

### 8.4 Table 不支持 `cellStyle.width`

列宽按内容自动分配，短列被压到 ~60px，`01` 这种会**竖排**。
对策：① 首列只放 `01`/`R1`/`#` 极短串；② 或改用「分条 Box 布局」（序号列固定 40 + 正文 flex:1 + 后果列固定 400），彻底不用表格。C 版第 3 页就是这么救回来的。

### 8.5 页面下方大片空白

`justifyContent:'space-between'` 在内容不足时会露白。
**检测**：`python tools/slide_gap.py <deck>/preview`（阈值 70 幻灯片像素）。
**修法**：SVG 页写脚本把 `y/y1/y2/cy/height` 与 viewBox 高同比例放大 k 倍；表格页加高 `height`；列表页加大 `paddingTop/paddingBottom`。

### 8.6 浅底色块配白字看不清

L0 用 `#D9DEE7` 底 + 白字，肉眼几乎不可见。深色底一律改 `#3D4C63`。

### 8.7 无头浏览器测窄屏是假象

`msedge --headless --window-size=390,xxx` 在 Windows 上**窗口被夹到约 477 CSS px**，截图是"477 宽页面裁掉右边"，看起来像横向溢出。
**千万不要据此改 CSS**。用 `tools/html_shot.py`（iframe 钉死视口）才是真 390。
`--force-device-scale-factor=1` 对窗口夹取无效。

### 8.8 容器内 svg 被尺寸规则误伤

`.fig-frame svg{width:100%;min-width:640px}` 会命中占位框里 52px 的图标 svg，把它撑成 760px 巨图。
**规则**：给容器内 svg 写尺寸，一律用直接子代选择器 `.fig-frame > svg`。

### 8.9 移动端表格压字号没用

`table-layout:fixed` 只是把三列压成每列 ~110px，出现一字一行竖排。
**正解**：窄屏改卡片堆叠 —— 每个 `<td>` 加 `data-label`，`table/thead/tbody/tr/td{display:block}`，首列作标题条，其余 `td::before{content:attr(data-label)}`。
**坑中坑**：标题条想用 `display:flex` + `::before{order:2}` 让标签靠右，标题一长就会把标签甩到上一行，顺序错乱。改用 `display:block` + `::before{float:right}` 才稳定。

### 8.10 中文标题孤字

`text-wrap:balance` 用于 h1/h2/h3，`text-wrap:pretty` 用于正文段落。

### 8.11 pandoc 智能引号把开引号判成 `”`

md 里原用 ASCII 直引号（918 个）会让 Word 里显示错误。转 docx 前统一转中文弯引号。
