### 调研推翻的四条旧结论（本轮最重要的发现）

1. **MinIO 已死**：2025-05 移除控制台 → 2025-10 只发源码 → 2025-12 维护模式 →
   2026-02-12 "不再维护" → **2026-04-25 仓库归档** → 2026-09 Docker Hub 镜像下架、dl.min.io 返回 410。
   设计方案表 10-3/10-7 原把 MinIO 列轨一。改：主轨 **Ceph RGW**，过渡轨 **RustFS 1.0.1**，
   备选 SeaweedFS 4.47 / pgsty-silo（后者 AGPL + 单一维护者，不进关基）。
2. **vCluster 0.38 是 limited availability**（2026-11-18），官方建议存量留 0.37 LTS。
   改：锁 **v0.37.7**。原设计未指定版本。
3. **Kyverno `ClusterPolicy` 在 1.20 移除**（1.19 是最后支持版，补丁 "main+1" 约 3 个月）。
   策略必须写在 `policies.kyverno.io` 的 ValidatingPolicy/MutatingPolicy/GeneratingPolicy/
   ImageValidatingPolicy/DeletingPolicy 上。按旧教程写，交付半年即过期。
4. **K8s 1.34 于 2026-10-27 EOL**；**CVE-2026-2270**（StatefulSet 控制器混淆代理，CVSS 5.9）
   可把 Pod 送进他人命名空间，只在 1.35.9/1.36.5/1.37.1+ 修复。Capsule 0.15.x 又要求 ≥1.36。
   改：生产基线 **≥1.36，推荐 1.37.3**。**版本本身就是隔离强度的一部分。**

### 五项必须先实测（P0 前两周）

1. **达梦 RLS 会话上下文作用域**（最关键）：RLS 靠谓词注入 + session context，
   共享连接池复用会话会串租户。若不支持事务级上下文，L1 只能改"每租户独立 DB 用户 + 小池"，
   容量规划差一个量级。给三种处置：A 每租户独立用户+独立池（L2/L3）/ B 共享池+请求级重置（L1）/
   C 应用层行过滤+视图收紧（兜底）。本方案 L1 用 B+C，L2/L3 用 A+C。
2. Capsule 0.15.2 on 鲲鹏+麒麟 V11（arm64 镜像、webhook 证书链）
3. vCluster 0.37.7 private nodes 模式网络栈
4. Cilium 1.20 on 麒麟 V11 内核 6.6（国产内核有自研补丁：KYSEC、eBPF 工具集）
5. APISIX on 国产 CPU 限流性能与精度

### 几个值得记住的实现细节

- **Capsule 2026 年多个跨租户提权 CVE**（GHSA-jr6p-8pjj-mfx6、GHSA-gjw4-v3v3-rqxg 高危等）
  → 反证"准入双引擎"不是冗余而是必需：单一 webhook 就是单点。
- **Cilium 1.20 实现上游 ClusterNetworkPolicy** → 集群级护栏可用可移植 API 写，
  换 CNI 不废；租户级细粒度仍用 Cilium 原生 CRD。**护栏可移植、细则用原生。**
- **APISIX `key_type` 默认 var、`key` 默认 remote_addr** → 不显式设就是"每 IP 一份配额"，
  这是限流最常见的实现事故。
- **OpenCost 口径是 `max(request, usage)`** 不是实际用量；`tenant_id` 标签必须打在 pod template 上
  （只打 Deployment 无效，分配从 running pod 算）。
- **Keycloak 一个 Realm + Group 层级**，不要每租户一 Realm（不共享用户、900 个 Realm 启动即崩）。
- **CNCF 平台工程成熟度模型 v1（2026-09-01）** 拿来定位：P0 = Interfaces L2、Measurement L1。
