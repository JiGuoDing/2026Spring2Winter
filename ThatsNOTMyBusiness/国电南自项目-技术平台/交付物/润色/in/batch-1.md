@@P001@@
**中国华电集团体系 · 华电睿思数智底座**

@@P002@@
> **阅读提示**：本文所有涉及客户现状的表述，均标注客户材料的页码证据（P142–P153 指《数智底座宣讲材料-对外 V0.1》页码）或标注【待确认-Txx】。客户材料中的"支持 / 可实现 / 灵活调整"属配置能力描述，本文一律改写为"客户材料表述为……（未提供验证证据）"。

@@P003@@
华电睿思数智底座已在集团 31 个省级区域、近 700 个场站投入运行，形成应用构建、应用集成、数据集成、时序数据、大数据、大模型工具链、多租户管理七大能力板块，并配套统一门户、统一待办、统一身份与用户中心。就多租户而言，客户已具备"配置驱动的租户创建"能力：容器、中间件、数据库、功能模板、安全、通知六类配置模板齐备（P146），一级/二级租户概念模型完整（P143），并已支持"多租户共享或分离"的部署形态选择（P151）。数据面的事实基础较好——每类能力已对应独立数据库实例（统一用户中心库、生产环境库、业务库、融合集成库、Doris 库、IoTDB 库、智能计算库、工具链库共 8 个），中间件（消息队列、缓存、任务调度）亦为独立实例。

@@P004@@
**但现状是"配置驱动"，不是"治理驱动"**：有创建能力，没有判定准则；有资源分配，没有配额与计量；有身份中心，没有跨租户权限边界。

@@P005@@
其余三项（应用自治与集团统管的权责划分、多环境与租户级运维视角、命名/接入/变更/审计治理规范）作为治理件缺口，分别在 §7.4、§8、§4.5 处理。

@@P006@@
**以"安全分区为第一约束、以信任等级定隔离强度、以控制面为改造重心"的分级多租户架构**：全部平台资源（含 L3 独立集群）只部署在管理信息区（安全Ⅲ区），生产控制区数据仅经电力专用横向单向安全隔离装置单向进入平台且平台不回写控制类指令；租户按 L0–L3 四级隔离，用"业务类型 + 数据敏感度 + 监管要求 + SLA"四维 1–5 分打分定档并设 5 条一票否决；A 类内部租户用 K8s 原生命名空间 + Capsule 的 Tenant CR 作治理层，B 类第三方开发商强制 vCluster 或独立集群；身份以集团 4A 为权威源、平台侧只做联邦（SP），组织与用户改为"按可见范围同步 + 增量同步 + 冲突仲裁"。

@@P007@@
代价必须写清：测试占比约 24%（高于常规 15%），因为本方案的三个核心验收指标——隔离有效性、越权拦截率、配额生效——只能测出来、不能看代码看出来，**不砍测试**；三个最不确定项带区间提交：身份 ±50%、子系统适配 ±40%、隔离 ±30%。工作量能压到 109.5 人月的前提是"数据面已独立实例"这一客户现状事实，改造重心因此在控制面（§7.2），该判断使工作量相对"从共享库改造为独立库"的方案降低约 30%。

@@P008@@
中国华电集团采用总部—区域/省公司—基层企业三级管控。这一组织形态对多租户平台的第一位影响不是"要不要隔离"，而是"租户边界和组织边界不一致"：一个区域公司既是一级租户的管理主体，又可能同时管辖水电、新能源、煤电三类业态的若干厂站；一个厂站既是二级租户，其人员又可能同时被授权访问集团级应用。租户模型必须能表达"人—组织—租户"的多对多关系（§4.2、§5.1），否则一人多租户场景会退化为多套账号。

@@P009@@
三类业态的信息化差异决定了配额模板与落档打分的差异化基础，不能用一个模板套全集团：

@@P010@@
这三类差异直接落到三个设计参数上，而不是停留在业务描述层面：**配额模板**按业态分（水电重存储与时序写入、新能源重租户数量与轻量配额、煤电重计算资源与只读汇聚）；**落档打分**中新能源场站因数据源自场站监控系统而 R 值偏高（判例 C-3）；**子系统适配优先级**按业态排序，新能源先做场站接入与边缘采集，水电先做时序保留策略与大坝安全类应用的隔离，煤电只做只读汇聚不做控制类业务。若不按业态分模板，就会出现"给一个只有两名信息化人员的风电场站配 32 核配额"这种既不经济也无法运维的结果。

@@P011@@
需要特别说明两条与业务格局直接相关的事实口径，避免在后续容量与覆盖率讨论中被误用：

@@P012@@
1. "接入睿思底座的装机容量 8000 万千瓦"（2025-12 口径）与"集团发电总装机 2.86 亿千瓦"（2026-09 口径）**分母不同，不可相互折算**，本方案不作任何覆盖率推算。

@@P013@@
2. 集团"十五五"目标为装机超 4 亿千瓦、新能源装机倍增、清洁能源占比超 70%，意味着租户数量与场站接入规模仍将增长；本方案所有容量设计按"可线性扩容的模板化下发"而非"一次性精确容量"处理，绝对容量参数以【待确认-T09】【待确认-T10】为准。

@@P014@@
按客户一手材料（P142–P153）逐项盘点七大能力板块与四个统一能力，状态分"已落地 / 蓝图（材料表述为能力，未提供验证证据）/ 缺口"三态。完整版见附录 A，本节为摘要版。

@@P015@@
三态标注不是文字游戏，它直接决定验收口径。标"已落地"的项，我方在设计时可以假定其机制存在，只做接口对接；标"蓝图"的项，我方必须在 P0 第一周做现场实测盘点，实测不通过的部分要按"新建"计工作量。以时序数据为例：客户材料表述支持 600 万测点同时写入，这属于能力声明；本方案不据此推算容量，而是在【待确认-T04】中要求提供实际测点规模与写入峰值，原因是一旦按声明值做容量设计，实际写入量只需达到声明值的三分之一就可能击穿存储规划。同理，"混合租户"这个定性在材料里是"物理共享 + 逻辑隔离与独立部署并存"，它准确描述了现状的**结果**，但没有描述**判据**，这正是本方案要补的第一个缺口。

@@P019@@
**目标**：给出可评审、可施工、可验收的多租户架构设计，使客户在不推翻既有容器云平台（KubeSphere / Rancher / OpenShift 类平台一律"拿机制不拿平台"）、不新建域名体系（沿用 `*.zhsc.chd.com` 泛域名 + 出口 IP 分集群 A/B/C）、不重构数据面的前提下，获得隔离分级、配额治理、身份贯通、应用自治四项治理能力。

@@P020@@
**在范围内**：租户模型与治理模型；统一身份与权限；资源隔离与配额；应用自治与集团统管；与运行保障体系的衔接；安全合规映射；技术选型建议；三期路线与原型验证方案；待确认清单。

@@P021@@
**不在范围内**：生产落地实施与具体代码改造；硬件采购与机房建设；安全接入区建设；等保测评实施；运行保障方案（由并行方案承接，§8.1）；商业报价（【待确认-I06】）。

@@P023@@
**特权三角色必须互斥**：平台管理员、租户管理员、安全审计员由同一人兼任时，租户冻结/注销、审计配置变更等控制全部失效。这意味着客户侧至少需要三个岗位编制：集团侧平台管理员组、审计组、各租户管理员，具体人力见【待确认-T16】。

@@P024@@
七个角色与客户实际岗位不是一一对应关系，汇报时须说明映射：集团信息化主管部门对应集团数字化管理部门；区域/省公司平台管理员在多数区域是"信息化专责 + 少量外包"的组合；厂级租户管理员在厂站通常由信息班组长兼任，不是专职岗位；安全审计员在集团侧最可能由审计或纪检岗位兼任，但**不能由平台管理员兼任**。这个映射的现实含义是：本方案设计的操作步骤必须按"兼职人员、每周只有几小时处理平台事务"来设计，凡是需要连续操作或专业命令行的流程都要做成批量或模板化，否则规则会因无人执行而失效。

@@P025@@
此外必须单列一类"共用账号"：场站值班场景下多人共用一个操作账号在电力行业是常态。若不设"主从账号映射授权"（把公共账号与多个实名登录账号建立映射，实现实名审计），审计链条在值班环节就断了（§5.2、R-14）。

@@P026@@
**S1 集团新设区域公司，一天内开通一级租户并带上默认子系统**

@@P027@@
集团信息化主管部门在服务台提交租户申请，选择业态（水电/新能源/煤电）、层级（一级）、配额模板与默认子系统包。系统按四维打分预填档位（无跨租户数据供给时为 L1），平台管理员审批后触发开通流水线：创建租户元数据 → 创建命名空间与配额 → 初始化独立 schema → 按模板下发子系统配置 → 绑定域名与证书 → 生成租户管理员账号。涉及设计点：租户生命周期状态机（§4.4）、模板化开通（§7.1）、配额默认值（§6.6）、域名沿用（§6.5）。

@@P028@@
**S2 某水电厂作为二级租户上线一套检修管理应用（低代码 + 流程 + 报表）**

@@P029@@
厂级业务人员在设计态沙箱内配置表单、流程、报表与字典，提交发布申请；租户管理员审批后发布到本租户运行态；流程实例自动带 tenant_id 标签并推送待办到一级租户门户流程中心。全过程不涉及代码、不涉及跨租户数据。该场景四维打分为 9 分落 L1（§6.1 判例 C-1），是本方案的默认路径与原型验证场景（§11.3）。涉及设计点：低代码成熟度 M2、设计态沙箱、租户上下文注入、待办隔离校验。

@@P030@@
**S3 新能源场站侧边缘节点接入集团时序数据平台，数据只在租户内可见**

@@P031@@
场站侧按轻量模板开通二级租户，采集侧通过 OPC/MQTT/104 等协议接入，数据经区域汇聚节点写入时序库。写入路径强制注入 tenant_id 标签，查询侧由数据层过滤保证只在本租户可见。该场景监管要求维度为 4（数据源自场站监控系统），一票否决后至少 L2，需独立时序实例避免写入争抢（判例 C-3）。涉及设计点：时序租户标签与保留策略（§6.3）、边缘节点不缓存重要数据（§9.2）、带宽配额（§6.6 Q-11）。

@@P032@@
**S4 两个租户之间需要共享一份主数据（供应商/设备台账）**

@@P033@@
数据所有方租户（如某水电厂）提出共享申请，与消费方租户、平台方三方确认共享对象、字段、有效期（≤ 90 天）；平台开通"受控通道"（数据服务 API 而非数据库直连），双向授权并留痕，到期自动复审。本场景会触发落档升级：供给方一旦成为"重要数据"提供方，数据敏感度从 2 抬到 4，总分 11 落 L2（判例 C-2）。涉及设计点：跨租户数据共享授权（§5.4）、数据集成受控通道（§7.2）、数据分级（§9.4）。

@@P034@@
**S5 专业开发人员在租户内自建微服务并接入 API 网关，受配额约束**

@@P035@@
开发人员在本租户命名空间内部署微服务，镜像必须来自白名单仓库，工作负载通过基线准入；服务注册到网关时申请租户路由与限流策略，网关按租户维度累计 API 调用量并比对配额。超过上限触发审批流而非直接拒绝存量流量。涉及设计点：准入双引擎（§6.2）、网关计量点（§6.6）、配额突破审批（§6.6）。

@@P036@@
**S6 大模型工具链按租户计量 Token 与算力，超额需审批**

@@P037@@
租户调用平台托管的模型服务，模型网关按请求记录输入/输出 Token 并归集到租户；GPU/NPU 按卡·小时计量并受队列配额约束。超额时拒绝新请求并提示申请突破。模型与智能体本身不按租户隔离（共享是收益最大化路径），仅做可见性与配额。涉及设计点：Token 输入/输出分开计量（§6.7）、算力配额（§6.6 Q-10）、大模型成熟度 M3（§7.2）。

@@P038@@
**S7 某租户发生故障或算力挤占，不得影响其他租户**

@@P039@@
单租户工作负载异常时，先由限流与熔断隔离爆炸半径；若造成节点级资源争抢，关键租户因处于独立节点池而不受影响；平台侧通过 QoS 分级（关键/普通/批处理）与节点池物理分组限制影响面。事后由隔离策略漂移检测确认隔离是否真的生效。涉及设计点：故障隔离与降级（§8.3）、节点池分级（§6.2）、漂移检测（§6.2）。

@@P040@@
**S8 租户注销/合并时的数据归档、导出与彻底清除**

@@P041@@
租户申请注销后进入冻结态（保留只读 N 天），期间完成数据导出（按租户级导出清单，覆盖 8 类独立库）、归档与交接确认；冷静期（≥ 30 天）后执行销毁：PVC 擦除、对象存储级联删除、备份副本联动删除、审计日志按规定留存（审计日志不随租户数据销毁）。三方复核（平台 + 租户 + 审计）。涉及设计点：生命周期状态机（§4.4）、剩余信息保护（§9.5）、高危动作 H-06（§5.4）。

@@P042@@
八个场景构成一张覆盖矩阵，而不是八个孤立用例：S1/S2 覆盖租户生命周期与低代码路径（控制面 + 应用构建）；S3/S4 覆盖数据隔离与跨租户数据流转（数据面 + 数据集成）；S5/S6 覆盖配额与计量（网关 + 模型网关，即三项 K8s 层不可见的配额）；S7 覆盖故障隔离与爆炸半径；S8 覆盖退出机制与数据交还。八个场景全部落在"设计可验证"的范围内——每个场景都能在原型环境中用可观测指标判定通过与否（§11.3）。反过来看，若某个需求无法映射到这八个场景中的任何一个，它大概率属于运行保障方案的范围而非本方案范围（§8.1）。
