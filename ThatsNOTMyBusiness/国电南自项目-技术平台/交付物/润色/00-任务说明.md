# 润色任务说明（内部执行稿，不对外）

## 任务
把《集团级多租户技术平台架构设计方案（初版）》的**正文叙述段落**逐条润色，让文字读起来像资深架构师亲手写的，而不是模板拼出来的。表格不动。

## 输入 / 输出
- 输入：`润色/in/batch-1.md` … `batch-6.md`，每条以 `@@P0xx@@` 开头，下一行是原文（单行）。
- 输出：`润色/out/batch-1.md` … `batch-6.md`，格式与输入完全一致——`@@P0xx@@` 单独一行，下一行是润色后的文本，条目之间空一行。
- **条数与 ID 必须一一对应，不增不减、不换序。**

## 硬约束（违反即返工）
1. **事实零改动**：数字、参数、版本、比例、人名/单位名、法规条号、页码证据（P142–P153）、结论与限定语（"未提供验证证据""须回溯""待确认"）一个都不能丢，也**不得新增任何事实、案例、数字、类比**。
2. **保留全部标记**：`**加粗**` 的关键强调、`- ` 与 `1. ` 列表符号与层级、`> ` 引用、`【待确认-Txx：…】`、`[A-1]`/`[Sxx]` 来源编号、`§7.2`/`表 6-2`/`图 3-1` 交叉引用、英文术语与缩写（K8s、OIDC、SAML2、vCluster、Capsule、RBAC、ResourceQuota、NetworkPolicy、PSA、Doris、IoTDB、4A 等）一律原样。
3. **一条还是一条**：不改段落边界，不合并、不拆分；列表项不增删、不合并不换序。
4. **长度**：单条改写后汉字数与原文相差 **±15% 以内**；整批总字数浮动 **±8% 以内**。写完自查一遍。

## 改写取向（做到这些才算润色到位）
1. **句长要有起伏**。原文大量 40–80 字的单句，拆成两三句；短句就让它短。相邻句子避免同构（连着两个"以…为…""通过…实现…""既…又…"就该改）。
2. **主语落到能动作的东西上**。把"本方案""该能力""相关工作"这类空主语换成平台、网关、准入控制器、租户管理员、评审组。
3. **删套式连接词**。"首先/其次/再次/最后""值得注意的是""综上所述""由此可见""不难看出""在…方面""从…角度"能删就删，靠内容顺序衔接；转折用"但""不过""反过来""问题在于"。
4. **破折号节制**：每段最多一个"——"，其余改成逗号、冒号或断句。
5. **少用对偶与排比**。"既…又…""不但…而且"尽量改掉；术语性三连（如"可配置、可扩展、可审计"）可留，其余拆开说。
6. **判断句直接说**。删掉"需要指出的是""必须强调的是"这类前置，直接陈述；真正的强约束才留"必须"。
7. **语气**：克制、具体、给得出取舍理由的工程口气。禁词：赋能、抓手、闭环、数智化、新范式、全方位、深度融合、有机统一、打造。
8. **术语与自称统一**：我方、客户、租户、一级租户、二级租户、租户管理员、平台管理员、资源域、隔离等级（L0–L3）。不出现"我们公司""甲方""乙方"。

## 不要做的事
- 不碰表格（本次不处理表格行）。
- 不加小标题、不加例子、不加"综上"式收尾。
- 不把陈述改成设问、感叹或口号。
- 不调整段落顺序与章节结构。
- 输出里不要出现任何解释、批注、序号、"以下是润色结果"之类的话。

## 输出格式示例
```
@@P007@@
平台现在能建租户，但建多大、给多少资源、什么业务必须独立部署，全靠人拍。评审问一句"为什么这个厂给独立集群"，答不上来。
```
