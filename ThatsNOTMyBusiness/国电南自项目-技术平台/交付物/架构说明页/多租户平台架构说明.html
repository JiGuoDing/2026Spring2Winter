01

整体架构

一条红线定边界，四层结构定职责，控制面与数据面定风险。

一条红线：全部资源只落安全Ⅲ区第一约束

依据《电力监控系统安全防护规定》（2024 年第 27 号令，2025-01-01 施行）：平台全部资源，包括 L3 物理隔离的独立集群，只能部署在管理信息区（安全Ⅲ区）。生产控制区的数据单向进入，控制指令一律不回写。

约束一

数据单向进入

生产实时数据经电力专用横向单向安全隔离装置进入平台，只做汇聚与展示，不回写任何控制类指令。

约束二

安全接入区不存重要数据

该区只承担通信代理与端到端身份认证；场站边缘节点因此只缓存非重要数据，原始数据一律直传。

约束三

三级部署，不做“每站一边缘云”

集团中心云 + 区域节点 + 场站边缘采集。近 700 场站的规模下，每站一朵边缘云在成本上不可行。

约束四

L3 是隔离强度，不是跨区通行证

L3 指独立集群、独立资源池、独立控制面，但仍落在Ⅲ区内；需要控制类系统的业务须独立建设、单独测评。

四层结构：层间只走四条契约

分层不是画出四层框就算数。层与层之间只暴露契约、不允许跨层直连；每条契约都必须显式定义、可校验，否则分层会退化成示意图。

  • L4 → L3仅经网关调用：应用不得直连服务实例。被绕过 → 跨租户计量与留痕同时失效。
  • L2 → L3租户上下文注入：服务实例不采信调用方自报的租户身份。被绕过 → 越权防护失效。
  • L3 → L2状态上报与计量流水：实际用量与策略生效状态回传，供对账与漂移检测。被绕过 → 漂移检测失效。
  • L2 → L1配额下发与准入拦截：配额声明式下发，准入在写入前拦截。被绕过 → 配额治理整体失效。
设计意图 分层不是为了好看，是为了把“谁负责任么”钉死在契约上。任何一条契约被绕过，都会直接摧毁本章后面的一个具体结论——所以这四条要写进接入规范，由准入校验强制执行。

控制面与数据面分离

控制面承载租户元数据、配额、落档、授权、模板、计量与审计策略；数据面承载业务流量与业务数据。分离的标准不是画两列框，而是五个维度都独立。

维度要求为什么必须独立
故障域控制面不可用时，已开通租户的业务照最后一次下发的配置继续跑控制面恢复后按期望状态收敛（声明式 + 定期对账）
网络路径管理流量与业务流量物理或逻辑隔离，管理面不向租户网络开放避免租户侧横向探测到管控接口
权限路径管理员进数据面须走高危动作流程：限时 + 双人 + 录屏 + 租户可见平台方的访问必须可被租户审计
变更节奏控制面变更视同生产发布：双人复核、灰度、可回滚一次错误下发会同时打到大量租户
对账机制控制面记期望状态，数据面定期上报实际状态，差异超阈值告警隔离策略的漂移检测也靠这套机制
设计意图 把两类风险放进同一个故障域，等于拿“单租户级”的运维纪律去管“全平台级”的变更。分开之后，控制面按生产发布标准管，数据面按租户维度做灰度与降级，两者的责任人与节奏可以不同。
02

核心模块

控制面六个功能域，分别回答“谁、多少、怎么给、用了多少、留了什么痕”。

六个模块不是并列的六个功能，而是一条有先后的链路：租户管理给主键，身份联邦给人，配额与准入给量，开通编排把前三者落成资源，计量采集把实际用量回写，审计横向覆盖全部写操作。

模块 01

租户管理

定义一级 / 二级租户、组织与人员归属、资源域与订购关系，用状态机管住从申请到注销的全过程。

唯一事实源9 个状态≥ 30 天冷静期
模块 02

身份联邦与授权

集团 4A 是唯一权威，平台只做 SP；OIDC 与 SAML 双栈并行，存量 CAS 保留兼容层；外部账号另立账号域。

连接而非替换双栈外部账号不进 4A
模块 03

配额与准入

15 项配额按四档给默认值、倍数上限与突破审批；一票否决硬编码在准入校验里，优先于总分。

分档 + 倍数 + 审批5 条否决
模块 04

模板与开通编排

沿用客户六类配置模板作为流水线输入，把命名空间、库、配置、域名、管理员账号一次性备齐。

六类模板声明式下发
模块 05

计量采集与聚合

12 项计量中 4 项客户已有数据，方案只补强制标签、聚合口径与展示，不新建监控体系。

补齐而非重建P0 只出用量
模块 06

审计与合规

以“用户 + 激活租户”为二元组记录写操作，支持租户视角审计与跨租户操作回溯。

租户可见高危动作留痕

L3 的适配策略：差异化，不一刀切

七个能力板块按“是否触碰租户边界”划线，改的只有控制面那五个；大数据与大模型只接计量、内核一行不改。

改造强度板块理由
必改 5 项多租户管理、统一身份接入、API 网关、低代码平台、集成平台不触碰租户边界，租户根本无法开通；网关还是配额与计量的唯一执行点
轻改 3 项统一门户、待办中心、时序库适配只加适配层与租户上下文透传，不动数据模型与流程定义
不动 2 项大数据平台、大模型工具链重构风险大于收益；只在网关接计量，内核不改
设计意图 “必改”的五个都是控制面组件，改造量集中、可控；业务应用侧基本零改动。这是分期能落地、也是 109.5 人月这个量级成立的前提。
03

交互与数据流程

三条主链路：把租户开出来、把人登进来、把配额管住。

3.1 租户开通：申请到运行的五个环节

打分落档发生在审批环节，并且一票否决优先于总分——它在开通之前就拦住不合规的租户，而不是上线后再整改。

3.2 登录与身份联邦：只做联邦，不建第二套

集团 4A 是唯一身份权威。平台做 SP，只验签、不发号：不存密码、不发凭证、不做组织建模，否则又会多一份要维护的主数据。

关键约定

sub 是唯一主键

令牌的 sub 映射为平台 external_id，禁用 email 作主键；iss + sub 组合唯一。租户、角色等以自定义 claim 承载。

关键约定

一人多租户靠“激活租户”

集团专家跨厂支持时，一个 4A 账号对应多条租户成员关系；登录后先选租户，令牌内携带“当前激活 tenant_id”，审计记“用户 + 激活租户”二元组。

3.3 配额强制执行：三层缺一，必然被绕过

配额不是一张表，是三个执行点各自算得出来、各自拦得住。API 调用量、Token、并发这三项在 K8s 层完全看不见，只能靠网关与模型网关——所以网关是 P0 的第一个里程碑。

设计意图 100% 直接掐断会造成生产事故，所以阈值分三档；配额必须配“分档 + 倍数 + 审批”三件套——只给默认值人人都来突破，只给上限小租户会被大配额浪费。
04

方案特点

五条可检验的取舍，而不是五个形容词。

特点 01

不做一刀切，八成停在 L1

把“能不能上 L2”变成要论证的例外，而不是默认选项。约 80% 的二级租户落 L1，资源当量降到全量 L2 的 45%–55%；L3 目标 ≤ 5 个集群，超出即按失控处理。

默认档 L1例外要论证
特点 02

只做联邦，不建第二套身份

4A 是唯一权威，平台侧不建主身份库、不做组织建模。省下的不是开发量，而是“两份人员数据长期对不齐”的治理成本。

连接而非替换责任不转移
特点 03

配额靠三层执行点，不靠一张表

K8s 硬、准入准硬、网关软；调用量、Token、并发只能靠网关计量。这是把“配额写在制度里”变成“配额跑在系统里”的唯一办法。

网关 = P0 第一里程碑
特点 04

差异化改造：必改 5 / 轻改 3 / 不动 2

改造量集中在控制面五个组件，业务应用侧基本零改动。大数据与大模型只接计量，不重构内核——重构风险大于收益。

改造量可控分期能落地
特点 05

测试不砍，约占 24%

隔离有效性、越权拦截率、配额生效这三个指标只能测出来，不能靠看代码看出来，所以测试投入单列、不与其他开发项合并。

20 组越权用例六步验收
特点 06

区间先宽后窄，把不确定性摆到桌上

P0 ±50%、P1 ±40%、P2 ±30%。一期不确定的是边界，不是人力；边界一锁，估算就该收敛。

≈ 109.5 人月43.5 / 34.0 / 32.0

四条关键取舍

方案里每个“选这个”，都对应一个“不选那个”和一份要付的代价。这些取舍已录入架构决策台账，按季度复核。

决策不选的备选理由代价
软硬多租户混合全软隔离 / 全硬隔离全硬成本是 L1 的 5–8 倍；全软无法满足外部开发商与重要数据供给方维护两套技术栈与两套运维流程
单集群多命名空间为主每租户一个集群900 个租户不可能每户一集群；L1/L2 在单集群内可通过节点池强化共享 API Server，须 APF 与准入护栏
身份以 4A 为权威平台自建 IdP / 商业 IAM 为主身份权威源唯一是集团化 IAM 主流取向；自建会造成双份人员数据强依赖 4A 接口排期，是最大外部风险
计量复用既有监控新建统一计量平台客户已有 Prometheus + Grafana 与低代码埋点，重复投资会引发抵触标签体系需补齐，历史数据无法回溯

还缺一块：实测证据

方案里的当量、时长、拦截率目前都是经验值或目标值。三个最不确定项要带区间提交，等原型环境跑出来再回填。

设计意图 把不确定性写在明面上，比在评审时被逐条追问省时间。三个区间（身份 ±50%、子系统适配 ±40%、隔离 ±30%）不是保守估计，是真实风险。

依据《电力监控系统安全防护规定》（2024 年第 27 号令，2025-01-01 施行）；分区表述统一为生产控制区（安全Ⅰ/Ⅱ区）— 安全接入区 — 管理信息区（安全Ⅲ/Ⅳ区）。人月为经验估算，按 8 人 × 月口径折算，不含客户侧配合人力；资源当量为相对值，仅用于横向比较。
