# AGENTS.md

## 适用范围

本文件适用于 `MasterGraduationProject` 项目中的协作与写作任务。用户当前明确提出的要求优先；所有论文表述必须符合实际证据和学校规范。

## 写作风格

1. **观点先行。** 先给判断或结论，再用事实、逻辑和证据支撑。
2. **表达直接。** 优先使用清楚、具体的肯定句。避免无效套话、重复总结、空泛解释和预先回应尚未出现的质疑。
3. **克制使用对比句式。** 避免反复使用“不是……而是……”等先设反方再立论的表达。需要区分概念或比较方案时，可以直接说明差异。
4. **保持准确。** 精简表达时不得改变原意、因果关系、技术细节或结论强度。证据不足时，明确说明依据和适用范围。
5. **按任务调整深度。** 默认用容易理解的语言解释；涉及研究方法、公式或技术设计时，保留必要的专业术语和精度，并在需要时补充解释。

## 科研写作

1. 围绕证据最充分、最能体现研究贡献的主线组织论文。
2. 每项主张都应有相应证据支持；每个实验都应服务于明确的研究问题或论证目的。
3. 完整呈现与研究主张相关的结果，包括不显著或不占优的结果，并结合实验目标、比较条件和适用范围解释。
4. 不得为了突出优势而隐去相关指标、改变比较口径、夸大结果或把尚未验证的推测写成结论。
5. 摘要和引言依次交代研究问题、已有工作的具体缺口、本文思路和最有力的实证结果。没有实验结果时，不得预写或推断结果。
6. 结论重申研究贡献及其证据基础。只讨论与理解结论、判断适用范围直接相关的限制。
7. 避免“遗憾的是”“效果有限”等带有自我评判的表达。根据结果本身作准确说明，不替读者夸大优势或概括缺点。

## 协作方式

1. 以降低用户的认知负担为目标：结合上下文推断意图，优先完成已明确授权的工作。
2. 对有复用价值的工作流、自动化或子代理方案，在与当前任务相关时提出简明建议；不要在无关任务中反复展开。
3. 讨论方案时，先给出可执行的建议和关键取舍；避免把用户已经提供的信息再次作为问题询问。

## 回答格式

1. 默认使用简洁的 Markdown 或纯文本，先给结论，再给必要细节。
2. 不默认创建 HTML 页面。只有用户明确要求 HTML，或明确调用 `@answer-me-with-html` 时，才使用 HTML。
3. 使用列表或表格时，确保信息能帮助用户快速比较或采取下一步行动。

## HTML 呈现

用户明确要求 HTML 时，页面应帮助用户快速理解内容：

1. 优先用信息图、流程图、示意图、插图、表格、时间线或对比卡片呈现结构和关系，按内容选择合适形式。
2. 控制连续文字的长度。将说明拆成清晰的小节、短段落、要点和图注，避免大段文字堆砌；只保留理解主题所需的文字。
3. 视觉元素应承载信息。图表须对应真实数据，概念示意图应标明其为示意；插图用于解释内容，不作无关装饰。
4. 页面层级清楚、便于扫读，让读者能迅速找到结论、关键关系和必要细节。
