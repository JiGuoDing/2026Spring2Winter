# 第一章研究设计：缓存价值建模与生命周期管理

> 文档性质：选题讨论稿，回答"1.1 价值建模到底对什么建模、怎么建模、输入输出是什么；1.2 生命周期具体研究什么、怎么做"。
> 与 `20261102大论文讨论.md` §1 对应；与 `20261102_与导师讨论初稿版本三.md` 研究点一的口径一致（三层派生状态、四类管理税、净收益核算）。
> 事实边界：Flink Agents 能力引自官方文档 1.0-SNAPSHOT；成本参数与复用率均需预实验测量，本文不预设数值。

## 0. TL;DR

**核心主张：缓存研究的优化目标应从 hit ratio 转向"单位资源的净收益 + 质量预算下的有效复用率"。**

两节的分工是一句老实话：

| 节 | 回答的问题 | 本质 | 交付物 |
| --- | --- | --- | --- |
| 1.1 价值建模 | "这个东西值多少钱？" | **估值**（valuation） | 一个校准过的价值函数 `V(x,t,c)` + 不确定性 |
| 1.2 生命周期 | "什么时候对它做什么？" | **控制**（control） | 一个策略 `π(state) → action` |

1.1 的输出是 1.2 的奖励信号；1.2 的日志是 1.1 的训练/校准数据。**两者不是并列，是一个闭环。**

## 1. 先把"建模对象"钉死

### 1.1 建模单元不是"层"，是"决策"

不要在"ctx / rag / resp 三层"上直接建模——层只是类型标签。真正要建模的是三元组：

```text
(x, t, c) = (状态项, 决策时刻, 请求上下文)
```

- `x`：一个具体的缓存对象实例（一条摘要、一个 RAG 块、一条历史回答）
- `t`：决策时刻（有请求到来、容量吃紧、版本变更、扩缩容）
- `c`：当前请求与系统状态

价值是这个三元组的函数，**不是对象的固有属性**。同一条历史回答，在空闲时几乎不值钱，在过载时可能值几十 GPU-秒——因为省下的是稀缺容量。

### 1.2 价值必须有反事实基线

```text
V(x,t,c) = E[ U(复用 x 服务 c) − U(不用 x、走重算) | F_t ]
```

没有基线的"价值"没有意义。这带来一个方法论问题：**两个分支只能观测到一个**。三种处理：

1. **模型两分支**（仿真/解析）——便宜，但依赖假设；
2. **随机留出**（如 5% 流量强制重算）——无偏，但有质量/成本代价；
3. **日志回放 + 倾向加权**（off-policy evaluation）——无额外代价，但方差大。

论文里必须明确选哪种，并报告估计偏差。这是本章最容易被审稿人攻击的点。

### 1.3 三个聚合粒度，一套模型

| 粒度 | 用途 | 形式 |
| --- | --- | --- |
| 单体 | 准入、淘汰、复用门控 | `V(x,t,c)` 标量 + 区间 |
| 层 | 预算分配（本章） | `F_l(s)`：给第 l 层 s 字节能换多少净收益 |
| 系统 | 与第二章联合配置 | `F(s_ctx, s_rag, s_resp; λ, ρ)` |

**同一套价值函数，三种聚合。** 这样第一章和第二章不是两个模型，而是一个模型的两个视图。

## 2. 1.1 价值建模：建什么、怎么建

### 2.1 六因子分解（建什么）

不要训练一个端到端回归器去直接吐"价值"。分解成六个因子，每个单独可估、可审计、可消融：

```text
V = p_use · B − C_verify − q_wrong · L − C_hold − C_churn
```

| # | 因子 | 含义 | 估计方式 | 关键难点 |
| --- | --- | --- | --- | --- |
| 1 | `p_use` | 该对象在未来窗口被再次使用的概率 | 生存分析/风险模型；或带衰减的计数 | 长尾、非平稳、会话结束即失效 |
| 2 | `B` | 命中时避免的真实工作 | **核算，不学习**：token 数、GPU-ms、远端字节、检索调用 | 单位统一（GPU-ms 为锚） |
| 3 | `q_wrong` | 命中但答错/过时/越权的概率 | 校准分类器（vCache 式门控）+ conformal 上界 | 标签稀疏、分布漂移 |
| 4 | `L` | 一次错误复用的效用损失 | 由质量基准标定的损失函数 | 不同层不可混用 |
| 5 | `C_verify` | 每次复用的验证开销（embedding/judge/ACL） | 直接测量 | 短回答上可能比回源更贵 |
| 6 | `C_hold` | 持有成本（存储、刷新摊销、机会成本） | 测量 + 影子价格 | 与容量约束耦合 |

**关键取舍：2 和 5、6 是"算"出来的，1、3 是"学"出来的，4 是"标定"出来的。**
把可算的东西交给学习模型，是这类论文最常见的失败原因。

### 2.2 每个因子的具体做法

**因子 1（复用机会）**：按对象类别建风险模型

```text
h_i(τ) = P(在 τ 时刻被再次访问 | 已存活到 τ)
```

- `ctx`：随会话剩余轮数衰减，会话结束即归零 → 用"剩余轮数"的生存模型
- `rag`：随知识热度呈 Zipf，用带衰减的访问计数即可
- `resp`：随查询重复率与时间衰减，是三层里最接近经典 IR 缓存的一层

**因子 2（收益）**：纯记账。命中 resp 省一次完整推理（prefill+decode）；命中 rag 省一次远端读取 + ANN；命中 ctx 省上下文组装 + 缩短 prompt。统一折算到 GPU-ms 与字节。

**因子 3（风险）**：这是唯一需要 ML 的地方，也是最容易做出"贡献"的地方。
输入是相似度、版本差、证据覆盖度、租户 ACL；输出是 `q_wrong` 的**上界**而非点估计。
必须报告：可靠性图、ECE、conformal 覆盖率、以及"决策后悔"（用上界 vs 用均值差多少）。

**因子 4（损失）**：分层标定，不混用——答案语义等价、检索正确性、摘要事实准确性、最终任务质量。

### 2.3 接口：输入与输出

**输入（决策时刻必须在线可得的廉价特征）**

```text
ValueInput {
  item: {item_id, layer, tenant, session, size_bytes, created_ts,
         last_access_ts, access_count, version_vector, prompt_fingerprint,
         source_refs[], ttl, tier}
  request: {query_embedding, top1_similarity, prompt_len, expected_out_len,
            session_turns_left, slo_class}
  system: {queue_len, utilization ρ, shadow_price λ, occupancy, cost_rates}
}
```

**输出（带不确定性与可解释原因）**

```text
ValueEstimate {
  p_use_now, p_use_horizon,
  benefit: {gpu_ms, tokens, bytes, calls},
  cost:    {verify_ms, hold_ms, churn_ms},
  risk:    {q_wrong_mean, q_wrong_ub, loss},
  net_value: {mean, p10, p90},
  action_hint: REUSE | VERIFY_THEN_REUSE | REFRESH_THEN_REUSE | RECOMPUTE,
  reason_codes: [...]
}
```

`action_hint` 与 `reason_codes` 不是装饰：没有它们，策略层无法调试，实验也无法归因。

### 2.4 三个可以写成论文的技术内核

#### 内核 A：价值的"影子价格"形式（把第一章和第二章数学上缝起来）

缓存命中省下的是容量，而容量的边际价值随负载变化。设容量约束为 `Σ work ≤ μ`，
其对偶变量 `λ = ∂U*/∂μ` 就是每 GPU-秒的影子价格，则：

```text
B_effective = λ(ρ) · w        w = 避免的工作量（GPU-秒）
```

- 低负载：`λ ≈ 0` → 缓存只买到时延，买不到吞吐 → 应少缓存（省 CPU/内存）
- 高负载：`λ` 大 → 同样一次命中值更多 → 应激进复用

**这条让"缓存价值"从静态属性变成系统状态的函数**，也解释了为什么固定阈值策略在不同负载下必然失效。
它是本章最有辨识度的建模贡献，且与第二章的容量控制共享同一个 `λ`。

#### 内核 B：从质量预算反推复用率（回答原文"根据阈值反推复用频率"）

设允许的错误回复比例为 `δ`，总请求数为 `N`，对象 `i` 被判错的概率 `q_i`、计划复用 `m_i` 次。
（注意：一个错误对象被复用 m 次会产生 m 条错误回复，所以必须按"次数"而非"对象"计数。）

```text
约束： Σ_i q_i · m_i  ≤  δ · N
```

这直接把"复用频率控制"变成一个**带风险预算的背包**：

```text
最大化 Σ_i v_i · m_i   s.t.  Σ_i q_i · m_i ≤ δN,  Σ_i m_i·size_i ≤ S
贪心：按 v_i / q_i 排序，依次准入，直到风险预算或容量耗尽
```

两个值得写进论文的推论：

1. **独立情形**：单一复用率上限 `r ≤ δ / q`（当 `q` 同质）。
2. **聚集情形**（热门对象被反复复用，错误完全相关）：错误不再独立，
   有效约束变成"错误对象覆盖的用户数"，因此需要**逐对象复用次数上限** `m_i ≤ m_max(δ)`，
   而不是全局比率。这一点现有工作（含 vCache 式阈值）普遍没有处理。

#### 内核 C：指纹稳定性 = 可缓存性的前提

若每次摘要重写都会改变 `prompt_fingerprint`，则回答缓存命中率趋近 0。
把"可缓存性"显式建模为一个概率：

```text
P(answer hit) ≈ P(fingerprint 在复用窗口内保持不变)
```

于是"冻结稳定前缀"不是工程技巧，而是一个**可建模的决策变量**：
重写频率↑ → 新鲜度↑、命中率↓；重写频率↓ → 反之。二者的最优点在 1.2 里求解（见 §3.3）。

### 2.5 怎么研究：四步法

| 步骤 | 做什么 | 产出 | 时长 |
| --- | --- | --- | --- |
| S1 测量 | 跑 3 类 Agent 负载（问答/RAG 调研/长会话），记录每次复用决策与结果 | 复用机会分布、对象价值/大小分布、漂移率 `θ`、错误率 `q` | 2–3 周 |
| S2 建模 | 按 §2.1 因子化估计；每因子单独验证 | 校准报告（ECE、覆盖率）、因子敏感性 | 2–3 周 |
| S3 决策评估 | 离线回放 + 小规模在线 | 相对 Oracle 的后悔、决策质量 | 2 周 |
| S4 消融 | 去掉影子价格 / 风险预算 / 冻结 / 依赖失效 | 每个机制的真实贡献 | 1–2 周 |

**S1 必须先做。** 如果实测语义重复率只有 3%，整章的收益前提就不成立，应立刻把重心从 `resp` 层移到 `ctx`/`rag` 层。这是本章最大的风险，也是最便宜的排除手段。

**评价指标不是 AUC/MAE，而是：**

- 净收益（GPU-ms 节省 − 管理税）
- 质量违约率（错误复用比例）与风险预算使用率
- 决策后悔（vs 知道未来的 Oracle）
- 校准质量（ECE、区间覆盖率）
- 命中精度（复用中通过验证的比例）

## 3. 1.2 生命周期：具体研究什么

### 3.1 三个决定

> **一个缓存项的一生，只需要回答三个问题：建不建、新不新、留不留。**

其他动作（迁移、预取、分层放置、恢复排序）都是这三个的工程变体，**基础版一个都不做**。

| 决定 | 什么时候问 | 唯一的权衡 | 简单规则 |
| --- | --- | --- | --- |
| **建不建** | 一次请求刚算完 | 创建成本 vs 未来会不会再问 | `p_use × V̄ > C_create` |
| **新不新** | 版本变了 / 到点了 | 刷新成本 vs 用旧数据服务的损失 | `T* = sqrt(2C_r/(λθℓ))` |
| **留不留** | 空间不够了 | 占地方 vs 将来要重建 | `p_use × V̄ / size` 最低的先走 |

三个规则共用一个输入：1.1 算出来的 `V̄`（这个对象一次复用值多少）。
**所以 1.2 不需要新模型，它只是 1.1 的价值函数在三个时刻的三种用法。** 这是本章能保持简单的根本原因。

### 3.2 四个触发器（替代状态机）

不需要状态机。生命周期里所有动作都由四个事件触发：

```text
请求到达   → 命中就直接用；没命中就重算，并决定"建不建"
版本变更   → 标记失效（下次重建）或立刻刷新（热对象）
时间到期   → 刷新（热对象）或淘汰（冷对象）
容量不足   → 淘汰价值密度最低的
```

一条时间线就画完了：

```text
第1轮 ──建──► 命中5次 ──政策变更──► 失效 ──重建──► 30天无人用 ──淘汰
```

### 3.3 唯一需要多想的耦合：刷新会杀死别人的命中

这是本章唯一"不显然"的地方，也是最值得写的一点。

摘要/事实每重写一次，`prompt_fingerprint` 就变一次 → 依赖它的回答缓存**全部失效**。
所以刷新不是免费的：

```text
刷新的真实成本 = 重算成本 C_r + 被它杀死的回答缓存的重建期望成本
```

**推论**：热对象应"冻结"稳定前缀（少刷、只增量），冷对象直接惰性失效。
这一条不需要新算法，只需要在 `C_r` 里把"杀死命中"的代价加进去。

### 3.4 最小实现

每个缓存项只需要这些字段：

```text
{ id, layer, size, created_at, last_hit, hit_count,
  version_vector, fingerprint, V̄, theta_class }
```

三个规则加起来不到 30 行伪代码：

```text
on_request(r):
    if hit(r) and valid(r): return cached
    ans = recompute(r)
    if p_use_class(r) * V̄ > C_create: admit(ans)      # 建不建
    return ans

on_version_change(item):
    if is_hot(item): refresh(item)                     # 新不新
    else:            mark_invalid(item)

on_capacity_pressure():
    while usage > budget:
        evict(argmin(p_use * V̄ / size))                # 留不留
```

参数只有五个：`p_use`（按类分档）、`V̄`、`C_create`、`θ`（按知识类型分档）、`C_r`。
**不要一上来就学 `p_use`**——先按"高频/中频/低频"三档，跑通了再考虑模型。

### 3.5 实验与对照（保持最小）

| 实验 | 对照 | 指标 |
| --- | --- | --- |
| 淘汰 | LRU / LFU / 价值密度 | 净收益、churn |
| 刷新 | 固定 TTL / TTL* / 不刷新 | 陈旧率、指纹一致率、净收益 |
| 建不建 | 全建 / 阈值建 / 不建 | 净收益、无效率 |

三层用**同一套规则**，只是 `θ`、`size`、`λ` 不同。不要给每层设计一套算法。

### 3.6 可选（时间够再做）：跨层预算

给定总预算 `S`，在 `ctx/rag/resp` 间分配，使 `Σ F_l(s_l)` 最大。
因为 `F_l` 边际递减，贪心/水位法即可，不需要新理论。
**默认不做**：先把三层各自的三个决定跑通，再考虑分配。

## 4. 两节如何衔接

```text
1.1 估值 ──► V 与不确定性 ──► 1.2 策略（奖励信号）
     ▲                              │
     └────── 决策日志与结果 ◄────────┘
```

写论文时的叙事线索建议：

1. 命中率不是好目标（反例：高命中率但错误复用/管理税高）
2. 所以要先定义"净收益"，并说明它依赖系统状态（影子价格）
3. 所以要控制"质量预算下的复用率"（风险背包）
4. 于是生命周期只需要回答三个问题：建不建、新不新、留不留
5. 其中唯一不显然的是"刷新会杀死别人的命中"（指纹耦合）

这是一条能自洽讲完的因果链，而不是"我做了三个模块"。

## 6. 判定性实验与负结果

| 预实验 | 问题 | 不通过时 |
| --- | --- | --- |
| P1 复用机会 | 语义重复率是否足够支撑缓存收益？ | <5% → 重心移到 ctx 层，resp 降为精确匹配 |
| P2 管理税 | 验证成本是否小于命中收益？ | 不划算 → 只对高价值对象启用验证 |
| P3 价值密度 | 是否显著优于 LRU？ | 差距小 → 淘汰策略降为工程细节 |
| P4 影子价格 | 负载变化是否真的改变最优策略？ | 不变 → 删除该机制，退化为固定阈值 |

负结果区间必须写进论文：低复用、重算便宜、知识高频更新、严格质量约束、低负载。
结论应是"机制何时有效、何时不值得启用"，而不是只挑有利负载。

## 7. 与第 2、3 章的接口

| 章 | 输入 | 输出 |
| --- | --- | --- |
| 1 → 2 | 有效到达率（复用短路后）、单位请求工作量分布、影子价格 λ | — |
| 1 ← 2 | 容量 μ、利用率 ρ、λ | 缓存预算建议 |
| 1 → 3 | 对象价值排序、会话粘性需求 | — |
| 1 ← 3 | 路由导致的命中/未命中、迁移事件 | 失效与重建触发 |

**反身性提醒**：扩缩容会导致会话迁移 → 缓存冷启动 → 复用率下降 → 有效负载上升。
这条反馈必须在第一章的价值模型里被显式表达（`C_churn` 与 `p_use` 都依赖它），否则第二章的控制器会算错账。

## 8. 风险与裁剪

1. **最大风险：复用机会不足。** 先做 P1，不要先写模型。
2. **第二风险：反事实不可观测。** 必须选一种估计策略并报告偏差，不能默认"省下的就是赚到的"。
3. **第三风险：范围膨胀。** 三层 × 七动作 = 21 个组合，四个月做不完。按 §5 的 MVP 裁剪。
4. **新颖性风险**：单看"带成本模型的缓存"接近经典 GDSF/\(\mathrm{GreedyDual}\)。必须靠
   影子价格、风险预算背包、指纹稳定性、刷新—命中耦合这四点立住。
5. **不要做的事**：不设计新的语义相似度算法、不建向量数据库、不碰 KV（已划归并行项目）。

---

## 9. 需要确认的三件事

1. 是否有真实（或半真实）Agent 会话 trace？没有的话，S1 只能靠公开数据集 + 合成器，结论强度要相应下调。
2. 第 1.1 是否允许"只到模型 + 离线评估"，还是必须落到在线系统？这决定 MVP 的大小。
3. 质量损失 `L` 的标定用哪套基准（LoCoMo/LongMemEval vs HotpotQA/MuSiQue），以及是否接受 LLM judge 的成本计入管理税。
