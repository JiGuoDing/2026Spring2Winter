0. 结论摘要

2026 年与 Agent 缓存相关的研究已经从“相同请求复用”明显转向四类问题：

  1. 语义命中是否可信：vCache、MVR-cache、LaCache、缓存投毒研究分别从逐条目错误率保证、多向量匹配、响应侧验证和对抗攻击角度处理正确性。
  2. 缓存集合如何优化：INFOCOM 2026 与 MobiHoc 2026 的工作把语义缓存从阈值问题推进到带失配成本、未知分布、连续查询空间和切换成本的优化问题。
  3. 缓存生命周期如何管理：Cortex、RAG-Cache、TVCACHE、C-DIC 以及一批 Agent memory 工作分别覆盖知识缓存、工具结果、上下文压缩、记忆合并和失效更新。
  4. 缓存如何评测与治理：Closing the Operational Gap、NDSS、LDPCache 等工作说明命中率、准确率和原始成本都不够，还要看可用命中、陈旧风险、安全风险和隐私预算。

对当前毕业设计第一章最有利的定位不是“再做一个多层缓存”，而是：

推荐定位

面向流式 Agent 的依赖感知缓存价值建模与生命周期控制。 研究重点从“相似度阈值”转向“净复用价值 + 状态有效性 + 生命周期动作”。

核心问题应从“相似度阈值是多少”推进为：

  • 这个缓存对象的未来复用概率有多大？
  • 命中它能节省多少真实工作，在动态负载下这些工作值多少钱？
  • 它的语义、来源、会话状态和工具环境是否仍然有效？
  • 验证、刷新、迁移和错误复用分别引入多少管理税与风险？
  • 在容量和质量预算约束下，什么时候准入、复用、刷新、降级和淘汰？

1. 收录与分类口径

1.1 缓存对象

本文使用以下五类逻辑对象描述 Agent 缓存：

类型 典型对象 主要收益 主要风险
resp 最终回答、回答模板、生成程序 短路完整推理或降低模型档位 语义误命中、答案过时、缓存投毒
rag 文档块、检索结果、知识子图、远端查询结果 避免重复检索、远端 I/O 和上下文拼装 来源版本变化、权限越界、证据不足
act 工具调用结果、执行观察、API 返回 避免重复调用和等待 环境状态不同导致相同调用产生不同结果
ctx 会话摘要、事实/约束、工作记忆、计划草案 减少上下文长度和重复压缩 摘要失真、事实冲突、旧状态未失效
control 准入、验证、刷新、淘汰、分层和路由决策 把缓存价值转化为系统动作 管理税、策略抖动、负载变化下失效

2.1 2026 年 CCF-B 以上正式主会/期刊

论文与作者 出处与状态 缓存对象与核心机制 对第一章的用途
vCache: Verified Semantic Prompt Caching — Luis Gaspar Schroeder et al. ICLR 2026 Poster；CCF-A；arXiv:2502.03771 为每个缓存回答在线学习独立相似度阈值，并用随机探索和悲观置信界满足用户指定的错误率上界。 直接支撑 q_wrong、质量预算和“不可见反事实”下的探索；是回答缓存质量门控的强基线。
MVR-cache: Optimizing Semantic Caching via Multi-Vector Retrieval and Learned Prompt Segmentation — Ali Noshad, Zishan Zheng, Yinjun Wu ICML 2026 Regular；CCF-A；arXiv:2605.24914 将 Prompt 学习式分段，以多向量检索和 MaxSim 做细粒度匹配，在正确性约束下最大化缓存命中。 说明“单 embedding + 单阈值”不足以表示复杂请求；可作为语义 key 设计和匹配成本的参考。
Semantic Caching for Low-Cost LLM Serving: From Offline Learning to Online Adaptation — Xutong Liu et al. INFOCOM 2026；CCF-A；DOI:10.1109/INFOCOM59046.2026.11571467 将语义缓存淘汰写成带查询失配代价的集合优化，并在查询分布和回源成本未知时学习缓存集合。 与净收益和淘汰问题最接近；可用于构造 p_use × saved_work − mismatch_loss 的理论基线。
Continuous Semantic Caching for Low-Cost LLM Serving — Baran Atalar et al. ACM MobiHoc 2026，已录用/DOI 在线；CCF-B；会议日期 2026-11-22 在连续 embedding 空间中对语义响应缓存建模，用动态 ε-net、Kernel Ridge Regression 处理不确定性和切换成本，并给出 sublinear regret。 为“查询空间连续、负载和回源成本随时间变化”提供理论接口，适合连接第一章与负载控制。
Cortex: Achieving Low-Latency, Cost-Efficient Remote Data Access for LLM via Semantic-Aware Knowledge Caching — Chaoyi Ruan et al. NSDI 2026；CCF-A；正式 proceedings pp. 2407–2421 缓存 Agent 发往远端搜索、RAG 或数据服务的“工具查询 → 知识结果”；ANN 召回、小模型 judger 验证、LCFU 淘汰、TTL 和预取组合。 rag 层最完整基线；提供命中验证、成本感知淘汰和预取的生命周期模板。
RAG-Cache: Efficient Query-Specific Knowledge Caching for Retrieval Augmented Generation — Haoying Jin, Haoyang Feng DASFAA 2026 Short Paper；CCF-B；First Online 2026-05-10 三层非冗余 RAG 知识缓存，使用 HARF（Hotness-Aware Rechecked FIFO）结合二次机会 FIFO 和 2-bit 引用计数。 补充 RAG 缓存的容量结构、并发吞吐和轻量替换策略；适合与传统 LRU/LFU/HARF 对比。
TVCACHE: A Stateful Tool-Value Cache for Post-Training LLM Agents — Abhishek Vijaya Kumar et al. ICML 2026 Regular；CCF-A；arXiv:2602.10986 用完整工具调用历史树做最长前缀匹配，只有 Agent 的工具调用历史一致时才复用工具结果，以保证环境状态一致。 工具结果不能只用“工具名 + 参数”做 key；是 act 依赖闭包、执行前缀和状态有效性建模的直接依据。
LaCache: Robust Semantic Caching for LLM Serving — Jiacheng Liang et al. NeurIPS 2026 Poster，已录用；CCF-A；arXiv:2608.01718 同时检查查询和推测生成的前 k 个 token 是否命中，用响应侧语义约束抵御 cache collision，并提升检索相关性。 说明命中判断应包含“响应是否可安全复用”的验证；可支撑 VERIFY_THEN_REUSE 动作。
From Similarity to Vulnerability: Key Collision Attack on LLM Semantic Caching — Zhixiang Zhang et al. ICML 2026 Regular；CCF-A；arXiv:2601.23088 将语义 key 看成 fuzzy hash，研究局部性与抗碰撞性之间的根本冲突，并在 Agentic workflow 中实施响应劫持。 把 key 完整性、租户隔离和对抗投毒纳入缓存价值；不能只以相似度估计正确率。
When Cache Poisoning Meets LLM Systems: Semantic Cache Poisoning and Its Countermeasures — Guanlong Wu et al. NDSS 2026；CCF-A；DOI:10.14722/ndss.2026.240200 系统展示语义缓存投毒攻击，在主流公有云环境中验证可行性，并评估现有提示注入防御为何失效。 支撑显式风险项 q_poison × L_security；说明“高命中”可能意味着更大的共享攻击面。
LDPCache: Locally Differentially Private Multi-Query Processing with Cache Optimization for Large Language Models — Haoqiang Shi et al. NeurIPS 2026 Poster，已录用；CCF-A 在多查询 LLM 服务中结合本地差分隐私、历史响应复用、期望准确率收益和多因素淘汰。 证明缓存复用必须受隐私预算约束；可扩展价值函数中的租户隔离和隐私成本。
Context-Driven Incremental Compression for Multi-Turn Dialogue Generation — Yeongseo Jung et al. ICML 2026 Regular；CCF-A；arXiv:2606.12411 把对话看成多个上下文线程，保存可修订的线程级压缩状态，通过 retrieve → revise → write-back 更新旧记忆。 支撑 ctx 的增量刷新和局部失效；避免每次版本变化都全量重写上下文。
ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL — Zhuoshi Pan et al. EMNLP 2026 Main Track；CCF-B；arXiv:2608.28476 用细粒度强化学习训练 Agent 主动执行检索、删除、摘要、压缩和长期记忆管理。 说明生命周期动作可以由状态相关策略学习，而不是依赖固定 TTL 或启发式阈值。

主表小结：正式主会/期刊共 13 篇，其中 CCF-A 10 篇、CCF-B 3 篇；已满足“至少 12 篇 2026 年 CCF-B+ 主会/期刊”的目标。

Closing the Operational Gap in Semantic Caching — Aditeya Baral et al. EMNLP 2026 Industry Track；CCF-B 场次但非主会；arXiv:2606.19719 提出 Precision–Cache Hit Ratio AUC 和 Operational Retention Rate，揭示离线 PR-AUC 与在线部署可用性之间的偏差。 第一章必须同时报告“命中了多少”和“在固定操作区间内有多少命中真正可用”。

3. 上下文与记忆生命周期近邻

这些论文不一定以 cache 命名，但它们直接处理“保留什么、压缩到什么保真度、何时重写、如何恢复”的问题，适合补强 ctx 层。

论文与作者 出处与状态 可借鉴内容
Sculptor: Empowering LLMs with Cognitive Agency via Active Context Management — Mo Li et al. ICLR 2026 Poster；CCF-A 给 Agent 提供分段、摘要、隐藏、恢复和精确搜索工具；对应上下文缓存中的 HIDE/RESTORE/COMPRESS 动作。
MemForest: Efficient Agent Memory Management via EventTree Partitioning and Progressive Merging — JunXi Wang et al. NeurIPS 2026 Poster，已录用；CCF-A 用事件树分区和渐进合并压缩冗余记忆；论文报告 50% 压缩下保留 99.7% 性能并获得 2.24× 检索加速。
MemCoRe: Recovering Evidence from Progressively Compressed Factual Knowledge for Agent Memory — Zhenyuan Zhang et al. NeurIPS 2026 Poster，已录用；CCF-A 研究从渐进压缩的事实记忆中恢复证据，适合建模“压缩保真度—恢复成本—质量损失”三角关系。
MGMem: An Efficient, Deterministic, and Provenance-Preserving Framework for Long-Horizon Agent Memory — Junhong Huang, Xin Tong, Jun Xia NeurIPS 2026 Poster，已录用；CCF-A 强调确定性、来源保留和长程记忆管理，可直接借鉴到缓存 provenance、版本和审计字段。
Remember the Decision, Not the Description: A Rate-Distortion Framework for Agent Memory — Mingxi Zou et al. NeurIPS 2026 Poster，已录用；CCF-A 只保留会影响后续决策的信息，并按决策冲突在线细化记忆分区；对应“缓存价值取决于未来决策”而非描述完整性。
Beyond RAG for Agent Memory: Retrieval by Decoupling and Aggregation — Zhanghao Hu et al. NeurIPS 2026 Poster，已录用；CCF-A xMemory 先从历史中解耦事实、更新和区分性细节，再聚合成可增量修订的层级记忆。
Learning Query-Aware Budget-Tier Routing for Runtime Agent Memory — Haozhen Zhang et al. ICML 2026 Regular；CCF-A 按查询和预算选择不同记忆层，为跨层容量分配、分层存储和缓存感知路由提供直接参考。
ACON: Optimizing Context Compression for Long-horizon LLM Agents — Minki Kang et al. ICML 2026 Regular；CCF-A 面向长程 Agent 优化上下文压缩，可作为 ctx 状态表示和 token 预算控制基线。
COMI: Coarse-to-fine Context Compression via Marginal Information Gain — Jiwei Tang et al. ICLR 2026 Poster；CCF-A 以 Marginal Information Gain 联合考虑相关性和冗余，说明“信息单元的价值”不能只由相似度衡量。
TokenPilot: Cache-Efficient Context Management for LLM Agents — Buqiang Xu et al. EMNLP 2026 Findings；CCF-B 场次但非主会 同时做 ingestion compaction 和生命周期驱逐，并显式权衡文本稀疏性与 prompt-prefix 连续性。

7. 现有第一章设计的主要缺口

7.1 从“命中价值”转向“净复用价值”

vCache 和 MVR-cache 解决的是“是否应当命中”，INFOCOM/MobiHoc 解决的是“缓存集合如何优化”，但它们大多把回源成本视为相对稳定的参数。第一章可以把计算资源稀缺性显式引入：

  • 低负载时，一次命中主要节省时延，GPU 影子价格较低。
  • 高负载时，同样的命中节省的是稀缺 GPU 时间，价值上升。
  • 但高负载也会提高刷新和重算成本，不能简单使用“越忙越激进复用”的一条规则。

这使缓存价值成为系统状态 c 的函数，而不是对象的静态属性。

7.2 从“语义相似”转向“依赖有效”

2026 年文献已经给出三个不同层次的有效性信号：

  • resp：LaCache 和缓存投毒研究表明，相似查询可能对应恶意或不可复用响应。
  • rag：Cortex 和 RAG-Cache 证明需要知识检索索引和成本感知淘汰，但来源版本仍是弱项。
  • act：TVCACHE 证明相同工具调用只有在完整执行历史一致时才能复用结果。

第一章应把缓存 key 从 semantic_key 扩展为 semantic_key + scope + version_vector + dependency_closure。

7.3 从“固定淘汰”转向“风险预算下的生命周期”

现有工作分别覆盖：

  • 淘汰：LCFU、HARF、prefix/LRU 类替换。
  • 刷新：C-DIC 的 revise/write-back。
  • 验证：vCache、Cortex、LaCache。
  • 压缩：MemForest、MemCoRe、ACON、COMI。
  • 恢复：MemCoRe、Sculptor。

但几乎没有工作统一回答“准入、复用、验证、刷新、降级、淘汰”六个动作之间的资源竞争关系。

7.4 从“单对象”转向“依赖闭包和失效传播”

建议把刷新成本写成：

C_refresh_total(i) =
  重算(i) 的成本
  + 因 i 变化而失效的下游对象期望重建成本
  + 刷新期间的短期质量损失

否则模型会系统性低估热对象刷新成本，也会忽略“刷新一个摘要会杀死多个回答缓存命中”的耦合。

7.5 从“离线命中率”转向“流式有效 goodput”

Closing the Operational Gap 和 ChurnBench 说明，离线排序好并不等于在线可用。第一章至少需要同时观察：

  • 有效命中率：通过验证且没有过期/越权的命中比例。
  • 质量违约率：错误复用和陈旧复用占总请求比例。
  • 净节省：节省的 GPU/检索资源减去验证、刷新、迁移和存储成本。
  • 决策后悔：相对知道未来复用结果的 Oracle 的损失。
  • 负载扰动下的恢复时间：扩缩容或路由变化后，命中率和 goodput 的恢复速度。

8. 建议的研究框架

建议定位

面向流式 Agent 的依赖感知缓存价值建模与生命周期控制。

8.1 建议标题

面向流式 Agent 的依赖感知缓存价值建模与生命周期控制

该标题比“Agent 多级缓存管理”更聚焦：核心不是堆叠缓存层，而是研究日志状态、版本依赖、质量风险与资源约束如何共同决定缓存价值。

8.2 三个研究问题

  1. 净价值估计：如何为一个带依赖闭包和版本状态的 Agent 缓存对象估计未来复用概率、工作节省、验证成本、陈旧风险和安全风险？
  2. 生命周期控制：在容量、质量、隐私和新鲜度约束下，如何联合决定准入、复用、验证、刷新、降级和淘汰？
  3. 流式状态落地：如何用 Flink keyed state、timer、broadcast dependency index、checkpoint 和 rescale 实现上述策略，并量化缓存迁移与冷启动代价？

8.4 扩展价值函数

V_i(t, c) =
    p_use · [ λ(ρ) · W_saved + β · latency_saved ]
  − C_verify
  − C_hold
  − C_refresh_total
  − C_churn
  − q_wrong · L_answer
  − q_stale · L_stale
  − q_security · L_security
  − q_privacy · L_privacy

其中：

  • λ(ρ) 是随系统利用率和容量约束变化的资源影子价格。
  • C_refresh_total 包含下游失效和重建成本。
  • q_security/q_privacy 不是一般准确率风险，而是租户隔离、投毒和隐私预算风险。
  • 所有成本最终统一到 GPU-ms、检索调用、token 或可比较的归一化成本。

8.5 建议的 MVP

MVP 原则

先让 resp + rag 的价值与失效链路闭环，再增加工具和计划缓存。不要同时铺开多种记忆架构。

第一阶段不要同时铺开所有缓存对象：

  1. 主对象 resp：复用 vCache/MVR/INFOCOM 的强基线，研究风险预算、容量和负载价格联合决策。
  2. 第二对象 rag：复用 Cortex/RAG-Cache 的结构，引入文档版本、来源和刷新。
  3. ctx 作为依赖源：记录会话摘要、事实和版本的变更，不先做完整通用记忆系统。
  4. act 作为扩展实验：用 TVCACHE 式执行历史前缀验证工具结果复用。
  5. 计划缓存作为后续扩展：参考 AgenticCache 和 SemanticALLI，不进入第一版 MVP。

9.1 预实验

10. 与现有项目材料的关系

10.1 保留的部分

现有材料中以下判断仍然成立：

  • 命中率不是最终目标，应使用净收益和有效复用率。
  • ctx/rag/resp 三层可以作为分析框架。
  • 价值建模与生命周期控制应组成一个闭环。
  • 影子价格、质量预算、指纹稳定性和刷新—命中耦合具有辨识度。
  • MVP 应先度量复用机会，再决定是否实现复杂模型。

10.2 需要调整的部分

  • 把 KV/prefix cache 文献集中放入边界小节，不与逻辑缓存主表混排。
  • 把 resp 研究从“相似度阈值”扩展到“验证、风险、集合优化和负载价格”。
  • 把 rag 的风险从“知识过期”细化为来源版本、依赖传播、权限和刷新成本。
  • 把 act 独立视为依赖完整执行历史的状态对象，不把它简单归入普通 RAG 文档。
  • 把 ctx 的压缩、降级和恢复纳入生命周期动作，而不是只作为 prompt 工程。
  • 在评测中增加 Operational Retention、stale error、security violation 和 rescale recovery。

11. 证据边界与后续核验

  1. 本文主表按 2026 年会议/期刊版本统计，不把 arXiv 首发时间当作正式发表时间。
  2. NeurIPS 2026 和 MobiHoc 2026 的若干论文在本文截止日期前已录用，但会议尚未召开；正式引用时应再次核对 camera-ready 版本。

  4. TVCACHE 的完整工具历史匹配解决的是“相同环境状态”问题，不证明所有工具结果都可跨用户、跨租户复用。
  5. vCache 和 MVR-cache 的错误率/正确性保证依赖各自的任务定义和评估集；不能直接外推到 RAG 事实正确性、工具副作用或安全攻击。
