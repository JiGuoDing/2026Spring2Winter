# 基于 Flink 的地球物理大模型流式推理与自适应调度系统

> Flink-based Streaming Inference and Adaptive Scheduling System for Geophysical Large Models

---

# 第一章 改进背景与动机

## 1.1 原始设计回顾

原始硕士毕业设计题目为"基于 Flink 的地球物理流式 RAG 智能推理系统"，其核心架构包含两个 Flink 任务：第一个 Flink 任务负责用户输入与地球物理数据的接入、处理、时空双流 Join 融合、RAG 检索增强、Prompt 构造及请求攒批；第二个 Flink 任务负责从 Kafka 读取批量推理请求，调用大模型推理框架完成推理，并进行结果输出、系统监控和负载自适应调控。该设计将流式计算与大模型推理相结合，具有一定的创新性，但其中"时空双流 Join"部分存在实现复杂度高、与地球物理业务耦合度大、实验验证困难等问题。

## 1.2 修改要求

经讨论，决定将原设计中与"双流 Join"相关的数据采集与融合部分全部删除，即不再处理实时地球物理数据流的接入和 Join 操作。这意味着系统不再直接处理原始地球物理观测数据流，而是将重心转向大模型推理服务本身的优化与调度。删除双流 Join 后，需要引入新的创新点来填补工作量和研究深度，同时保证课题的完整性和创新性。

## 1.3 改进思路概述

基于对地球物理大模型云服务平台、算力资源调度管理系统以及大模型推理部署技术的调研，本文提出以下三个核心创新点作为改进方向：第一，基于 Flink 的异构算力感知推理调度与弹性扩缩容，利用 Flink 的流式处理能力实时监控 GPU 负载并动态调整推理并行度和批处理大小；第二，大-小模型协同推理与动态路由，通过查询复杂度分析将简单查询路由至小模型、复杂查询路由至大模型，实现资源效率与推理质量的平衡；第三，基于 Tool-Calling Agent 的自适应调控，将原有 Agent 升级为具备工具调用能力的智能体，能够主动感知系统状态并执行调度策略。这三个创新点分别从资源调度、推理优化和智能控制三个层面构建了完整的研究体系。

# 第二章 改进后的系统总体架构

## 2.1 架构设计总体思路

改进后的系统仍然保留两个 Flink 任务的架构框架，但各任务的职责和内部组件发生了显著变化。第一个 Flink 任务从原来的"数据采集 + 双流 Join + RAG"调整为"RAG 检索增强 + 查询复杂度分析 + 模型动态路由 + 请求攒批"，其中查询复杂度分析和模型动态路由是新增的核心模块。第二个 Flink 任务从原来的"批量推理 + 监控 + Agent 调控"升级为"异构算力推理调度 + 大-小模型协同推理 + Tool-Calling Agent 自适应调控"，其中异构算力感知调度和 Tool-Calling Agent 是新增的核心模块。两个任务之间通过 Kafka 进行解耦通信，保证了系统的可扩展性和容错性。

## 2.2 第一个 Flink 任务：查询处理与路由层

第一个 Flink 任务负责用户查询的接入、处理和路由，具体包含以下几个核心组件：

### 2.2.1 用户查询接入与解析模块

该模块从 Kafka 或 REST API 接收用户的地球物理相关查询请求，对查询文本进行预处理，包括文本清洗、分词、命名实体识别等。与原设计不同的是，该模块不再处理原始地球物理观测数据流，而是专注于用户查询文本本身的理解与分析。该模块还负责提取查询的基本特征，如查询长度、是否包含专业术语、是否涉及多步骤推理等，为后续的复杂度分析提供基础数据。

### 2.2.2 RAG 检索增强模块（保留并增强）

该模块保留了原设计中的多级缓存机制，包括本地缓存、远程缓存和向量数据库缓存三个层次。在原有基础上增加了自适应 Top-K 调整策略：当查询复杂度较低时，减少检索文档数量以加速响应；当查询复杂度较高时，增加检索文档数量以提升推理质量。这种自适应策略与后续的查询复杂度分析结果联动，形成了从查询理解到检索策略的闭环优化。此外，还引入了基于查询模式的预测性缓存，对高频查询模式的检索结果进行预加载，进一步降低检索延迟。

### 2.2.3 查询复杂度分析与模型动态路由模块（新增）

这是改进后新增的核心模块，负责对用户查询进行复杂度评估并动态路由到合适的模型。复杂度分析基于多维度特征：查询文本长度、专业术语密度、是否涉及多步骤推理、是否需要数值计算等。基于这些特征，系统将查询分为简单、中等、复杂三个等级，并分别路由到小模型（如 7B 参数量的地球物理专用模型）、中等模型（如 14B 参数量）和大模型（如 72B 参数量）。这种级联路由策略能够在保证推理质量的同时显著降低资源消耗，尤其是在高并发场景下，大部分简单查询可以由小模型快速处理，释放大模型的算力资源。

### 2.2.4 请求攒批与优先级管理模块（增强）

该模块在原有攒批策略基础上增加了优先级感知的批次组装策略。不同复杂度等级的查询具有不同的优先级，复杂查询优先分配到大模型的推理资源，而简单查询则优先保证响应延迟。批次组装时，系统会将相同模型路由的请求聚合在一起，并根据模型的最优批处理大小进行组装，从而最大化 GPU 利用率。同时，该模块还支持超时丢弃和重试策略，保证系统在高负载下的稳定性。

## 2.3 第二个 Flink 任务：推理执行与调度层

第二个 Flink 任务负责实际的模型推理执行和系统调度，是改进后创新点最集中的部分，具体包含以下核心组件：

### 2.3.1 异构算力感知推理调度模块（新增）

该模块是改进后的核心创新点之一，解决的是地球物理大模型云服务平台中异构 GPU 资源的统一调度问题。在实际部署环境中，地球物理大模型通常需要在不同类型的 GPU 上运行（如 A100、V100、A10 等），不同 GPU 的显存容量、计算能力和带宽差异显著。该模块通过 Flink 的度量系统实时采集各 GPU 节点的负载指标（显存利用率、计算利用率、队列积压程度等），并基于这些指标动态调整推理任务的分配策略。具体而言，当某个 GPU 节点负载较高时，系统会自动将新请求路由到负载较低的节点；当某类型的 GPU 资源整体不足时，系统会触发弹性扩容操作。

### 2.3.2 大-小模型协同推理模块（新增）

该模块实现了基于查询复杂度的级联推理策略。系统同时部署大模型和小模型两套推理服务，小模型负责处理简单查询（如地球物理概念解释、简单数据查询等），大模型负责处理复杂查询（如多步骤推理、复杂数值计算、综合分析等）。当小模型的推理结果置信度低于阈值时，系统会自动将该查询升级到大模型重新推理，形成"小模型先行、大模型保底"的协同推理模式。这种策略在保证推理质量的同时，能够显著降低平均推理成本和响应延迟。

### 2.3.3 Tool-Calling Agent 自适应调控模块（新增）

该模块是对原设计中 Agent 的重大升级。原设计的 Agent 主要基于规则进行简单的负载调控，改进后的 Tool-Calling Agent 具备了工具调用能力，可以主动感知系统状态并执行复杂的调度策略。Agent 可以调用的工具包括：调整推理并行度、修改批处理大小、触发弹性扩缩容、切换模型路由策略、调整资源分配比例等。Agent 通过定期采集系统指标（如 GPU 利用率、请求队列长度、平均响应时间、推理成功率等），利用 LLM 进行决策，并通过工具调用执行具体的调度操作。这种基于 LLM 的调度方式相比传统的规则引擎更加灵活，能够处理未预见的负载模式和异常场景。

### 2.3.4 结果输出与反馈模块

该模块负责将推理结果写入 Kafka 供下游消费，同时将推理过程中的关键指标（推理延迟、Token 吞吐量、模型路由结果、置信度分数等）写入监控数据流，供 Tool-Calling Agent 和异构算力调度模块使用。如果查询被小模型处理但置信度低于阈值，该模块还会触发升级重推理流程，将查询重新发送到大模型的推理队列。

# 第三章 核心创新点详述

## 3.1 创新点一：基于 Flink 的异构算力感知推理调度与弹性扩缩容

### 3.1.1 问题背景

地球物理大模型的推理服务通常部署在包含多种类型 GPU 的异构集群上。例如，一个典型的地球物理算力平台可能同时包含 A100（80GB 显存）、V100（32GB 显存）和 A10（24GB 显存）等不同规格的 GPU。不同 GPU 的显存容量决定了其能够加载的模型规模和批处理大小，计算能力决定了推理速度，而带宽则影响数据传输效率。传统的推理服务通常采用静态分配策略，无法根据实时负载情况动态调整资源分配，导致部分 GPU 资源闲置而另一部分过载，整体资源利用率低下。

### 3.1.2 解决方案

本文提出一种基于 Flink 流式计算框架的异构算力感知推理调度方案。该方案的核心思想是利用 Flink 的实时流处理能力，将 GPU 资源监控、负载评估和任务调度统一在一个流式管道中实现。具体而言，系统通过 Flink 的 Source 算子实时采集各 GPU 节点的负载指标，通过状态管理维护各节点的资源快照，通过自定义分区器实现基于负载状态的请求分配。弹性扩缩容通过 Flink 的动态并行度调整实现：当系统检测到整体负载持续超过阈值时，自动增加推理算子的并行度；当负载降低时，自动减少并行度以释放资源。

### 3.1.3 关键技术细节

资源感知层通过定时轮询和事件驱动两种方式采集 GPU 指标。定时轮询通过 Flink 的 ProcessFunction 的 onTimer 机制实现，每隔固定时间间隔采集一次各节点的 GPU 指标；事件驱动则通过监听 GPU 节点的异常事件（如 OOM、推理超时等）触发即时采集。调度策略采用加权最少连接算法，权重计算综合考虑当前负载、GPU 计算能力和网络带宽三个因素。弹性扩缩容采用滑动窗口机制，避免因负载瞬时波动导致的频繁扩缩容。扩容触发条件为连续 N 个采样周期内平均负载超过阈值，缩容触发条件为连续 M 个采样周期内平均负载低于阈值。

## 3.2 创新点二：大-小模型协同推理与动态路由

### 3.2.1 问题背景

地球物理领域的查询需求具有明显的复杂度分化特征。一方面，大量查询属于简单的概念解释或数据查询，例如"什么是地震波的 P 波和 S 波""某测线的观测数据范围是多少"，这类查询可以由小模型快速且准确地回答。另一方面，少部分查询涉及复杂的多步骤推理或综合分析，例如"基于多台站观测数据分析该地区的地震风险"，这类查询需要大模型的强大推理能力。如果所有查询都由大模型处理，不仅造成算力资源的浪费，还会增加简单查询的响应延迟。

### 3.2.2 解决方案

本文提出一种基于查询复杂度分析的大-小模型协同推理与动态路由方案。该方案包含三个核心组件：查询复杂度评估器、动态路由器和置信度反馈机制。查询复杂度评估器基于多维度特征（查询长度、专业术语密度、推理步骤数、数值计算复杂度等）对查询进行分类，将其划分为简单、中等、复杂三个等级。动态路由器根据复杂度等级将查询分别路由到小模型、中等模型或大模型。置信度反馈机制是保障推理质量的关键：当小模型的推理结果置信度低于阈值时，系统自动将查询升级到大模型重新推理，确保最终输出的准确性。

### 3.2.3 关键技术细节

查询复杂度评估采用基于规则与基于学习相结合的混合方法。规则层面，定义了一组地球物理领域的复杂度指示规则，例如包含"反演""正演""全波形反演"等关键词的查询通常为复杂查询，包含"定义""是什么"等关键词的查询通常为简单查询。学习层面，基于历史查询数据训练一个轻量级的复杂度分类模型，用于处理规则难以覆盖的边界情况。置信度评估采用两种方式：一是基于模型输出的 logprob 计算平均置信度，二是基于小模型与大模型输出的一致性判断。当平均置信度低于阈值或小模型输出与历史大模型输出差异较大时，触发升级重推理。

## 3.3 创新点三：基于 Tool-Calling Agent 的自适应调控

### 3.3.1 问题背景

原设计中的 Agent 主要基于预定义规则进行负载调控，例如"当 GPU 利用率超过 80% 时减少并行度"。这种规则引擎的问题在于：第一，规则难以覆盖所有可能的系统状态组合，存在规则盲区；第二，多条规则之间可能存在冲突，需要人工调解；第三，规则更新需要重启服务，无法在线调整。在地球物理大模型推理场景中，负载模式具有明显的时变性（如地震事件后查询量突增），传统规则引擎难以适应这种动态变化。

### 3.3.2 解决方案

本文提出将 Agent 升级为具备 Tool-Calling 能力的智能体。Tool-Calling Agent 的核心思想是：将系统调度操作抽象为一组"工具"，Agent 基于当前系统状态自主决定调用哪些工具以及传入什么参数。这种方式的优势在于：Agent 可以综合考虑多个指标的关系，做出更加合理的调度决策；Agent 可以处理未预见的系统状态，不受预定义规则的限制；Agent 的调度策略可以通过 Prompt 在线调整，无需重启服务。

### 3.3.3 工具定义与调度流程

Agent 可调用的工具集包括以下几类：

- **资源管理类工具**：`adjust_parallelism`、`scale_inference_instances`、`modify_batch_size`
- **模型路由类工具**：`switch_routing_strategy`、`adjust_complexity_threshold`、`toggle_confidence_escalation`
- **系统配置类工具**：`update_cache_policy`、`set_timeout_threshold`

调度流程如下：Agent 定期从监控数据流中获取系统状态摘要，将状态信息和可用工具列表一同输入 LLM，LLM 生成工具调用指令，Agent 执行工具调用并观察执行结果，如果结果不符合预期则进行调整。这种"感知-决策-执行-反馈"的闭环流程使得 Agent 能够持续学习和优化调度策略。

# 第四章 实验方案设计

## 4.1 实验环境

实验环境需要包含以下组件：一个包含多种类型 GPU 的集群（建议至少包含两种不同规格的 GPU，如 A100 和 V100），用于验证异构算力调度的效果；Apache Flink 1.18+ 集群，用于运行两个 Flink 任务；Kafka 集群，用于任务间通信和数据缓冲；向量数据库（如 Milvus 或 Elasticsearch），用于 RAG 检索；大模型推理框架（如 vLLM 或 TGI），用于提供推理服务。如果硬件资源有限，可以使用同一类型 GPU 但配置不同的资源限制来模拟异构环境。

## 4.2 实验数据集

实验数据集需要包含两部分：地球物理领域的知识库（用于 RAG 检索）和查询测试集（用于评估系统性能）。知识库可以从地球物理学术论文、教材、技术报告等来源构建，建议规模在万级文档以上。查询测试集应包含不同复杂度等级的查询，建议按照简单:中等:复杂 = 5:3:2 的比例构建，总量不少于 500 条查询。同时需要构建负载模拟数据，用于测试系统在不同并发量下的性能表现。

## 4.3 实验设计与评估指标

### 4.3.1 实验一：异构算力感知调度实验

该实验旨在验证异构算力感知调度的有效性。实验分为三组：基线组采用静态分配策略（轮询或随机分配），对照组采用基于负载的加权调度策略（不包含弹性扩缩容），实验组采用完整的异构算力感知调度与弹性扩缩容方案。在不同并发量（10、50、100、200 QPS）下测量以下指标：平均响应时间、P99 响应时间、GPU 利用率、资源分配均衡度、系统吞吐量。预期实验组在高并发场景下的 GPU 利用率比基线组提升 20% 以上，平均响应时间降低 15% 以上。

### 4.3.2 实验二：大-小模型协同推理实验

该实验旨在验证大-小模型协同推理的效果。实验分为三组：基线组所有查询均由大模型处理，对照组采用固定规则路由（基于查询长度阈值），实验组采用基于复杂度分析的动态路由与置信度反馈机制。测量指标包括：平均推理延迟、推理结果准确率（与大模型单独推理结果的一致性）、算力资源节省率、升级重推理触发率。预期实验组的平均推理延迟比基线组降低 30% 以上，推理准确率与基线组的差异不超过 5%，算力资源节省率达到 40% 以上。

### 4.3.3 实验三：Tool-Calling Agent 自适应调控实验

该实验旨在验证 Tool-Calling Agent 的调度效果。实验分为三组：基线组采用传统规则引擎调度，对照组采用基于 PID 控制器的自动调度，实验组采用 Tool-Calling Agent 调度。实验场景包括：负载突增场景（模拟地震事件后查询量突增）、负载波动场景（模拟日周期性负载变化）、异常场景（模拟节点故障和恢复）。测量指标包括：调度响应时间（从异常发生到调度生效的时间）、系统稳定性（调度后系统指标恢复正常的时间）、调度决策合理性（专家评估）。预期实验组在负载突增场景下的系统恢复时间比基线组缩短 30% 以上。

## 4.4 实验对比基线汇总

| 实验 | 基线组 | 对照组 | 实验组 |
|------|--------|--------|--------|
| 实验一 | 静态分配 | 负载加权调度 | 异构感知 + 弹性扩缩容 |
| 实验二 | 全大模型推理 | 固定规则路由 | 复杂度动态路由 + 置信度反馈 |
| 实验三 | 规则引擎调度 | PID 控制器 | Tool-Calling Agent |

# 第五章 可行性分析

## 5.1 技术可行性

从技术角度看，三个创新点均基于成熟的技术栈实现，不存在技术壁垒。异构算力感知调度主要依赖 Flink 的状态管理和度量系统，这些都是 Flink 的核心能力，实现难度不大。大-小模型协同推理的核心是查询复杂度分析和置信度评估，复杂度分析可以基于规则和简单的机器学习模型实现，置信度评估可以利用模型输出的 logprob 信息。Tool-Calling Agent 可以基于现有的 LLM API（如 OpenAI Function Calling 或开源模型的工具调用能力）实现，不需要从零训练模型。总体而言，三个创新点的实现难度适中，在硕士阶段的时间和资源约束下是可行的。

## 5.2 工作量分析

从工作量角度看，三个创新点的工作量充裕且分布合理。异构算力感知调度模块的工作量主要在于资源监控的实现、调度算法的设计与实现、弹性扩缩容的触发逻辑，预计需要 3-4 周。大-小模型协同推理模块的工作量主要在于复杂度分析模型的训练、动态路由的实现、置信度反馈机制的实现，预计需要 3-4 周。Tool-Calling Agent 模块的工作量主要在于工具定义、Agent 逻辑实现、调度流程设计，预计需要 2-3 周。实验设计与执行预计需要 3-4 周。论文撰写预计需要 3-4 周。总体工作量约为 14-19 周，符合硕士毕业设计的时间要求。

## 5.3 创新性分析

三个创新点的创新性体现在以下方面：第一，将 Flink 的流式计算能力与异构 GPU 资源调度相结合，这是一个较新的研究方向，现有工作主要关注 Kubernetes 等容器编排层的调度，而非流式计算框架层面的调度。第二，将大-小模型协同推理应用于地球物理领域，并结合置信度反馈机制，这在地球物理大模型推理服务中尚无先例。第三，将 Tool-Calling Agent 应用于流式推理系统的自适应调控，这是将 LLM Agent 技术与流式计算系统管理相结合的新尝试，具有明确的创新价值。三个创新点从不同层面（资源层、推理层、控制层）构建了完整的研究体系，避免了单一创新点的单薄感。

## 5.4 风险与应对

主要风险包括：第一，异构 GPU 环境的获取困难，应对策略是使用同类型 GPU 但配置不同资源限制来模拟异构环境。第二，大-小模型的推理质量差异可能导致升级重推理率过高，应对策略是充分测试小模型在地球物理领域的能力边界，合理设置复杂度阈值。第三，Tool-Calling Agent 的调度决策可能不稳定，应对策略是设置调度操作的安全边界（如并行度调整范围、批处理大小上限等），防止 Agent 做出极端调度决策。第四，实验数据集的构建需要地球物理领域专业知识，应对策略是与导师和同门合作构建测试数据。

# 第七章 总结与展望

## 7.1 改进总结

本文针对原硕士毕业设计中双流 Join 部分删除后的创新点缺失问题，提出了三个核心创新点作为改进方向。创新点一"基于 Flink 的异构算力感知推理调度与弹性扩缩容"解决了地球物理大模型推理中异构 GPU 资源的统一调度问题，通过 Flink 的流式处理能力实现了实时负载监控和动态资源分配。创新点二"大-小模型协同推理与动态路由"通过查询复杂度分析和置信度反馈机制，实现了推理质量与资源效率的平衡。创新点三"基于 Tool-Calling Agent 的自适应调控"将传统规则引擎升级为具备工具调用能力的智能体，显著提升了系统的自适应能力。三个创新点从资源层、推理层和控制层三个维度构建了完整的研究体系，既保证了创新性，又确保了实验可行性。

## 7.2 未来展望

未来可以从以下方向继续深入研究：第一，引入推测性调度，基于历史负载模式预测未来负载变化，提前进行资源调整。第二，探索基于强化学习的调度策略，让 Agent 通过与系统的交互自主学习最优调度策略。第三，将系统扩展到多模态地球物理推理场景，支持图像、时间序列等多种数据模态的推理请求。第四，研究基于 Flink 的分布式推理缓存与增量推理机制，进一步降低推理延迟和资源消耗。
