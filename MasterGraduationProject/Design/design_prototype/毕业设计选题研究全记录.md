## 0.3 最终结论速览

当前研究的最新结论（截至 2026-08-13）：

1. **主线方向**：选题三「多轮会话（Agentic）负载下的流式大模型推理服务质量保障」，三个研究点 = 会话行为在线分布预测（感知）→ 驻留-流处理参数联合优化（决策）→ 会话感知调度与 KV 驻留控制（执行）。
2. **三点组合**：方案一「会话状态感知」为最主推，方案二「异构 SLO 保障」为实验受阻退路，方案三「多维资源效率」为备选。
3. **最新升级方向**：语义库/语义记忆——把复用粒度从"会话前缀"提升到"语义级"，以 Memory Tax（记忆税）为故事引擎，是选题三的语义化、通用化、跨会话化升级。
4. **关键差异化锚点**：现有工作（Continuum/IntentKV/Leyline/RKSC/SwiftCache、vCache/Cortex）都在"引擎内"或"单机"打补丁，本课题在**流处理层**做"语义记忆 × SLO × 推理资源"的联合控制，层级差异清晰。

# 第一部分 · 项目基底

> 来源：`毕业设计选题候选池_v2.md` §2、`AGENTS.md`、`InferTuner_positioning_vs_vLLM_SGLang.md` 摘要。

## 1.1 InferTuner 概览与三大核心组件

InferTuner 是一个基于 Apache Flink 的流式 LLM 推理管线系统级控制器。主管线为：

```
NJULocalRequestSource（读 prompt/workload，发射请求）
  → InferenceStateFetcherProcessor（keyBy(userId)，Operator State 存缓存条目）
  → InferenceRequestBatcherProcessor（并行度 1，攒批到 batchsize）
  → NJULocalInferenceAsyncProcessor（异步调 TCP 推理服务 / vLLM）
  → NJULocalCacheTestSink（聚合时延/SLO/GPU 指标，写 CSV + 上报守护进程）
```

三大核心组件：

| 组件 | 现状 |
|---|---|
| **推理时延预测** | token 数预测（BGE-m3 embedding + PCA + 5 层 MLP，MAPE 5–13%）+ 算子级单 token 生成时间预测（GBDT，特征含 batch/layer/prompt 长度/生成位置 `post_token_num`） |
| **FREQUENCY 动态缓存** | 基于访问频率分布动态调整缓存容量 S，命中率与 P95 时延全面优于 STATIC/FLUID |
| **PB 联调（MCKP DP）** | 并行度 p × 批次 b 的离散组合搜索，SLO 约束下最小化 GPU 数，对比 DS2/ContTune 全面占优 |

## 1.2 系统定位（vs vLLM / SGLang）

InferTuner 不是另一个 LLM inference engine，也不是 LM programming runtime，而是**基于 Flink 流处理系统的系统级资源控制与编排层**：

| 对比维度 | vLLM | SGLang | InferTuner |
|---|---|---|---|
| 系统定位 | LLM inference engine | LM program 语言与运行时 | Flink 流式推理管线的系统级控制器 |
| 核心问题 | KV cache 内存碎片化导致的吞吐瓶颈 | multi-call LM program 执行低效 | 动态负载下端到端 SLO 合规的资源扩缩容 |
| 控制对象 | KV cache 块、请求调度、token 生成 | KV 跨调用复用、约束解码、多调用并行 | 推理算子并行度 p、上游批次 b、缓存容量 S |
| 工作粒度 | token/request 级 | program call/instance 级 | operator/pipeline 级 |
| 底层框架 | PyTorch + CUDA | PyTorch + CUDA | Apache Flink |
| 与另两者关系 | 可封装为 inference backend | 可封装为 inference backend | 将两者视为可插拔 backend，在其外部做控制 |

一句话：**vLLM/SGLang 解决"单个推理后端如何更快地跑"，InferTuner 解决"在 Flink 数据流里如何决定开多少个推理 operator、上游如何分批、状态缓存如何扩缩，以满足端到端 SLO"。** 三者不重复、可组合。

## 1.3 基底可复用资产清单

| 资产 | 复用方式 |
|---|---|
| 推理时延预测（token 数 + 算子级 GBDT） | 作为各选题"点 1 感知"的离线基础模型；GBDT 特征已含 `post_token_num`，天然支持 JIT 精化 |
| FREQUENCY 动态缓存 | 频率统计可复用为"复用热度"统计，支撑驻留/淘汰决策 |
| MCKP DP 择优 | 决策变量可平滑扩展（KV 驻留 TTL、DVFS 频率、max_tokens、语义库容量等） |
| `InferenceStateFetcherProcessor` | 语义上就是"会话状态管理"算子——多轮会话 KV 驻留、语义记忆的天然载体 |
| 完整实验平台 | Flink 1.17 管线 + vLLM 集成 + HDFS workload + 真实流量 trace（casestudy_workloads）+ 各类 CSV 结果与绘图脚本 |
| 硬件 | H20-141G / A6000 均支持 `nvidia-smi` 功率读取；**实验机无管理员权限**（不涉锁频/功率封顶） |

## 2.1 v1 三选题演进说明

v1 给出「一条骨架 + 三个选题」：点 1（感知）与点 2（决策）三选题共用，点 3（执行）三选一。

- **选题一**：双时间尺度闭环——点 3 = 请求级调度（EDF/SRTF 预测驱动）；
- **选题二**：漂移驱动的自适应闭环——点 3 = 无中断重配置（开销建模 + 切换门控）；
- **选题三**：多租户扩展——点 3 = 多租户公平分配。

v2 在此基础上扩展：候选从 3 个增加到 6 个，新增「会话状态感知（Agentic 多轮）」「能耗感知」「调优成本本身」三个完整选题；并把三点拆成可替换模块（点 1 三种变体 × 点 2 三种变体 × 点 3 六种变体）。

## 2.2 v2 文献格局五趋势（新候选的研究土壤）

v2 的全部新候选都从以下五个真实趋势中长出：

1. **预测从"点估计"走向"区间预测 + 运行时精化"**：Tempo（QRF 区间）、JITServe（NSDI'26，解码中持续修正长度预测）、llm-d 生产实践（在线训练 TTFT/TPOT 预测，MAPE≈5%）。
2. **Agentic/多轮负载成为一级服务场景**：Continuum（ICLR'26，KV 驻留 TTL）、MARS、KAIROS；vLLM×Mooncake 生产 trace（94.2% 前缀命中、131:1 输入输出比、中位 33 轮）；MLPerf 2026-07 官方 Agentic Inference 基准。
3. **能耗成为服务系统的一等公民**：GreenLLM（DAC'26，分相位 DVFS，能耗 −34%）、throttLL'eM（迭代级调频）。
4. **调优本身走向"低成本、可迁移、混合保真"**：AutoScout（稀疏 MCTS + 保真自适应）、SageServe（SoCC'25，流量预测 + ILP，省 25% GPU-hours）、ZeroTune（ICDE'24）。
5. **Flink 官方全面转向"Data + AI 平台"**：Flink 2.1/2.2 引入 AI Model DDL + `ML_PREDICT` + `VECTOR_SEARCH`，FLIP-577 提出 AI 时代范式转型。

## 2.3 v2 六个打包选题

### 选题一（继承 v1 主推）：双时间尺度闭环——区间预测驱动的流式推理自适应控制

- **研究出发点**：现有预测驱动调度全部假设预测是精确点估计，但 Tempo 证明点估计会系统性低估导致 SLO 违约，JITServe 证明"到达时信息不精确"应作为设计前提。
- **点 1 = P1-b**（区间预测 + 生成中 JIT 精化）；**点 2 = P2-a**（机会约束 MILP）；**点 3 = E1**（预测驱动请求调度）。
- 推荐度 ★★★★★。

### 选题二：漂移驱动的自适应闭环——预测-择优-重配置时机优化

- **研究出发点**：基底双阈值触发器是纯启发式；StreamShield 证明防抖/回滚是工业刚需；"切换成本 vs 失配损失"有干净的抽象（ski-rental 类在线问题，MC-SF 可做竞争比分析）。
- **点 1 = P1-a/b**；**点 2 = P2-a**；**点 3 = E2**（重配置开销建模 + 切换门控）。
- 推荐度 ★★★★☆。

### 选题三（v2 全新，已选定）：会话状态感知的多轮流式推理——Flink 有状态流处理 × Agentic 负载

- **研究出发点（三层证据）**：① 负载变了（多轮会话的统计特征与单轮完全不同）；② 系统错位了（现有引擎都在引擎内打补丁，而会话状态本质是流处理的 keyed state）；③ 时机对了（MLPerf 刚发布 Agentic 基准）。基底 `InferenceStateFetcherProcessor`（keyBy(userId) + 状态缓存）就是现成的会话状态算子。
- **点 1 = P1-c**（会话行为预测：剩余轮次、工具间隔、上下文增长）；**点 2 = P2-a 变体**（决策变量新增 KV 驻留 TTL/预算）；**点 3 = E3**（会话感知调度 + 驻留门控）。
- 推荐度 ★★★★★。【2026-08-08 用户已选定为本毕设方向】

### 选题四：能耗感知的流式推理服务——从"省卡"到"省电"

- **研究出发点**：推理能耗已占 LLM 生命周期能耗主体；GreenLLM 证明分相位 DVFS 省 34% 能耗；流处理语境下的能耗控制尚属空白。
- **点 1 = P1-b 变体**（时延与能耗双预测）；**点 2 = P2-a 变体**（决策变量新增 SM 频率档位）；**点 3 = E4**（相位感知功率控制）。
- 风险：**实验机无管理员权限，锁频（nvidia-smi -lgc）与功率封顶（-pl）不可行**，点 3 须降级为"纯测量 + 离线频率建议器"。
- 推荐度 ★★★★☆。

### 选题五：让调优更便宜——可迁移成本模型与混合保真参数搜索

- **研究出发点（直接回应审稿意见）**：基底 HPDC'26 审稿人明确质疑 profiling 成本与调优开销。
- **点 1 = P1-a 变体**（成本模型少样本迁移，分层模型 + 标定层）；**点 2 = P2-b**（混合保真搜索）；**点 3 = E5**（漂移触发的在线轻量重调优）。
- 推荐度 ★★★★☆。

### 选题六（继承 v1 选题三）：多模型多租户共享 GPU 池——路由 × 调度 × 分配三级控制

- **研究出发点**：生产多模型 serving 已是主线；RouteBalance 证明路由必须感知实例负载，但其路由是无资源规划的贪心。
- **点 1 = P1-a/b**；**点 2 = P2-a + 租户间加权 max-min 公平分配**；**点 3 = E6**（请求路由层）。
- 推荐度 ★★★☆☆（变量最多，4 个月周期下建议作为备选）。

# 第三部分 · 锁定方向：选题三（会话状态感知）

> 来源：`选题三_开题报告.md` + `选题三_技术方案设计书.md`。两份互补：开题报告是学术叙事（为什么做、现状、关键问题、创新点），技术方案设计书是工程蓝图（怎么建、怎么测）。

## 3.1 开题报告（全文）

### 论文题目（备选三个）

1. **面向多轮会话负载的流式大模型推理服务质量保障关键技术研究**（推荐）
2. 会话状态感知的 Flink 流式 LLM 推理服务资源优化方法研究
3. 面向 Agentic 负载的流处理系统推理服务质量保障：预测、规划与调度

（英文参考：*SLO Assurance for Streaming LLM Inference under Multi-Turn Conversational Workloads: Prediction, Planning, and Scheduling on Apache Flink*）

### 一、研究背景与意义

**1.1 大模型推理负载正在从"独立单轮"转向"多轮会话"**

LLM 智能体（Agent）规模化落地后，推理请求不再是独立问答，而是多轮会话中的一个环节。2026 年公开生产 trace 显示：典型 agent 会话中位 33 轮，上下文增长至 8 万 token 量级，**94.2% 的输入前缀可跨轮复用**，输入:输出 token 比高达 131:1，轮间间隔由工具执行决定、中位秒级但长尾可达分钟级。MLCommons 于 2026-07 发布官方 Agentic Inference 基准，标志多轮会话负载已成为标准化评测对象。

负载形态转变使既有优化结论部分失效：轮间共享前缀使 KV cache 从"一次性计算的副产品"变为"跨轮有价值的持久状态"；轮间隔的高度可变使"完成即淘汰"与"无条件驻留"两种极端策略都造成显著浪费。

**1.2 流处理系统是承载会话式推理的自然底座，但其资源控制机制尚未适配**

Flink 2.1/2.2 官方引入 AI Model DDL 与 `ML_PREDICT`、`VECTOR_SEARCH`，将模型推理确立为一等流处理算子。会话状态在语义上正是流处理中的键控状态（keyed state）。然而现有研究在两个阵营之间留出空白：

- **流处理系统调优阵营**（DS2、ContTune、StreamTune）以无状态/弱状态算子和确定性处理时间为假设，不感知 LLM 推理的自回归变长特性，更不感知会话结构；
- **LLM serving 阵营**（vLLM、SGLang 及 Continuum、MARS、KAIROS）在推理引擎内部优化 KV 管理与调度，对流处理语境中的排队、批聚合、背压、并行副本编排黑盒。

本课题认为：多轮会话负载下的推理服务质量保障，需要在流处理层建立"感知—决策—执行"闭环。

**1.3 研究意义**

- **理论意义**：将"会话 KV 驻留"形式化为收益-成本可核算的在线决策问题，并纳入含机会约束的联合配置优化模型。
- **应用价值**：在已有 Flink 流式 LLM 推理实验平台（InferTuner）上开展，2–4 张 GPU 即可复现。
- **方向契合**：同时处于 Flink 官方 Data+AI 转型与 2026 年 serving 系统前沿（Agentic）的交汇点。

### 二、国内外研究现状

**2.1 流处理系统的资源调优与弹性伸缩**：DS2（OSDI'18）、ContTune（VLDB'23）、StreamTune（2025，GNN）、StreamShield（2026，生产弹性稳定性）、Justin（2025，CPU/内存混合弹性）。均以通用流处理算子为对象，未涉及 LLM 推理的变长执行与状态化负载。

**2.2 LLM 推理服务系统**：vLLM（SOSP'23，PagedAttention）、SGLang（NeurIPS'24，RadixAttention）、DistServe（OSDI'24，prefill/decode 分离）、Mooncake（FAST'25，KVCache 中心分布式池）、Strata/Contextra（OSDI'26，层级缓存）。均优化单引擎内部，不处理流处理语境。

**2.3 预测驱动的推理调度**：S3（输出长度预测）、PARS（成对排序近似 SJF）、ELIS（BGE 响应长度预测 + ISRTF）、Tempo（分位数回归区间预测）、JITServe（NSDI'26，解码中持续修正预测）、llm-d 生产实践（在线训练 TTFT/TPOT 预测）。趋势：从离线点估计走向区间预测与在线精化。但均面向单轮独立请求，未建模会话级行为。

**2.4 Agentic/多轮负载的 serving 系统**：Continuum（ICLR'26，KV 驻留 TTL，JCT 改善 8×）、MARS（GPU-CPU 耦合调度）、KAIROS（功耗管理）、Agentix（NSDI'26，agent 程序一等调度实体）、KunServe（EuroSys'26）、Concur（ICML'26，准入控制）。均未利用流处理系统的 keyed state 与容错语义。

**2.5 配置择优与数学规划方法**：AutoScout（结构化搜索 + 混合保真）、SageServe（SoCC'25，流量预测 + ILP）、vCache（ICLR'26，语义缓存阈值在线学习）。

### 三、研究目标与拟解决的关键问题

**总目标**：面向多轮会话负载，在 Flink 流处理层构建"预测（感知）→ 规划（决策）→ 调度（执行）"闭环的推理服务质量保障系统，以最少 GPU 资源满足会话级与轮次级 SLO。

**三个关键问题**（相互独立、依次衔接）：

1. **多轮会话推理行为的可预测性问题**（感知）：会话的轮间隔、剩余轮数、上下文增长受工具执行与环境交互驱动，兼具规律性与强随机性。研究这些量的**分布级**在线预测方法，并给出漂移下的在线校准机制。
2. **会话状态驻留的收益-成本量化与联合配置问题**（决策）：KV 驻留的收益与成本均随负载动态变化。研究其解析量化模型，并将驻留参数与流处理参数纳入统一的机会约束混合整数规划。
3. **流处理语义下会话感知控制的一致性与低开销问题**（执行）：驻留决策状态需随 Flink checkpoint 容错、随并行度变化迁移；亲和路由需在扩缩容时最小化会话迁移。

### 四、研究内容（三个研究点）

**研究点 1：多轮会话行为的在线分布预测（感知层）**
- 预测目标：轮间隔 d、剩余轮数 T_rem、上下文增长 g 的**分布**（分位数）；
- 方法：工具类型 × 轮次区间分桶的分位数在线估计（EWMA）为基础版，分位数回归森林（QRF）为进阶对照；在线 conformal 校准保证名义覆盖率；漂移检测触发校准加速；
- 验证：覆盖率误差、校准收敛速度、以及"预测驱动门控 vs oracle 门控"的下游 JCT 差距（目标 ≤10%）。

**研究点 2：驻留感知的联合配置优化（决策层）**
- 建模：决策变量 = (并行度 p, 批次 b, TTL 分位 q, 驻留显存预算 M_kv)；目标 = 最小 GPU 成本；约束 = 会话 JCT 与轮 TTFT 的机会约束 + 服务能力 + 显存可行性；
- 求解：小空间枚举 + 约束检验（毫秒级），保留 OR-Tools MILP 接口；重配周期分钟级或漂移触发；
- 与既有工作区分：区别于基底 MCKP 查表（新增驻留维度与机会约束），区别于引擎内 TTL 启发式（与流处理参数联合、由预测分布驱动）。

**研究点 3：会话感知调度与 KV 驻留门控（执行层）**
- 机制：① 会话亲和路由（一致性哈希，与 keyBy 分区对齐，扩缩容最小迁移）；② 驻留门控（逐轮收益-成本在线核算：P(d≤τ)·(重算+排队节省) vs 显存时间机会成本）；③ 控制面（Flink Operator State 驻留表，随 checkpoint 容错）与数据面（vLLM 前缀缓存，易失）分离。

### 五、研究方法与技术路线

总体路线：理论建模与系统实现交替——"形式化 → 原型实现（InferTuner 管线改造）→ 受控实验（合成器旋钮）→ 真实负载验证（trace 改编）→ 消融与退化分析"。

关键技术手段：① 在线学习/序贯估计（分桶分位数 + EWMA + conformal 校准）；② 数学规划（机会约束混合整数规划，小空间枚举求解）；③ 流处理系统工程（Flink keyBy/Operator State/checkpoint、一致性哈希路由、异步算子回调）；④ 数据驱动 workload 构造（公开 agent trace 改编 + 规则式会话合成器）。

实验平台：InferTuner；硬件 A6000-40G×4 单机与 H20-141G 集群（2–4 GPU）；主模型 Qwen3-4B-Instruct，泛化验证 Falcon3-7B 与可选 SGLang 后端。

评估指标：会话 JCT（均值/P95）、跨轮 TTFT（均值/P95）、SLO 达成率、吞吐与 GPU 时数、KV 复用率、驻留命中/误驻留率、预测覆盖率与校准收敛时间、控制器决策时延。

## 3.2 技术方案设计书（全文）

> 已确认决策：推理后端 vLLM 为主、SGLang 泛化验证；Workload 公开 agent trace 改编 + 规则式会话合成器双轨；点 2 锁定 P2-a（MILP）；JITServe 无需避让；实验机无管理员权限（本选题不涉锁频）。

### 1. 设计目标与总体思路

**1.1 要解决的系统问题**：多轮负载下，一个"请求"是会话中的一轮。相邻轮共享大量前缀（94.2% 可复用）；轮间隔由工具调用决定、高度可变（中位 5.2s、P99 81.4s）；会话 KV 是跨轮有价值的持久状态。现有 serving 在引擎内部处理，但会话状态本质是流处理 keyed state，本设计把它提升到 Flink 层，形成"预测 → 规划 → 执行"闭环。

**1.2 与 InferTuner 基底的映射关系**：

| 基底组件 | 原语义（单轮） | 新语义（多轮） |
|---|---|---|
| NJULocalRequestSource | 读 prompt/workload 按速率发射 | 读会话 trace，按会话-轮次结构发射（携带 sessionId、turnIdx、工具间隔标签） |
| InferenceStateFetcherProcessor | keyBy(userId)，Operator State 存 KV 缓存条目 | keyBy(sessionId)，Operator State 存会话档案（轮历史摘要、驻留表项、TTL 到期时间） |
| InferenceRequestBatcherProcessor | 攒批到 batchsize | 保留；新增会话混合约束（批内会话数上限） |
| NJULocalInferenceAsyncProcessor | 异步调 TCP 推理服务 | 异步调 vLLM×p 实例；新增会话亲和路由 + 驻留门控回调 |
| NJULocalCacheTestSink | 聚合时延/SLO/GPU 指标 | 新增会话级指标：会话 JCT、跨轮 TTFT、KV 复用率、驻留收益/成本核算 |
| 双阈值触发器/MCKP DP | 周期或阈值触发 (p,b) 重配 | 决策变量扩展为 (p,b,τ,M_kv)，由 P2-a MILP 求解 |

**1.3 关键工程取舍（诚实边界）**：① 不改 vLLM 内核（Flink 层控制"哪些会话前缀保持热"，通过亲和路由 + 驻留门控 + 准入控制实现，与 Continuum 是不同层级、可组合）；② TTL 收益核算在 Flink 层完成（不需读 vLLM 内部状态，接口黑盒）；③ 会话合成器先行（若 trace 改编受阻，合成器可独立支撑全部实验）。

### 2. 概念模型与形式化

**2.1 会话与轮次**：会话 s = ⟨r₁,…,r_T⟩，第 i 轮 r_i 携带 ctx_i（上下文 = 共享前缀 + 本轮新增 delta_i）、o_i（输出 token 数）、d_i（轮间隔）、m_i（KV 显存占用）。

**2.2 驻留决策的收益-成本模型（点 2/点 3 共用核心量化）**：轮 r_i 完成且检测到工具调用时，决策是否驻留、驻留时长 τ_i：
- 期望收益 `B_i = P(d_i ≤ τ_i) · [ C_prefill(ctx_i) + C_queue ]`；
- 期望成本 `K_i = m_i · τ_i · ρ(t)`，其中 ρ(t) 为显存时间机会成本率（低负载时 ρ→0，高负载时上升——给出负载自适应的激进/保守切换）；
- 门控规则 `B_i > K_i` 且热集预算允许 → 驻留，τ_i 取使 B−K 最大的值。
- E3 是逐轮在线微决策，P2-a 在秒~分钟尺度决定其参数，两个尺度职责分离。

**2.3 点 2 优化问题（P2-a MILP）**：
- 决策变量：p ∈ {1,…,4}、b ∈ {1,…,8}、M_kv ∈ [0, M_gpu]、q ∈ {0.5,…,0.95}（TTL 分位参数）；
- 目标：min 成本 = w₁·p + w₂·能耗代理（学硕阶段 w₂ 可为 0）；
- 约束：① SLO 机会约束 P(JCT≤SLO)≥1−ε₁、P(TTFT≤SLO)≥1−ε₂；② 容量约束 λ·(W_q+W_s) ≤ p·μ；③ 显存约束；④ 整数约束；
- 求解：决策空间小（p≤4、b≤8、q≤9 档），枚举 + 约束检验毫秒级出解；保留 OR-Tools MILP 接口。

### 3. 点 1：P1-c 会话行为预测器

**3.1 预测目标（均输出分布而非点值）**：轮间隔 d_i（用途：E3 门控 P(d≤τ)、P2 的 τ 分位）、剩余轮数 T_rem（容量规划）、上下文增长 g_i（显存压力预估）。

**3.2 特征**（全部可从 StateFetcher 会话档案在线获得）：会话内历史（已进行轮数、历史 d/|ctx|/o 序列）、工具类型分布、会话来源标签、系统状态（队列深度、热集占用率）。

**3.3 模型（基础版 → 进阶版）**：
- 基础版（必做，W3–W4）：分桶直方图 + 分位数估计。按（工具类型 × 轮次区间）分桶，桶内 EWMA 更新经验分布（存 P10/25/50/75/90 分位）。零训练成本、天然在线。
- 进阶版（选做，W5–W6）：分位数回归森林（QRF，对齐 Tempo）。
- 在线校准（必做）：在线 conformal 校准，保证经验覆盖率 ≈ 名义覆盖率。

**3.4 训练/初始化数据**：离线初始化用改编 agent trace（70% 初始化分桶、30% 验证）；在线更新用运行期观测回流（EWMA + conformal）。

**3.5 评估指标**：各分位覆盖率误差（目标 ≤5%）、NLL；下游效用（预测驱动门控 vs oracle 门控 JCT 差距 ≤10%）；漂移场景覆盖率恢复时间。

### 4. 点 2：P2-a 联合配置优化（实现要点）

1. 重配周期默认 60s 或漂移检测触发；2. 输入为点 1 的分布 + 当前 λ + profile 表（复用基底 GBDT/MLP 预测查表）+ M_gpu；3. 枚举 (p,b,q)×M_kv 档位 → 核算期望 JCT/TTFT/成本 → 取最小成本可行解；4. 输出 (p*,b*,q*,M_kv*) 下发（p 经 Flink rescale、b 改 Batcher、q/M_kv 改 E3 门控，热更新无需重启）；5. 枚举空间 ≈2300 候选，毫秒级，论文报告决策时延。

### 5. 点 3：E3 会话感知调度与驻留门控

**5.1 三个机制**：
- 机制 1 会话亲和路由：sessionId 一致性哈希到 vLLM 实例，p 变化时最小迁移；与 Flink keyBy 对齐。
- 机制 2 驻留门控（TTL admission gate）：推理完成回调解析到工具调用时，按收益-成本决策，通过则写入驻留表（sessionId → {m_i, τ_i, 到期时间戳, 累计收益核算}）；淘汰按到期/预算压力（B−K 最低者）/会话结束。
- 机制 3 会话级调度排序（增强项）：同会话连续轮优先、长会话不饿死，借鉴 Continuum 的 program-level FCFS。

**5.2 与 Flink 容错语义的关系**：驻留表存 Operator State（复用 ListState + checkpoint）→ 故障恢复后决策状态不丢；KV 本体在 vLLM 侧属易失加速结构，故障后首轮重 prefill 重建——表述为"控制面状态（Flink，持久）与数据面缓存（引擎，易失）分离"的设计原则。

**5.3 反馈回路**：Sink 聚合每轮观测 → 回流点 1 更新分布与 conformal 校准 → 点 2 下周期重估约束参数。闭环自证指标：门控决策的 B−K 核算误差应收敛。

### 6. Workload 构造方案（双轨）

**6.1 轨 A：公开 agent trace 改编**：vLLM 开源 Codex/SWE-bench Pro trace（610 条，含每轮 token 数、轮间隔）、BFCL（函数调用型多轮）、SWE-bench（任务结构）。统一会话格式（JSONL，每行一轮）：`{"session_id","turn","ctx_tokens","delta_tokens","max_output","tool","arrive_after_prev_sec","task_type"}`。

**6.2 轨 B：规则式会话合成器（三旋钮）**：旋钮 1 会话长度 T（中位 10/33 两档）、旋钮 2 轮间隔 d（对数正态，中位 5s/30s/长尾档）、旋钮 3 上下文增长 g（对齐 trace 的 ~2242 token/轮）。价值：受控变量实验（单扫一个旋钮，验证各机制敏感性）。

**6.3 与基底 HDFS 工作流衔接**：会话 JSONL 上传 HDFS；Source 按 arrive_after_prev_sec 定时发射；marker 文件完成语义保持不变。

## 4.3 新增六点详卡（RP13–RP18）

### RP13｜输出长度不确定性下的鲁棒 KV 显存预算

- **研究问题**：KV cache 显存按"预测输出长度"预留，但长度预测有误差——预测偏低导致显存溢出/抢占，偏高导致显存浪费。如何在长度不确定下做鲁棒显存预算？
- **启发来源**：Robust KV Cache Management under Output Token Length Uncertainty（arXiv 2607.16892）；Tempo（QRF 区间）；JITServe（运行时精化）。三者空白：都未把显存预算与流处理层的并发控制/批次调度联合。
- **方法**：① 区间预测表达长度不确定性；② 显存预算 = 机会约束（P(溢出)≤ε）下的可容许并发；③ 运行时随生成长度收紧区间、动态修正预算。
- **实验**：不同长度分布/预测误差注入；baseline = 固定预算/点估计预算/oracle；指标 = 溢出率、显存利用率、吞吐、SLO。
- **六维**：价值★★★★ 难度★★ 工作量★★ 实验★★★★ 实现★★ 资源★★。**关联**：可直接成为选题三点 2 的不确定性建模子模块。

### RP14｜意图感知的跨轮 KV 剪枝与驻留

- **研究问题**：多轮会话里，不是所有历史 token 对后续轮都有用，能否按跨轮意图选择性剪枝 KV，而非"全留或全丢"？
- **启发来源**：IntentKV（arXiv 2606.09916，cross-turn intent-aware KV pruning）；Leyline（arXiv 2606.01065，KV cache directives）；Irminsul（arXiv 2605.05696，position-independent caching）。三者空白：都需引擎侧支持，未从流处理"会话状态语义"切入。
- **方法**：① 用轻量信号（轮角色、工具调用类型、意图分类）标记"关键轮"；② 非关键轮 KV 压缩/剪枝/换出；③ 驻留决策 = 意图重要性 × 复用概率 × 成本。
- **六维**：价值★★★★ 难度★★☆ 工作量★★☆ 实验★★★★ 实现★★☆ 资源★★。**关联**：选题三点 3 的首选深化项。

### RP15｜在线学习的推理路由

- **研究问题**：多模型路由依赖离线难度预测器，但负载/模型性能随时间漂移——能否在线学习路由策略、无需监督标签？
- **启发来源**：Lodestar（arXiv 2606.00946，online-learning router）；RouteBalance（arXiv 2606.17949，警示"预测器只是校准器"）；Online LP for Multi-Objective Routing（arXiv 2607.03948）。
- **方法**：① 在线 bandit/EXP3 或在线 LP 选路由；② 反馈信号用可观测的（时延/负载/质量代理）；③ 与负载均衡状态联动。
- **六维**：价值★★★☆ 难度★★☆ 工作量★★ 实验★★★ 实现★★ 资源★★★。**关联**：独立（选题六升级版）。

### RP16｜token 漂移下的自适应 QoS 调度

- **研究问题**：请求到达时的长度/时延估计会随生成过程漂移，调度决策只在到达时做一次会失配。如何生成中持续修正调度？
- **启发来源**：DriftSched（arXiv 2606.02982）；JITServe（NSDI'26）；Cascade（arXiv 2608.06557）。空白：都面向引擎内，未覆盖流处理层攒批+排队+背压。
- **方法**：① 每生成若干 token 更新剩余长度/时延估计；② 调度优先级/批组成随新估计重排；③ 漂移幅度大时触发重新准入/降级。
- **六维**：价值★★★☆ 难度★★ 工作量★★ 实验★★★★ 实现★★ 资源★★。**关联**：选题三点 3 的调度增强，可与 RP13 合并成"不确定性驱动的会话调度"子线。

### RP17｜跨硬件/跨模型的成本模型迁移

- **研究问题**：换模型/换 GPU 时预测模型要重训——能否少样本迁移，只重学轻量"环境标定层"？
- **启发来源**：WattGPU（arXiv 2607.02391，预测未见 GPU/LLM 的功耗时延）；SLIM（arXiv 2607.29575，轻量饱和感知建模）；ZeroTune（ICDE'24，零样本成本模型）。
- **方法**：① 共享"算子结构特征"层 + 环境相关"标定层"（少样本重学）；② 迁移后作仿真器预筛配置空间；③ MAPE 超阈触发保真升级。
- **六维**：价值★★★☆ 难度★★☆ 工作量★★ 实验★★★★ 实现★★ 资源★★。**关联**：独立（选题五深化）。

### RP18｜多轮会话的异构 KV 共享与预推演

- **研究问题**：多轮会话里，不同会话/轮 KV 可部分共享，且下一轮输入可在当前轮生成时预推演——如何把异构共享与预解码结合降低跨轮 TTFT？
- **启发来源**：SwiftCache（arXiv 2606.16135，异构 KV 共享）；SparseX（arXiv 2606.01751，段级 KV 共享）；Speculative Pre-Positioning（arXiv 2606.29565，会话预解码到下一决策点）。
- **方法**：① 会话 KV 用共享树结构存储（前缀共享 + 分支）；② 空闲 GPU 时间预解码高概率下一轮；③ 命中则免 prefill。
- **六维**：价值★★★★ 难度★★★ 工作量★★★ 实验★★★ 实现★★★ 资源★★。**关联**：选题三点 3 的进阶项（建议作为"深度旋钮"）。

## 4.4 原十二点详卡（RP1–RP12）

### A 组：SLO 保障与调度

**RP1｜异构 SLO 的 credit-based 批调度与准入控制**：生产请求 SLO 天然异构（TTFT/TPOT 松紧不同），Flink Batcher 目前一视同仁。启发：SCORPIO（credit-based batching + VBS 准入 + least-deadline-first）。方法：① 每请求按 SLO 紧迫度积累 credit，满才入批；② Batcher 改为 credit-aware 攒批；③ 准入控制做虚拟批大小估算。实验：不同 SLO 混合比例扫变，baseline = FCFS/least-deadline-first/SCORPIO 复现。六维：价值★★★☆ 难度★★ 实验★★★★。

**RP2｜预测驱动的 SJF/优先级准入排序**：长请求阻塞短请求，用极轻量长度预测做排序。启发：Clairvoyant（19 词法特征 XGBoost 0.029ms/请求，短请求 P50 降 70–76%）、PARS、ELIS。方法：token 数预测器输出长度分档 → Batcher 前加排序缓冲 → 与批组成协同。六维：价值★★★ 难度★ 实验★★★★。

**RP3｜过载时的预测性请求拒绝**：负载饱和时主动拒绝"TTFT 预测已不可能满足 SLO"的请求，保护可达成请求。启发：SCORPIO TTFT Guard、Concur。方法：TTFT 上界预测 → 超阈且队列压力大则快速失败 → 拒绝策略（严格/概率/带重试）。六维：价值★★★ 难度★ 实验★★★★。

### B 组：缓存与状态

**RP4｜队列感知的缓存准入与淘汰**：缓存该不该驻留，不只看历史频率，还看"队列里接下来有没有请求会用它"。启发：PEEK（pending queue radix tree + 最长前缀匹配，命中 3.0×）、CacheWise。方法：① Batcher/StateFetcher 间维护 pending 队列 key 分布统计；② 缓存决策综合"历史频率 + 队列近期需求"打分。六维：价值★★★★ 难度★★ 实验★★★★。

**RP5｜语义缓存的流式阈值在线学习**：语义缓存相似度阈值是"命中率 vs 错误率"旋钮，静态阈值要么命中低要么错误高，在流式 pre-processing 层在线学习每个缓存项的阈值。启发：vCache（逐项在线阈值，命中 12.5×）。方法：embedding 相似检索 + 每缓存项在线阈值估计 + 与 SLO 联动。六维：价值★★★ 难度★★ 实验★★★。

**RP6｜存算分离下的会话状态管理**：Flink 2.0 存算分离把状态访问变跨网络，对推理会话这种高频访问、强局部性的状态是好是坏？如何设计分层放置？启发：Flink 2.0 Disaggregated State（VLDB'25）、Strata/Contextra。方法：分析会话 KV 访问模式 → 本地缓存 + 远程主存分层放置 → 评估 checkpoint/恢复/重配置对推理 SLO 的影响。六维：价值★★★★ 难度★★★ 实验★★★。

### C 组：资源配置

**RP7｜垂直+水平混合弹性伸缩**：应对负载波动有两条路——水平伸缩（改并行度，需重配置有中断）与垂直伸缩（改 batch/缓存容量，零断流），何时用哪条、如何混合？启发：Oceanus（SIGMOD'25，零断流垂直伸缩）、Justin。方法：快速路径垂直旋钮零断流响应，慢速路径水平重配置，两路径协调。六维：价值★★★☆ 难度★★ 实验★★★★。

**RP8｜多模型路由×负载均衡融合**：路由选模型与负载均衡耦合，贪心路由导致热点过载。启发：RouteBalance、HELIOS、SPECTRE。方法：时延预测估计各模型/实例时延 → 路由决策 = 质量-时延-负载三目标打分。六维：价值★★★★ 难度★★★ 实验★★★（serving 圈拥挤，建议作扩展）。

### D 组：推理计算优化

**RP9｜负载感知的自适应推测解码**：推测解码低负载省时延、高负载拖累吞吐，按负载动态开关 + 选推测长度。启发：Nightjar（MAB 选推测长度 + 关闭时 offload draft 释放显存）、Not-a-Bandit、MemSpec。方法：负载观测作为 MAB 上下文 → 决策开关 + 推测长度 k → 关闭时 offload draft。六维：价值★★★★ 难度★★☆ 实验★★★★。

**RP10｜负载感知的生成预算控制**：输出越长质量越高但时延越长，高峰时动态压缩输出长度/推理预算保 SLO。启发：TimeBill、HELIOS、Slim-SC。方法：max_tokens/生成预算作为负载函数 → 与 SLO 联动 → 质量影响量化。六维：价值★★★☆ 难度★★ 实验★★★。

### E 组：系统鲁棒性

**RP11｜重配置时机的门控优化**：调优器算出更优配置后，重配置本身有开销，何时值得切换、如何避免震荡？启发：StreamShield（防抖/回滚）、MC-SF（竞争比框架）、基底双阈值触发器 + reconfig 开销数据。方法：实测开销函数 → 在线门控（滞后双阈值 + 预测分布感知）→ 可选竞争比分析。六维：价值★★★ 难度★★ 实验★★★★。

**RP12｜容错开销与推理 SLO 协同**：checkpoint 会暂停/干扰推理算子，如何设置间隔/策略在容错与推理 SLO 间权衡？启发：Flink 2.0（ForSt 秒级 checkpoint）、StreamShield（region checkpointing）。方法：测 checkpoint 间隔/策略对推理影响 → checkpoint 间隔纳入择优 → 与推理算子内部状态协同。六维：价值★★★ 难度★★ 实验★★★★。

# 第六部分 · 三点组合方案

> 来源：`三点组合方案.md`。从 18 个研究点中组合出"三点成一章、三章成一篇"的最佳论文结构，回答"为什么这样组合 + 故事能否讲通"。

## 6.1 组合总逻辑

18 个研究点都服务于同一个母题：**动态负载下的流式 LLM 推理服务，如何以更少的 GPU/计算/显存稳定满足端到端 SLO？** 三个研究点为这个母题提供三条衔接的证据链，最成熟的三层结构是：

```
感知（Predict）→ 决策（Plan/Decide）→ 执行（Schedule/Act）→ 反馈回感知
   点 1              点 2                点 3
  [学习问题]        [优化问题]           [控制/调度问题]
```

这个结构的优势：① 三点问题类型不同（学习/优化/控制），天然不重叠；② 数据流单向衔接、末尾回注开头，天然成闭环；③ 消融实验天然成立。组合的关键不是挑三个"都好"的点，而是给三层各挑一个"最贴母题、彼此咬合"的点。

## 6.2 方案一（主推）：会话状态感知的流式推理服务

**一句话故事**：*推理负载从"独立单轮"变成"多轮会话"后，KV cache 从一次性计算的副产品，变成跨轮持久的有价值状态——Flink 的有状态流处理语义与之天然同构，本课题在流处理层对会话状态做"预测 → 规划 → 调度"的闭环管理。*

| 层 | 研究点 | 融合了哪些 RP | 核心方法 |
|---|---|---|---|
| 点1 感知 | 多轮会话行为的在线分布预测 | RP13 + 原选题三点1 | 分桶分位数 + QRF + 在线 conformal 校准 + 漂移检测 |
| 点2 决策 | 鲁棒的驻留-流处理参数联合优化 | RP13 + RP10 + RP7 | 机会约束 MILP：变量 (p, b, TTL, 驻留预算, max_tokens) |
| 点3 执行 | 会话感知调度与 KV 驻留控制 | RP14 + RP4 + RP16 + RP18 | 会话亲和路由 + 意图感知剪枝 + 队列感知驻留门控 + 控制面/数据面分离 |

**为什么这样组合**：① 母题最锐利（负载结构真实变化，有数据支撑）；② 三点咬合最紧（每层精确消费上层产出）；③ 血缘最近（StateFetcher 就是现成的会话状态算子）；④ 差异化最清晰（对手都在引擎内，本课题在流处理层）。

**故事能否讲通**：能，且是三个方案里最完整的——动机链（负载变了→单轮优化失效→需会话感知→流处理层最合适）、闭环链（分布→机会约束→配置→运行→观测回注）、消融链（去预测/去规划/去调度三组消融）全部成立。

## 6.3 方案二：异构 SLO 保障的流式推理服务

**一句话故事**：*生产请求的 SLO 天然异构，现有系统"一视同仁"导致大量违约；把 SLO 异构性当作资源，做"区间预测 → 差异化配置 → 差异化调度"的保障闭环。*

| 层 | 研究点 | 融合了哪些 RP | 核心方法 |
|---|---|---|---|
| 点1 感知 | 推理时延/长度的区间预测与在线精化 | RP2/RP16 的预测底座（Tempo QRF + JITServe） | QRF 区间 + 随生成进度收紧 + 在线校准 |
| 点2 决策 | 异构 SLO 的联合配置优化 | RP1 + RP3 + RP13 | 机会约束 MILP：决策变量含各 SLO 类的 credit/准入阈值 |
| 点3 执行 | SLO 感知的差异化调度 | RP1 + RP2 + RP3 + RP16 | credit 攒批 + 最小剩余时间优先 + 预测性拒绝 |

**特点**：动机普适（不依赖会话结构）、三点高度内聚（都围绕异构 SLO）、实验最简单（单模型即可）。**主要风险**：SCORPIO 已在引擎内做过，差异化必须落在"流处理层攒批 + 跨算子排队 + 背压"语境，新颖度略弱于方案一。

## 6.4 方案三：多维资源高效的流式推理服务

**一句话故事**：*GPU 成本是多维的（卡数、显存、计算量、切换开销、能耗），把"省卡"扩展为"多维资源效率"，做"成本模型迁移 → 多维联合优化 → 自适应执行"闭环，正面回应 profiling 成本质疑。*

| 层 | 研究点 | 融合了哪些 RP | 核心方法 |
|---|---|---|---|
| 点1 感知 | 跨硬件/跨模型的成本模型迁移 | RP17（WattGPU/SLIM）+ 时延预测 | 分层模型 + 少样本迁移 |
| 点2 决策 | 多维联合优化 | RP7 + RP10 + RP13 | 混合保真搜索 + MILP |
| 点3 执行 | 自适应执行 | RP9 + RP11 | 负载感知推测开关 + 带切换成本的在线门控 |

**特点**：直接回应 HPDC 审稿意见、省资源维度最全。**弱点**：点3 的 RP9（推测解码）与 RP11（门控）相对独立，章节内部需"自适应执行"伞概念粘合，凝聚力稍弱。

## 6.5 三方案对比与推荐

| 维度 | 方案一：会话感知 | 方案二：异构 SLO | 方案三：多维资源 |
|---|---|---|---|
| 母题锐利度 | ★★★★★ | ★★★★ | ★★★☆ |
| 三点咬合度 | ★★★★★ | ★★★★★ | ★★★☆ |
| 与基底血缘 | ★★★★★ | ★★★★ | ★★★★ |
| 新颖度（2026） | ★★★★★ | ★★★☆ | ★★★☆ |
| 实验难度 | 中高 | 低 | 中 |
| 撞车风险 | 中 | 中高 | 低 |
| 4 个月完成把握 | 中高 | 高 | 高 |
| **推荐** | **★★★★★ 主推** | ★★★★ 退路 | ★★★☆ 备选 |

**推荐结论**：主推方案一（继承选题三，无沉没成本，母题最锐利、三点咬合最紧、血缘最近）；方案二作为实验受阻时的最省力退路；方案三仅在导师偏好系统调优传统叙事时选。

## 6.6 故事完整性五条自检清单

1. **单一母题**：三点是否都回答同一个大问题？
2. **问题类型互异**：点1 学习 / 点2 优化 / 点3 控制，产出物分别是预测值 → 配置 → 动作。
3. **数据流单向闭环**：点1→点2→点3→回注点1，每层输出恰是下一层输入。
4. **时间尺度分层**：毫秒级预测 / 秒级求解 / 分钟级动作。
5. **消融可证**：去掉任一点端到端指标下降，且闭环收益 > 各点单独收益之和。

三个方案都通过这五条，区别只在母题锐利度和落地风险。

# 第七部分 · 语义库故事线（最新方向）

> 来源：`语义库故事线.md`。在保留 Flink 流式推理主框架不变的前提下，把"语义库/知识库"作为可控的状态化资源融入管线。关键概念锚点：Memory Tax（记忆税，来自 Memanto arXiv 2604.22085）。

## 7.1 概念厘清：三层记忆

推理系统里与"语义库/知识库"相关的机制，按复用粒度分三层：

| 层 | 名称 | 复用对象 | 作用 | 典型工作 |
|---|---|---|---|---|
| 输入侧 | 知识库（RAG） | 外部知识文档 | 检索知识作为上下文（提质量，不省计算） | RAG、VECTOR_SEARCH |
| 输出侧 | 语义缓存 | 历史响应 | 语义相似请求复用整个响应（省整次推理） | vCache、GPTCache |
| 计算侧 | KV cache | 前缀中间状态 | 复用 attention 前缀计算（省 prefill） | vLLM、RadixAttention |

统一概念：**语义记忆（Semantic Memory）** = 系统对"过往请求、响应、知识"的语义化、可检索的记忆。它同时支撑"复用响应"（省计算）和"检索知识"（提质量），是会持续演化、需要精心管理、本身有成本的资产。

## 7.2 故事引擎：Memory Tax

- **第一层张力（成本）**：Memanto 提出 Memory Tax——语义记忆的摄取（实体提取、建索引、写库）和检索（embedding、相似度、top-k）都要消耗算力和时间。
- **第二层张力（流式放大）**：现有语义记忆工作（Memanto/Synapse/GAM/HeLa-Mem）都在离线 agent 场景做记忆架构优化；而 Flink 管线里请求是持续流，记忆必须实时增量维护，检索延迟直接进入端到端 SLO。Memory Tax 在流式、SLO 约束下被放大成动态优化问题。
- **第三层张力（资源耦合）**：语义记忆命中越多 → 推理越少 → GPU 越省；但记忆占内存、检索占 CPU/延迟。出现全新耦合：**语义库容量/阈值 ↔ 推理资源(p,b) ↔ 端到端 SLO**，这是"流处理调优"和"agent 记忆架构"两个阵营的空白交汇处。

## 7.3 三点故事线

**母题**：动态负载下的流式 LLM 推理服务，需要语义记忆来复用推理成果、沉淀知识；但记忆要交税。本课题在 Flink 层对语义记忆做"感知 → 决策 → 执行"闭环，以最小记忆成本换最大推理节省。

| 层 | 研究点 | 核心问题 | 融入研究点 | 核心方法 |
|---|---|---|---|---|
| 点1 感知 | 语义复用价值与记忆税的在线建模 | 请求值不值得复用、可不可靠、能省多少？ | RP5 + 基底时延预测 | BGE-m3 + 在线校准/bandit 估计复用价值 + 检索延迟分布 |
| 点2 决策 | SLO 感知的语义记忆配置优化 | 语义库多大、阈值多严、什么该记？ | RP13 + 基底 MCKP | 机会约束 MILP：变量 (S_sem, τ, 摄取策略, p, b) |
| 点3 执行 | 流式语义记忆的在线维护与调度 | 记忆如何增删改、命中如何短路推理？ | RP4 + RP14 | 增量摄取 + 语义淘汰 + 快路径短路 + 三级复用协同 |

**闭环链**：点1 输出「复用价值 + 误匹配风险 + 检索延迟分布」→ 点2 的机会约束参数 → 点2 输出 (S_sem, τ, 摄取策略, p, b) → 点3 运行 → 观测（命中率/误匹配/时延）→ 回注点1 在线校准。

## 7.4 如何融入 Flink 主框架（管线不动，只升级一个算子）

```
Source → StateFetcher → Batcher → Inferencer → Sink
            ↑ 升级为「语义记忆算子」（embedding 索引 + 语义检索）
            ↑ 语义命中 → 短路 Batcher+Inferencer（省 GPU）
```

| 组件 | 现有 | 融入语义记忆后 |
|---|---|---|
| StateFetcher | 精确 key 匹配的状态缓存 | 升级为语义记忆算子：embedding 索引 + 语义相似检索，命中直接产出响应 |
| 快路径 | 无 | 语义命中 → 直接短路推理，未命中才走完整推理 |
| 记忆存储 | Operator State（KVCacheEntry） | Operator State 存记忆条目（随 checkpoint 容错）+ 轻量向量索引 |
| Batcher/Inferencer | 不变 | 不变（只接收未命中请求） |
| 预测/择优 | token 预测 + MCKP | 点1 在 StateFetcher 内做复用价值预测；点2 复用 MCKP 加语义记忆维度 |
| Sink | 指标汇总 | 增加命中率/误匹配/记忆税指标 |

**为什么这样融入最自然**：① 管线零改动，只把 StateFetcher 从"精确缓存"变"语义记忆"；② 复用 BGE-m3、FREQUENCY 统计、MCKP、Operator State；③ 记忆税在 Flink 算子里可测可控。

## 7.5 严谨性论证 / 与选题三关系 / 风险差异化

**严谨性论证**：① 有概念锚点（Memory Tax / vCache 阈值学习）；② 有明确空白（Memanto/Synapse/GAM/HeLa-Mem 都在 agent 应用层，vCache 在单机静态，无人在流处理层把语义记忆当可控算子）；③ 有基底血缘（StateFetcher + BGE-m3 + MCKP 现成）；④ 有闭环逻辑。

**与选题三关系：升级而非替代**——语义记忆 = 会话状态管理的语义化、通用化、跨会话化。选题三做"会话 KV 状态"（精确前缀/会话级），语义记忆做"跨会话、跨用户的语义级复用"（"帮我退票"和"我要取消订单"语义相同、措辞不同，KV cache 复用了，语义记忆能复用）。建议把选题三的"会话状态"收为语义记忆的一个子场景。

**风险与差异化**：agentic memory（Memanto/Synapse/GAM/HeLa-Mem）和 semantic cache（vCache）都很热，差异化 = "流处理层 + 动态负载 + 与推理资源/SLO 联合优化 + 记忆税显式建模"。实验不需多模型，单模型 + embedding 索引即可，权衡曲线用不同阈值/容量/负载档位扫出。

# 第八部分 · vCache 深度调研（语义缓存方向支撑）

> 来源：`vCache调研报告.md`。调研对象 vCache（ICLR 2026，arXiv v5）。通读 28 页全文 + 第三方解读交叉核对。对应 RP5（语义缓存阈值在线学习）、语义库故事线的"输出侧语义缓存"。

## 8.0 一句话结论（TL;DR）

vCache 是**第一个带"用户可定义错误率保证"的语义缓存**。它放弃全局静态相似度阈值，为向量库里**每一个缓存条目在线学习一个专属阈值**，并把"命中/重算"改成**带正确性约束的随机化探索-利用策略**：用户设定最大错误率 δ，系统在保证正确率 ≥ 1−δ 的前提下最大化命中率。核心贡献是把"语义缓存不可信"这个生产部署痛点，用一套零预训练、与嵌入模型无关、可在线适应的概率框架解决。

对我们的价值：它是 RP5 的直接对标，留下四个明确空白——**容量与淘汰、流处理状态语义、动态负载漂移、与 SLO/推理资源的联合优化**——恰好是选题三可切入的差异化位置。

## 8.1 论文基本信息

| 项 | 内容 |
|---|---|
| 标题 | vCache: Verified Semantic Prompt Caching |
| 作者 | Luis Gaspar Schroeder 等（UC Berkeley 为主，另有 Stanford、TU Munich） |
| 会议 | ICLR 2026（Accepted，Poster） |
| arXiv | 2502.03771（v1 2025-02-06，v5 2026-02-21） |
| 代码/基准 | github.com/vcache-project/vCache；huggingface.co/vCache（4 个语义缓存 benchmark） |

## 8.2 背景与动机

语义缓存：把每个请求 x 嵌入成向量 E(x)，找语义最近邻 nn(x)，若相似度 s(x) = sim(E(x), E(nn(x))) ≥ 阈值 t 则命中返回缓存响应，否则调 LLM 并入库。论文引用 GPTCache 数据：延迟最高可降 100×。

工业主流（GPTCache、AWS、Azure API Management、LiteLLM、waLLMartCache、SCALM）都用**全局静态阈值 t**（典型 0.8）。三个缺陷：① 无形式化正确性保证（返回错答案风险无法量化）；② 实际错误率不可控（正确/错误命中的相似度分布高度重叠）；③ 命中率次优（不同缓存条目的"安全阈值"差异巨大）。

既有两条改进路线（嵌入微调、EVM 阈值优化）都没解决"保证"问题。vCache 的定位：**在线、逐条目学阈值，同时给出 δ 错误率保证**。

## 8.3 问题形式化

- **缓存数据模型**：每个入库 prompt 存三元组 (E(x), r(x), O(x))，其中 O(x) 是"把 x 当最近邻的后续请求的（相似度, 正确性）对"集合——让每个缓存条目积累自己的局部经验，而非全局共用一个阈值。
- **错误率保证**：Definition 4.1，`Pr(vCache(x) == r(x)) ≥ 1−δ`（边际概率保证）。
- **探索概率下界 τ**：把"系统正确"拆成"探索（调 LLM 必正确）+ 命中且命中正确"两个互斥事件，反解出 `Pr(explore|x,D) ≥ τ = ((1−δ) − Pr(c=1)) / (1 − Pr(c=1))`。直觉：缓存越可能答对，允许探索越少、命中率越高。

## 8.4 方法详解

1. **sigmoid 建模**：`Pr(c=1|x,D) = L(s,t,γ) = 1/(1+e^(−γ(s−t)))`，t 为该条目专属阈值、γ 为陡峭度，用该条目观测 O(x) 做二元交叉熵 MLE 在线拟合，零预训练零标注。
2. **悲观置信带**：取 (1−ε) 置信带上的悲观值 t′(ε)、γ′(ε)，把样本不确定性折算成探索次数。附录两个引理：Lemma C.1（正确概率下界 α 给出探索概率上界）、Lemma C.2（参数置信区域 → 正确概率打折）。诚实实现细节：实验只对 t 做置信区间修正，γ 用点估计。
3. **随机化决策**：不是"相似度够高就命中"，而是"以 1−τ̂ 的概率命中"。冷启动自然保守（新条目 τ̂→1 几乎全探索），观测累积后命中率爬升。每次 explore 免费获得 (s,c) 标签回写。
4. **理论保证**（Theorem 4.1）：在 i.i.d. + sigmoid 族假设下，任意时刻、任意 prompt 的错误率 ≤ δ，非渐近。MLE 收敛速率 O(1/√n)。

## 8.5 实验评估

- 设置：嵌入模型 3 种（GteLargeENv1-5/E5-large-v2/OpenAI，验证"与嵌入模型无关"）；LLM Llama-3-8B-Instruct + GPT-4o-mini；向量库 HNSW + 余弦。
- 自建 benchmark（独立贡献之一）：SemCacheLMArena（60k）、SemCacheClassification（45k）、SemCacheSearchQueries（150k）、SemCacheCombo（27.5k，模拟"部分请求永无命中"）。
- 核心结果：① 保证始终兑现（所有 δ 档位实际错误率压在 δ 下，命中率随样本持续上涨；GPTCache 错误率随样本持续上升）；② Pareto 支配（LMArena 上最高 26× 更低错误率、12.5× 更高命中率）；③ 保守侧行为（δ<1.5% 时宁可多探索守正确性）；④ 免训练优势（无需训练即匹配/超过微调嵌入的 GPTCache）。
- 两处勘误：正文与图注 LLM 版本不一致（Llama-3-8B vs 3.1-8B）；§3 概述"总是入库"与 Algorithm 1"仅响应不同才入库"不一致（后者更合理）。

## 8.6 局限性与批评

**作者自述**：① 长响应等价性判断依赖 LLM-as-a-judge（只输出一个 token、可异步）；② i.i.d. + sigmoid 假设破坏时保证不成立。

**本调研补充的批评点（对差异化最有用）**：
1. **无容量与淘汰策略**（只回答"该不该命中"，不回答"库该多大、淘汰谁"）；
2. **标签获取存在探索偏置**（c(x) 只在 explore 时获得，观测集有偏，未做形式化处理）；
3. **"保证"依赖项多且部分靠近似**（置信带用均匀先验贝叶斯反转近似、γ 只用点估计）；
4. **单机、单轮、静态假设**（不涉及多轮会话、流处理状态、checkpoint 容错、背压攒批）；
5. **没有时延/SLO 约束**（只约束正确率，不约束检索延迟预算，探索概率与记忆税的关系未建模）；
6. **对负载漂移脆弱**（i.i.d. 假设在动态负载下失效，无漂移检测/重校准）。

2026 年同赛道工作的问题轴：vCache（准入）、Semantic Caching Offline→Online（淘汰/驻留，arXiv 2508.07675）、Continuous Semantic Caching（连续空间理论，arXiv 2604.20021）、Cortex（NSDI'26，系统架构）、Grounded Cache Routing（RAG 复用安全，arXiv 2605.27494）。结论：**准入、淘汰、连续空间、系统架构、复用安全五条线都在推进，但没有一条把语义缓存放进"流处理层 + 状态容错 + SLO 联合优化"的语境**。

## 8.8 对本课题的启发

**可直接借鉴的三个机制**：① 逐条目阈值 + 探索概率作为准入旋钮（BGE-m3 当 E(·)，per-entry 阈值和观测存 Operator State 随 checkpoint 容错）；② 悲观置信带与已有 conformal 校准同源（可写进现状综述作"不确定性感知准入"方法论血缘）；③ δ 作为"质量旋钮"进联合优化（δ 收紧⇒更多推理⇒质量优先，δ 放松⇒命中上升⇒省 GPU，把 δ 变成点 2 MILP 决策变量）。

**四个可进攻的空白**：① 无容量/淘汰 → 接入 submodular 淘汰 + FREQUENCY 频率统计 + PEEK 队列感知；② 无流处理状态语义 → 阈值学习状态如何 checkpoint/迁移；③ 无漂移处理 → 点 1 漂移检测 + conformal 重校准；④ 无 SLO/记忆税联合优化 → δ、S_sem、摄取策略与 (p,b) 一起进机会约束 MILP。

## 8.9 在 InferTuner 上复现与实验建议

最小复现清单（2–4 GPU，约 2–3 周）：① 数据优先用 SemCacheClassification（短响应、字符串匹配判等价，最省成本）；② 对照全局静态阈值 / vCache 式逐条目阈值 / 无缓存，扫描 δ∈{0.5%,1%,1.5%,2%,3%,5%}；③ 指标 = 命中率、错误率、P95 时延、GPU 时数、记忆税分布、checkpoint 恢复后阈值状态完整性；④ 增量实验 = 负载漂移下对比"vCache 原版 vs vCache+conformal 重校准"；⑤ 坑位提醒：随机化有方差需多次跑报 CI，观测集有偏需监控 t̂ 收敛轨迹。
