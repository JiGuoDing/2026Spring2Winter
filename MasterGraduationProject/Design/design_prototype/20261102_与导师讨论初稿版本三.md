## 0. 讨论目标与请导师确认事项

### 0.1 一句话方案

本课题拟研究：在动态多租户负载下，如何由 Flink 控制面统一管理会话语义、RAG 知识和历史回答三类派生状态，联合决定**保留什么、为语义复用配置多少缓存与算力，以及每个请求应先服务谁、采用何种复用动作、是否保持会话粘性**，从而在时延、质量和公平约束下降低推理资源成本。

题目中的“跨层”指语义状态层与推理服务层的协同，不含 GPU 显存中的 KV 张量。

暂定题目仍为：

> **面向异构 SLO 的流式 Agent 推理跨层状态管理与缓存感知调度研究**

原宽口径题目“基于流处理的 Agent 框架的高效资源管理与优化研究”可暂时保留为方向名称，待研究范围稳定后再决定是否改题。

### 0.2 三个研究点及其取舍

| 研究点 | 核心取舍 | 本版建议 |
| --- | --- | --- |
| 跨层状态价值与生命周期 | 状态压缩、刷新与驻留的未来收益，能否覆盖生成、验证、维护与质量风险成本 | 基础主线，先建立状态模型与净收益证据 |
| 缓存—算力联合配置 | 为语义缓存投入资源，与增加或调整推理算力之间如何选择 | 保留，以“缓存变化是否改变最优离散配置”为门槛 |
| 复用感知公平调度 | 保持会话粘性，与负载均衡、异构 SLO 和租户公平如何权衡 | 保留两级调度与本地/异地比较，先验证冲突能否复现 |

### 0.3 希望导师拍板的事项

| 决策事项 | 本版推荐 | 若不建议的降级方案 |
| --- | --- | --- |
| 三层研究结构 | 保留三层，不预设三章工作量相等，由预实验决定权重 | 收缩为“状态生命周期＋质量约束”，其余作支撑 |
| 研究点二范围 | 只做离散缓存预算与 `(p,b)` 联合选择，不做连续优化 | 改为固定、单侧与顺序调参的边界比较 |
| 研究点三范围 | 必做工作量公平、SLO 紧迫度与会话粘性的 local/recompute 路由 | 若冲突弱，仅保留调度作为执行模块 |
| 质量风险预算 | 基础版按层设定固定风险预算，并实测各层指标与最终质量 | 回答层退化为静态阈值或禁用近似复用 |
| KV 边界 | KV 由并行项目负责，本课题只消费“APC 在运行”，不建目录、不设预算、不评估准确性 | 若需可观测性，只增加一个只读亲和提示字段，不扩展为研究点 |
| 高风险增强 | 动态风险预算、delay-hit 感知组批等最多选一项，不进入 MVP | 全部删除，不影响主论文完整性 |

## 1. 从版本二到版本三：研究问题与范围

### 1.1 保留的问题内核

多轮 Agent 推理并非相互独立的请求序列。对话摘要、结构化事实、RAG 文档和历史回答都可能跨轮或跨会话复用：复用减少远端读取、上下文组装和整次推理，但引入状态存储、语义验证、刷新、迁移、恢复与路由开销。前缀 KV 同样减少 prefill，但其生成与驻留都在引擎内部，控制面既不可观测也不可控，故计入“环境能力”，不进入本课题的收益链与贡献。

版本三继续保留“保留什么 → 配置多少 → 如何调度”的顺序，但把三个模块闭合为一条反馈链：

```text
状态访问与复用观测
        │
        ▼
研究点一：估计可避免成本、管理税和质量风险
        │ 输出各层“预算—收益—风险”曲线
        ▼
研究点二：选择缓存预算、推理并行度和批次
        │ 输出配置、资源预算和过载信号
        ▼
研究点三：按租户 SLO、公平和会话粘性执行复用与路由
        │
        └────反馈命中、真实 GPU/辅助成本、时延、错误和服务份额────┘
```

三层不是三个孤立算法：缺少研究点一，规划器没有收益输入；缺少研究点二，调度器没有资源与质量边界；缺少研究点三，前两层无法验证真实尾时延与公平结果。

### 1.2 本版相对旧稿的主要修正

| 旧表述倾向 | 版本三的修正 |
| --- | --- |
| 以缓存类别数量或命中率衡量贡献 | 以单位资源净收益、SLO goodput、质量和公平衡量 |
| 冻结摘要后即可稳定复用前缀 | 冻结稳定前缀内的完整表示，使回答缓存有稳定的 `prompt_fingerprint` |
| 缓存收益只扣一次查询成本 | 显式核算在线、条件、后台和重配置/恢复四类管理税 |
| 默认缓存与算力一定需要联合优化 | 先用小规模离散扫描证明耦合存在 |
| 默认控制面能掌握引擎内部驻留 | KV 不再建模；路由只依据会话粘性、队列与实测时延 |
| 多层命中率与局部性可独立随机生成 | 收缩为三层，由会话事件与依赖图生成因果一致负载 |

### 1.3 范围边界

**必做：** 三层状态的统一元数据与依赖；vLLM 单后端；固定语义复用风险预算；离散配置；可审计的公平计数；机制分轨与受控端到端实验。

**交由并行项目（推理框架优化）：** 前缀 KV 的驻留、淘汰、迁移、预算、跨实例传输与逐前缀探测。本课题不建驻留目录、不设 KV 预算档位、不核算 KV 重建成本、不评估亲和预测准确率，也不与其比较 KV 层机制的优劣。

**条件增强：** 冷启动 ML、delay-hit 感知组批、在线精化预测、动态风险预算、故障期间主动预热。仅在基础闭环完成且预实验支持时选择。

**明确排除：** 引擎内 token pruning、非前缀 RAG KV 融合、KV 张量布局与 PagedAttention 改造、工具计划缓存、推测预解码、多后端泛化、多模型多硬件调度、强化学习调度与完整 MILP 在线求解。

### 1.4 为什么移出 KV 后论文仍然完整

三层覆盖三种介质与三种失效依据：文本状态在 Flink 状态后端，由版本与新鲜度失效；索引状态在外部向量库，由知识版本与 ACL 失效；答案状态在键值存储，由 prompt 指纹与上下文版本失效。三者生成、验证与重建成本各异，足以支撑“单位资源净收益”这一核心度量；研究点二只需“预算改变有效负载”，研究点三只需“同一会话是否留在同一副本”，都不依赖显存内容。

因此 KV 移出削减的是**性能上界**（少了 prefill 节省）与**一个故障维度**（驻留失真），不削减机制数量、因果链数量与实验对照数量。这一取舍应写成明确局限，而不是隐去。

## 2. 系统模型与关键语义

### 2.1 请求、约束与两类状态

请求 \(r\) 至少携带 `tenant_id/session_id/slo_class/arrival_time`，上下文组装后获得完整 prompt、依赖版本向量、`prompt_fingerprint` 和可用复用动作。租户约束包括 TTFT/E2E 时延、最终任务质量、权重与最低服务份额；被拒绝或降级的请求仍进入 offered-load 与 SLO 统计。

需要区分：

- **主状态**：原始对话、权威知识、权限和模型版本等真相来源，必须持久保存；
- **派生状态**：由主状态生成、用于加速的摘要、事实表示、检索结果和回答。可淘汰，但须可追溯来源并按要求失效或重建。

引擎内的前缀 KV 语义上也属派生状态，但不由本课题管理：不建模、不设预算、不做失效传播，只在 §1.3 声明分工。

### 2.2 三层派生状态

| 派生状态 | 典型对象 | 主要收益 | 主要风险 |
| --- | --- | --- | --- |
| 会话语义状态 `ctx` | 近期历史、冻结摘要、结构化事实与约束 | 减少上下文读取与未来 prompt 长度 | 摘要生成、事实过时、质量损失 |
| RAG 知识状态 `rag` | 文档块、embedding、检索结果及版本/ACL | 避免远端读取与重复检索 | 陈旧、越权、ANN/judge 成本 |
| 历史回答状态 `resp` | 带依赖、阈值与质量记录的回答 | 安全命中时短路整次推理 | 错误复用、embedding/verifier 成本 |

三层按“介质 + 失效依据”区分，而非按缓存位置区分。不把 KV 列为第四层，是因为它的价值与风险都绑定在具体显存和引擎实例内：控制面只能观测“请求落在哪个副本”，无法观测“哪些块还在”，强行建模只能得到不可证伪的猜测。

### 2.3 依赖失效必须闭合

```text
原始对话/权威知识/权限/模板/模型版本
        ├─→ 摘要与结构化事实 ─→ 完整 prompt ─→ prompt 指纹 ─→ 回答缓存
        ├─→ RAG 检索结果     ─→ 完整 prompt ─→ prompt 指纹 ─→ 回答缓存
        └─→ 历史回答的语义与质量依赖
```

失效判据由“物理位置”改为**内容指纹 + 版本向量**双重校验：指纹由规范化后的完整 prompt（含模板版本、模型 revision 与 salt）计算，版本向量记录知识版本、ACL 与事实 supersession，任一变化即禁止复用。

代价必须承认：无法按 prompt 位置做物理失效。残余风险两类——同义改写导致指纹不同，方向保守，只损失收益；依赖登记遗漏导致版本向量未覆盖某依赖，方向危险，会产生错误命中。前者靠实验报告额外 miss 率，后者须把依赖登记做成准入条件，并注入“未登记依赖”测量错误命中率。

不同层质量指标不能混用：回答语义等价、知识检索正确性、摘要事实准确性与最终任务质量分别报告，再用最终质量统一校验。分层预算只表示**各层语义复用风险预算**，不推出最终质量上界；最终质量须按租户、配置与漂移区间实测并报告置信区间，无法可靠校准时禁用相应近似复用。vCache-style 方法定位为**可校准门控**，不直接继承其特定分布假设下的理论保证。

## 3. 研究点一：跨层状态价值与联合生命周期

### 3.1 核心问题与输出

研究问题不是“如何再设计一种替换算法”，而是：

> 对每层派生状态，何时有资格复用，继续保留能避免多少真实工作，需要支付多少管理和风险成本，在有限介质预算下应采取什么生命周期动作？

每层输出有限的 `LayerBenefitPoint`，含预算、预计复用概率、时延节省分布、可避免资源工作、管理成本与质量风险，供研究点二选择。三层的可避免工作分别是上下文组装与读取字节、检索调用与 ANN 计算、整次推理的 GPU 时间。prefill 节省不计入收益，因其大小由引擎 APC 是否命中决定，控制面无法归因。

### 3.2 资格门控与净收益

状态项须同时满足 ACL、版本、新鲜度与质量要求才进入候选集。精确匹配项（同一 `prompt_fingerprint` 且版本一致）不占语义近似预算，但仍须通过 ACL 与隔离检查。

统一资源核算可写为：

```text
NetBenefit = AvoidedResourceWork
             - OnlineManagementCost
             - ConditionalMissOrStaleCost
             - AmortizedBackgroundCost
             - RebuildAndRecoveryCost
```

上式先按 GPU、CPU、网络等资源向量分别核算；确需压成标量时，再经部署单价或标定权重转换并做敏感性分析。时延收益保留为分布，质量作为约束，不把毫秒、GPU-ms、网络字节与质量分数相加。

| 管理税 | 具体内容 |
| --- | --- |
| 每请求在线税 | 状态访问、上下文组装、embedding/ANN、指纹计算与路由决策 |
| 命中/未命中条件税 | judge/verifier、安全验证、错误命中与额外回源 |
| 后台摊销税 | 摘要/事实提取、摄取、刷新、重校准、预取、checkpoint 与索引重建 |
| 重配置与恢复税 | rescale、状态迁移、恢复首轮上下文重组装与重复外部调用 |

每笔费用只进一个成本桶：无条件查询计在线税，命中或 miss 后触发的验证计条件税，故障与重配置窗口才计恢复税。辅助 embedding、judge、摘要模型的 CPU/GPU 消耗必须进 profile；指纹计算单次便宜但每请求发生，须计入在线税。

### 3.3 从“冻结摘要”到“冻结稳定前缀与指纹”

压缩动作的收益为：

\[
G_{compress}=\mathbb{E}[N_{future}]\Delta C_{shorter}-C_{summary}-C_{invalidation}
\]

其中 \(C_{invalidation}\) 表示因摘要、事实、RAG 或模板变化导致回答缓存失效、需重新推理的期望损失，并满足最终任务质量约束。

只有稳定前缀内的摘要、事实、RAG 片段、模板与模型兼容信息保持不变，`prompt_fingerprint` 才可能跨轮一致。若摘要每轮重写，指纹每轮变化，回答缓存命中率趋近零——这是“冻结”的经济含义，也是与“每轮重新摘要”的核心分歧。

实验须分两阶段：压缩后首轮测摘要生成、质量变化与失效损失；稳态测指纹一致率、回答命中恢复与回本轮数。对照包括不压缩、固定每 N 轮、价值/成本触发、去掉稳定前缀机制与知道未来轮数的 oracle。

### 3.4 最小实现、对照与裁剪

MVP 使用固定 chunk 与单一摘要 fidelity；RAG 采用版本/ACL 门控与 LRU/LFU；回答采用静态阈值或 vCache-style 二选一；复用频率用精确衰减计数，不强制 CMS 或 ML。

必做对照包括无缓存、LRU/LFU、静态阈值、价值密度策略与 Oracle。指标包括可避免 GPU-ms（仅计整次推理短路与上下文组装）、远端读取字节、检索调用次数、单位容量净收益、各层质量、churn 与四类管理税。

若 verifier 在短回答上比回源更贵，只对高价值回答启用；若状态规模不需要 CMS，则删除 CMS；若摘要频繁更新导致无法回本，固定 fidelity 或降为可选动作；若指纹失效率过高使回答缓存无法回本，则回答层只做精确重复命中。

## 4. 研究点二：面向异构 SLO 的缓存—算力联合配置

### 4.1 耦合假设必须可证伪

规划器在每个窗口选择离散配置：

\[
z=(p,b,B_{ctx},B_{rag},B_{resp},\theta_{resp},f_{ctx})
\]

`p` 表示 2–4 GPU 内独立单 GPU vLLM 副本数，而非引擎内 TP/PP；`b` 表示外部适配器允许进入每副本的最大在途请求数，不声称控制 vLLM 连续批处理内部 batch；`B_ctx/B_rag/B_resp` 是控制面可调的语义缓存预算。引擎侧 HBM 与 KV 档位由并行项目决定，本课题作为外生常量固定，不进入决策向量。

其成立依据不是“变量越多越先进”，而是缓存预算改变回答短路比例、有效到达率、上下文长度与检索调用，进而改变队列组成与最优 `(p,b)`。

```text
语义缓存预算变化
  → 回答短路比例与有效到达率变化
  → 上下文长度与检索调用变化
  → prefill/decode 与队列组成变化
  → 最优并行度或批次变化
```

2–4 GPU 下 `p` 只有少量整数点。若扫描中最优 `(p,b)` 不随缓存预算变化，就应写成“本规模下无需联合配置”的边界结论，而非用连续模型制造收益。这里的 prefill 变化只经 prompt 长度传导，不含“KV 命中率”，因此耦合假设比上一版更窄、更可验证。

### 4.2 分支时延与离散规划

端到端时延按路径建模：状态访问与组装、知识读取、回答检索与验证、排队、prefill、decode 与输出传输。回答命中与完全未命中分别估计，不能把平均命中率线性乘到单一时延模型上。

规划器与另外两点的最小接口：

| 输入 | 来源与用途 |
| --- | --- |
| 三层 benefit curves | 研究点一提供收益、管理税与风险随预算的变化 |
| workload forecast | 到达率、输出长度与会话复用预测 |
| TenantSLO 与最低份额 | 提供时延、语义复用风险与公平约束 |
| 分支时延与副本状态 | 提供回答/miss 路径、队列与副本能力画像 |
| previous config 与重配置 profile | 计算切换成本、滞后与冷却条件 |

规划器枚举合法配置，检查容量、队列稳定、最低份额与经实测校准的语义复用风险约束，选择满足约束的最低成本配置；运行反馈同时更新价值估计与预测器。预测误差不能只报 MAPE，还须注入相关漂移，报告高分位约束的经验 coverage、违约幅度与固定配置 fallback。

### 4.3 重配置与过载

新配置只有在其预计净收益覆盖 rescale、状态迁移、worker 调整、batch 打断与索引重建成本后才切换，并设置冷却与滞后。若所有配置都不可行，规划器输出过载信号，快环只能执行预先声明的降级、排队或快速拒绝，不得静默突破风险约束或质量准入边界。

核心对照收敛为固定配置、顺序独立调节、完整联合规划与离线 Oracle；只调 `(p,b)`、只调缓存及不计切换成本作为关键消融。若联合收益只在中高负载出现，应给出适用区间；若整体不显著，研究点二收缩为离散配置与边界分析。

## 5. 研究点三：复用感知的多租户公平调度

### 5.1 两级调度与真实工作量公平

第一级用 weighted deficit 与最低服务份额确定公平资格租户；第二级在合格集合内优先处理归一化剩余 slack 最小的请求。成本不能按请求数计量，但“只按 GPU/token”也会忽略高复用租户消耗的 ANN、judge、Flink state 与网络。

本版至少比较两种口径：

- **主推理资源口径**：按 token 加权估算的 GPU 工作量扣减；
- **关键共享资源口径**：按同一资源向量或标定成本，在主推理工作量上增加可归属的辅助管理成本。

连续批处理下不把 batch GPU 时间当作某请求的实测成本，可用 prefill/decode token 权重或 batch 级分摊估算，并用完成后观测校正。weighted service share 只在明确 backlogged 窗口内计算。分别报告 GPU 服务公平、请求/SLO 体验公平、辅助资源占用与最长等待，分析回答短路是否让高复用租户获得额外优势。Jain index 只作汇总，不能替代饥饿保护与分租户 goodput。

### 5.2 复用动作、会话粘性与 worker 路由

对未被回答缓存短路的请求，令 \(Q_w\) 表示预计排队等待时间，基础版比较：

\[
T_{sticky}=Q_w+T_{lookup}+T_{prefill-remain}+T_{decode}
\]

\[
T_{migrate}=Q_{w'}+T_{prefill-full}+T_{decode}
\]

`T_prefill-remain` 是**统计估计**：由同一会话前几轮实测 TTFT 与本轮 prompt 增量拟合，不来自驻留查询，本课题也不声称其准确。只有粘性路径的预计完成时间优于迁移重算并超过滞后阈值时，才保持粘性。

两条限定必须写明：其一，本课题不掌握显存驻留，粘性收益来自“引擎 APC 大概率仍有该会话前缀”，是概率性收益；其二，若“粘性”与“最短队列”的时延差落在噪声内，该机制在 2–4 GPU 上不成立，应退回最短队列。这正是 E0c 要回答的问题，也是本版最可能出现的负结果。

扩展版可把回答复用、部分上下文降级与完整重算统一视为动作集合，但仍须可解释，不默认引入学习型调度。

Preble 与 LMetric 是缓存复用—负载均衡的重要参照，本文借用其“局部性与负载存在张力”的问题设定，但不比较其 KV 层机制；DLPM/D²LPM 是 locality-fairness 参照；JITServe 与 QoServe 分别提供不精确信息下的 SLO goodput 与多 QoS/过载处理参照。黑盒外部调度器只实现“外部 SLO 紧迫度启发式”，不声称复现 JITServe 的引擎内机制。仅将一致性哈希换成 Flink 路由，或只比较 FCFS，不能构成充分贡献。

### 5.3 组批、过载与指标

组批可在公平选择后的集合内偏好相同副本、相近 prompt 长度、相近输出长度与相近 SLO，但须有界等待。所有 worker 都预计违约时，依次判断安全降级、可接受排队与快速拒绝，拒绝原因与租户须可审计。

核心对照收敛为 FCFS＋最短队列、一个最相关的 locality/fairness 基线、外部 SLO 紧迫度启发式、完整方法与 Oracle；一致性哈希、VTC、Preble/LMetric-style 按具体主张选择，不要求等价复现。指标包括分租户 P95/P99 TTFT/E2E、SLO goodput、weighted service share、slowdown、最长等待、会话迁移次数、粘性命中率、负载不均与路由开销。

所有到达请求计入 offered-load 分母；只有同时满足质量底线与 deadline 的请求进入 goodput 分子。回答命中可计入，但须完成同样的质量、SLO 与辅助资源记账；拒绝计入分母不计入分子，降级仅在达到声明质量底线时计入。

若 2–4 GPU 上粘性—公平冲突不稳定，调度收缩为执行模块；若预测成本误差导致公平失真，则采用完成后观测校正与保守估计。

## 6. Flink＋vLLM 实现可行性

### 6.1 控制面与数据面分工

```text
慢环：StateValueEstimator → JointPlanner
                              │ Broadcast PlannerConfig
                              ▼
Source → Admission + Fairness Accounting
       → Session Assembler → RAG/Response Reuse Gate
              │ miss                         │ response-hit
              ▼                              ▼
       Tenant Scheduler + Worker Router   State Update + Metrics → Sink
       → Batcher/vLLM → State Update + Metrics → Sink

Flink：会话状态、元数据、SLO、公平计数、配置和 checkpoint
数据面：ANN 索引、知识副本、vLLM 模型执行与辅助模型
       （引擎内 KV 张量由并行项目负责，本课题不读写）
```

准入与公平记账位于复用门控之前；回答命中与普通推理都进入统一的质量、SLO、offered-load 与辅助资源反馈，避免快速路径绕过研究点三。checkpoint 只覆盖控制状态，不声称恢复 ANN 索引或引擎内 KV。`request_id/config_epoch/worker_generation` 只用于关联、过期与去重，重复推理仍可能发生；重复输出由持久去重的 Sink 或适配层抑制，不能把外部 exactly-once 归功于 checkpoint。

### 6.2 后端能力与降级路径

| 能力 | 主版本可用语义 | 不可假设或降级方式 |
| --- | --- | --- |
| worker 校验 | 存活、负载和 `worker_generation` | 只用于故障与负载判断，不推断前缀是否驻留 |
| Flink 状态 | keyed/broadcast state、checkpoint 与重分区 | 大模型 KV 与大数据面索引不进 checkpoint |
| 异步外部调用 | 超时、重试、幂等键与重复完成处理 | 不宣称端到端 exactly-once |
| 前缀 KV 驻留 | 不在本课题范围，由并行项目负责 | 不建目录、不做逐前缀探测、不评估误判 |

本课题对 worker 只有三类观测：存活、负载、generation。三者都不足以推断显存内容，因此路由只判断“同一会话是否继续留在该副本”，不判断“某前缀是否还在”。

### 6.3 最小系统与工程退出条件

MVP 只做三层状态、离散配置与可解释调度；不建 KV 目录、不做 KV 迁移、不调用任何未公开的前缀探测接口。

若无法获得“同一会话落在哪个副本”的反馈，仍可比较“粘性开”与“粘性关”，并用量级估计给出粘性收益上界；若差值为零，说明该机制在本规模不成立，应把调度收缩为执行模块。若三层依赖负载、分支成本或 worker 反馈都无法稳定采集，应缩减状态层与调度功能，而不是用虚构接口维持表面完整。

## 7. 预实验、实验矩阵与证据链

### 7.1 因果一致的负载生成

端到端负载不能独立随机组合三层命中率。生成器以会话事件为单位：先生成 transcript、知识版本、摘要/事实更新、RAG 变更与模板事件，再派生完整 prompt、`prompt_fingerprint`、回答依赖与可用复用动作。回答命中会短路推理；指纹变化会使回答缓存失效；知识版本会约束回答有效性。

实验采用“机制分轨＋受控端到端”双轨，分别报告 cold cache、warm cache 与恢复期。真实 trace 用于外部验证，合成器用于注入租户权重、SLO、局部性、漂移、故障与过载。

最终任务质量用带参考答案的基准实测：长期会话用 LoCoMo/LongMemEval 任务指标，RAG 问答用 HotpotQA/MuSiQue 的 EM/F1；若用 LLM judge 评估回答等价性，须抽样人工校验其可靠性，并把 judge 成本计入管理税。合成负载不能替代最终质量验证。

### 7.2 E0：决定研究范围的门槛实验

| 预实验 | 要回答的问题 | 通过或不通过时的处理 |
| --- | --- | --- |
| E0a 管理税 | 稳态可避免成本是否大于在线、条件与后台摊销成本 | 无净收益层降级为简单基线；全生命周期收益由 E5 判断 |
| E0b 配置耦合 | 缓存预算变化是否改变最优离散 `(p,b)` | 不改变则研究点二转为边界与顺序配置 |
| E0c 粘性与公平冲突 | 会话粘性、负载与公平是否在 2–4 GPU 上稳定冲突 | 冲突弱或差值在噪声内，调度只作支撑模块 |

门槛实验由四道减为三道：原第四道（目录失真）随 KV 移出而删除。这不是遗漏，而是范围收窄的代价——本课题不再回答“控制面误判驻留造成多少损失”，该问题归并行项目。

### 7.3 核心实验矩阵

| 实验 | 对照与核心指标 |
| --- | --- |
| E1 状态净收益 | 无缓存、LRU/LFU、静态阈值、价值策略、Oracle；净节省、管理税、质量、churn |
| E2 摘要—指纹联合 | 不压缩、固定周期、成本触发、去稳定前缀、Oracle；首轮失效损失、回本轮数、指纹一致率、最终质量 |
| E3 联合配置 | 固定、顺序、联合、Oracle，消融单侧调节与切换成本；SLO goodput、GPU-hours、coverage、切换损失 |
| E4 公平调度 | FCFS、一个 locality/fairness 强基线、外部 SLO 启发式、完整方法、Oracle；分租户 goodput、公平、会话迁移、粘性命中 |
| E5 闭环与恢复 | 完整闭环、三层独立管理、固定配置、去公平、去质量门控、粘性开/关；端到端 goodput、总管理税、恢复时间、重复推理 |

关键结论报告多种子均值与 95% 置信区间，明确 warm-up、测量窗口、模型 revision 与软件版本。论文自报倍数只用于理解，不与本机结果横向比较。

### 7.4 必须保留的负收益区间

短上下文或 decode-bound、低复用、远端读取便宜、知识高更新、严格质量约束、严格公平、引擎前缀缓存已由外部框架优化到位、低负载无需重配置等场景都必须进入结果。研究结论应解释机制**何时有效、何时不值得启用**，而不是只挑选有利负载。

其中“引擎前缀缓存已由外部框架优化到位”是 KV 移出后新增的必报区间：它会直接削弱粘性收益，若无优势应作为主要负结果呈现。

## 8. 创新边界、范围裁剪与讨论收束

### 8.1 待实验支持的三项贡献

1. **三层派生状态模型与生命周期**：统一表达文本、索引、答案三种状态的来源、依赖、质量、管理税与恢复语义，验证何时具有正净收益。
2. **可裁剪的缓存—算力联合配置**：用离散收益曲线连接状态层与推理配置，明确耦合成立与不成立的负载区间。
3. **复用感知的公平调度**：在时延、质量与最低份额约束下，联合决定复用、排队、路由与会话迁移，量化真实工作量与公平结果。

三项均为待验证贡献，不使用“首个”“首次”或“必然优于”。第三项的证据强度取决于 §5.2 的粘性收益是否可测，不可测则自动降级。

### 8.2 与相关工作的边界

| 工作 | 已覆盖内容 | 本课题可保留的问题 |
| --- | --- | --- |
| vCache / Cortex | 回答或知识的语义缓存、验证与阈值 | 跨层依赖、管理税、质量与资源联合控制 |
| Preble / LMetric | 分布式前缀复用与负载均衡路由 | 多层语义状态、异构 SLO 与公平口径（不比较其 KV 层机制） |
| DLPM/D²LPM | locality-aware fair scheduling | 跨层复用动作、辅助资源成本、慢/快环协同；其为预印本，不夸大 venue |
| JITServe / SOLA | 不精确信息或状态感知的 SLO 调度 | 长生命周期会话状态、缓存预算与公平约束 |
| QoServe / Agentix | 多 QoS 调度或 Agent 程序级调度 | 三类派生状态、缓存净收益与跨副本恢复 |
| Strata / KVFlow | 引擎侧分层缓存与工作流感知 KV 管理 | 不进入该层，仅在“收益须扣除管理成本”这一观察上引用 |

### 8.3 裁剪顺序与高层安排

若预实验不支持完整方案，按序裁剪：先删高风险增强；再简化 ML、CMS 与动态风险预算；随后将研究点二或三降级为支撑模块；最后保留“跨层状态生命周期＋质量约束”作为最小主线。

16 周可概括为：W1–2 冻结负载、阶段 profile 与统一 schema；W3–6 完成状态层与 E0/E1/E2；W7–9 判断并完成配置实验；W10–12 完成调度实验；W13–15 做端到端、恢复、消融与外部验证；W16 整理论文与答辩材料。若 W2 仍无法稳定构造因果一致负载，立即采用机制分轨，不等待完美数据集。

### 8.4 带回导师讨论的最终问题

1. 是否认可“三层闭环但允许按预实验裁剪”的结构，而不是三章平均用力？
2. 研究点二的联合配置与研究点三的公平调度，哪一个更值得作为主要系统创新？
3. 是否同意把前缀 KV 整体交给并行项目，本课题只消费“引擎 APC 在运行”，不建目录、不设预算、不评估预测准确性？
4. 基础版采用固定语义复用风险预算、单后端且无 KV 目录，是否足以在四个月内形成完整证据链？
