## 0. 结论速览

### 0.1 推荐题目

当前拟题“基于流处理的 Agent 框架的高效资源管理与优化研究”覆盖面较宽，适合作为方向名称，但没有指出论文真正要处理的矛盾。建议准备三个层次不同的题目，待研究范围稳定后再定：

1. **面向异构 SLO 的流式 Agent 推理跨层状态管理与缓存感知调度研究**（推荐，问题边界最清楚）
2. **面向多租户 Agent 会话的流式状态、算力与 SLO 协同优化研究**（系统性更强）
3. **基于流处理的 Agent 框架高效资源管理与优化研究**（保留当前宽口径拟题）

本文按题目一的口径展开，但不要求现在改题。

### 0.2 推荐的研究母题

多轮 Agent 推理不再由彼此独立的请求组成。对话摘要、结构化事实、RAG 知识、历史回答和前缀 KV 等状态可以跨轮或跨会话复用。复用一方面减少远端知识读取、上下文处理和 GPU 推理，另一方面带来状态存储、语义验证、刷新、迁移与恢复开销，并使请求对特定 worker 产生缓存亲和性。

在多租户环境中，这种亲和性与另外两个目标发生冲突：

- 缓存亲和性希望相似请求集中到已有状态的 worker；
- 负载均衡希望请求分散到空闲 worker；
- 租户公平与异构 SLO 又要求不能长期优先服务容易命中的租户。

因此，论文不应以“设计更多缓存类型”为主线，而应回答一个统一问题：

> 在动态多租户负载下，如何由 Flink 控制面联合决定保留哪些可复用状态、为各层状态和推理配置多少资源，以及请求应当先服务谁、发送到哪里、何时放弃缓存亲和性，从而在时延、质量与公平约束下最小化资源成本？

### 0.3 三个研究点及其关系

| 层次 | 研究点 | 回答的问题 | 主要输出 |
| --- | --- | --- | --- |
| 状态层 | 跨层状态价值建模与联合生命周期管理 | 保留什么、何时刷新或淘汰 | 各状态层的“预算—收益—风险”曲线 |
| 规划层 | 面向异构 SLO 的缓存—算力联合配置 | 配置多少缓存和推理资源 | `(p, b, 四层预算, 阈值, fidelity)` |
| 执行层 | 缓存感知的多租户公平调度 | 先服务谁、发往哪里、何时放弃亲和 | 准入、复用动作、目标 worker |

三点之间的依赖是单向且可验证的：

```text
状态访问与复用观测
        │
        ▼
研究点 1：估计复用价值、质量风险和管理税
        │ 输出各层 benefit curve
        ▼
研究点 2：联合选择缓存预算、并行度和批次
        │ 输出配置与过载信号
        ▼
研究点 3：按租户 SLO、公平性和缓存位置调度
        │ 反馈命中、时延、错误、队列和服务份额
        └──────────────────────────────┘
```

### 0.4 核心取舍

本文纳入四类缓存，但不为四类缓存分别设计四套算法。四类对象共享：

- 统一的状态元数据；
- 统一的依赖与失效模型；
- 冷启动到暖态的复用概率估计；
- 质量、权限、版本与新鲜度门控；
- 预算变化下的收益曲线。

它们只在动作集合和容量介质上保留必要差异。这样才能把工作量控制在硕士毕业设计范围内。

## 1. 从“聚焦点”到可研究问题

### 1.1 当前方案已经具备的结构

`prototype.md` 第二版给出了一个正确的因果顺序：

```text
缓存管理决定“保留什么”
  → 算力管理决定“配置多少资源”
  → 负载均衡决定“先服务谁、送到哪里、何时放弃亲和性”
```

需要补足的不是更多名词，而是每一步的输入、输出和可检验假设。

当前表述还存在四个结构性问题：

1. **缓存对象不清**：上下文文本、摘要、RAG 文档、历史回答、embedding 和 KV 张量的表示、作用域、失效条件不同，不能统一称为“语义库”。
2. **价值口径不清**：命中率高不等于收益高。一次回答复用可能省掉完整推理，一次短 RAG chunk 命中只省掉很小的读取开销；错误命中的代价也不同。
3. **控制变量没有闭合**：并行度和 batch size 会影响推理能力，缓存预算会改变到达推理后端的有效流量，二者不能独立调节。
4. **调度冲突没有机制**：一致性哈希只能维持亲和性，无法判断拥塞时是否应当打破亲和，也没有多租户公平保证。

### 1.2 本课题真正研究的三组张力

#### 张力一：语义状态压缩与前缀 KV 复用

对话摘要和结构化事实可以缩短上下文，但摘要改写会改变 prompt 的 token 序列，原有 KV 链哈希随之失效。压缩的净收益不能只看 token 缩短量，还要扣除：

- 摘要生成或更新开销；
- 摘要替换后第一次 KV 重建的 prefill 开销；
- 语义压缩造成的任务质量损失。

这是一条适合形成研究问题的真实冲突，而不是“摘要和 KV 都能加速”的简单叠加。

#### 张力二：缓存预算与推理资源

回答缓存命中会直接减少推理请求；RAG 和上下文状态命中会缩短前处理；KV 命中会减少 prefill。缓存预算越大，到达推理 worker 的有效工作量通常越低，但状态访问、验证、刷新和 checkpoint 开销也会上升。

因此，`p`、`b` 与缓存预算之间存在耦合：

```text
缓存预算变化
  → 各层命中概率和管理税变化
  → 推理到达率、prompt 长度与 prefill 工作量变化
  → 最优并行度和 batch size 变化
```

#### 张力三：缓存亲和性、负载均衡与公平

只按缓存命中调度会把热点租户集中到少量 worker，甚至让高复用租户持续插队；只按最短队列调度又会频繁丢失前缀复用。已有 DLPM/D²LPM 已经研究 prefix locality 与公平、分布式负载均衡之间的矛盾，因此本课题不能只重复“缓存感知公平调度”。可保留的空间是：

- 调度对象从单层 prefix locality 扩展到 Agent 会话的四层状态；
- SLO 不只有公平份额，还包含租户级时延和质量预算；
- 调度使用研究点一、二产生的状态价值与全局配置；
- 缓存亲和的放弃条件显式考虑状态重建、语义验证和会话依赖。

### 1.3 总体研究问题

本文将总问题拆为四个可测试问题：

- **RQ1**：统一状态价值模型能否在相同容量下，比各层独立 LRU/LFU/静态阈值取得更高的有效复用收益，并把质量风险控制在租户预算内？
- **RQ2**：联合调节四层缓存预算、并行度和 batch size，能否比“只调算力”或“只调缓存”以更低资源成本满足异构 SLO？
- **RQ3**：两级多租户调度能否在缓存亲和、尾时延和公平性之间形成更优的 Pareto 折中？
- **RQ4**：在负载漂移、知识版本更新、worker 故障和 Flink rescale 时，控制面能否正确识别失效状态并有界恢复，而不把陈旧元数据当成可用缓存？

## 2. 研究边界与系统模型

### 2.1 必做范围

| 维度 | 本课题范围 |
| --- | --- |
| 业务形态 | 多轮、跨会话可复用的只读 Agent 推理 |
| 知识访问 | 管线内的只读 RAG 知识服务 |
| 流处理层 | Flink 中的会话状态、缓存目录、预测、配置与调度 |
| 推理后端 | vLLM 为主，使用公开能力做精确前缀缓存 |
| 资源规模 | 2–4 张 GPU |
| SLO | TTFT、单轮端到端时延、质量/错误预算、租户最低服务份额 |
| 时间尺度 | 慢环配置优化 + 快环逐请求调度 |

### 2.2 明确排除

- 不研究支付、写数据库、发消息等有副作用工具调用；
- 不修改 CUDA kernel、KV 张量布局或 PagedAttention；
- 不训练 IntentKV 式 token-level KV pruning 模型；
- 不把 KV 张量放入 Flink checkpoint；
- 不声称 Flink 对外部 vLLM 调用和 KV 驻留天然提供 exactly-once；
- 不把四类缓存做成四篇互不相关的小论文；
- 不把“命中率最高”直接当作系统最优目标。

### 2.3 系统实体

设：

- 租户集合为 \(\mathcal{K}\)，租户 \(k\) 具有独立 SLO 和公平权重；
- 会话集合为 \(\mathcal{S}\)，每个会话属于唯一租户；
- 请求集合为 \(\mathcal{R}\)，请求 \(r\) 是会话中的一轮；
- 推理 worker 集合为 \(\mathcal{W}\)，每个 worker 运行同一模型后端；
- 状态层集合为 \(\mathcal{C}=\{ctx, rag, resp, kv\}\)；
- 状态项集合为 \(\mathcal{E}_c\)，每项具有容量、位置、依赖、复用和风险属性。

请求的输入至少包含：

```text
Request {
  request_id,
  tenant_id,
  session_id,
  turn_id,
  user_query,
  arrival_time,
  slo_class,
  model_revision,
  prompt_template_revision
}
```

### 2.4 多租户 SLO

对租户 \(k\)，定义：

\[
\mathrm{SLO}_k =
(D_k^{ttft}, D_k^{e2e}, \epsilon_k^{lat},
\delta_k^{quality}, w_k, \rho_k^{min})
\]

含义如下：

| 符号 | 含义 |
| --- | --- |
| \(D_k^{ttft}\) | TTFT 目标 |
| \(D_k^{e2e}\) | 单轮端到端时延目标 |
| \(\epsilon_k^{lat}\) | 允许的时延违约比例 |
| \(\delta_k^{quality}\) | 允许的错误复用/质量损失预算 |
| \(w_k\) | 公平调度权重 |
| \(\rho_k^{min}\) | 过载时的最低服务份额 |

系统应满足：

\[
\Pr(T_r^{ttft}\le D_k^{ttft}) \ge 1-\epsilon_k^{lat}
\]

\[
\Pr(T_r^{e2e}\le D_k^{e2e}) \ge 1-\epsilon_k^{lat}
\]

\[
\Pr(\text{unsafe reuse or unacceptable quality loss})
\le \delta_k^{quality}
\]

质量预算不能与毫秒直接相减。它在基础版中作为硬约束；只有在所有候选配置都满足质量约束后，才比较资源成本和时延。

### 2.5 会话时延口径

由于本课题排除任意工具调用，且多轮会话之间可能存在用户思考时间，不能把整个自然时间跨度直接作为系统 JCT。实验使用两个口径：

1. **单轮端到端时延**：请求进入 Flink 到答案完成；
2. **会话主动处理时间**：一个会话所有轮次的系统处理时延之和，不包含用户空闲时间。

这样可以保留会话级评价，又不会把系统不可控的等待计入调度效果。

## 3. 四层可复用状态

### 3.1 状态分类

| 层 | 缓存对象 | 权威来源 | 命中后省略的阶段 | 主要位置 | 主要风险 |
| --- | --- | --- | --- | --- | --- |
| 会话语义状态 | 冻结摘要块、结构化事实/偏好/约束 | 原始 transcript | 摘要/事实提取及部分上下文 token | Flink Keyed State 或状态后端 | 压缩丢失、事实被后续轮次覆盖 |
| RAG 知识状态 | 文档 chunk、embedding、检索结果、版本 | 只读知识源 | 远端读取、embedding 或检索 | Flink/本地索引/外部状态后端 | 陈旧、ACL 越权、版本不一致 |
| 历史回答状态 | 完整 prompt/语义签名到历史回答 | 原始请求、依赖版本、生成结果 | 完整 LLM 推理 | Flink 元数据 + ANN 索引 + 回答存储 | 语义误命中、依赖已失效 |
| 前缀计算状态 | 精确 token 前缀对应的 KV blocks | transcript、RAG 和 prompt 可重算 | 命中部分的 prefill | vLLM worker 或可选外部 KV 层 | worker 丢失、精确前缀变化 |

需要区分“主状态”和“缓存”：

- 原始 transcript 和知识源是权威主状态，不因缓存淘汰而丢失；
- 摘要、结构化变量、embedding、历史回答索引和 KV 都是派生状态；
- 如果某项派生状态已经成为唯一信息来源，它就不再是可淘汰缓存，必须转入主状态治理范围。

### 3.2 会话语义状态

会话语义状态包含两种互补表示：

```text
SummaryBlock {
  session_id,
  chunk_id,
  source_turn_range,
  summary_text,
  source_hash,
  model_revision,
  fidelity_level,
  frozen,
  supersession_refs
}

StateVariable {
  session_id,
  variable_name,
  current_value,
  source_turn_id,
  confidence,
  valid_from_turn,
  superseded_by,
  variable_type  // fact, preference, constraint, goal
}
```

摘要保留叙事上下文，结构化变量保留可查询的当前事实。摘要一旦进入 prompt，应尽量冻结；反复重写会不断改变后续前缀，破坏 KV 命中。事实发生变化时，使用 supersession 链标记旧值过期，而不是静默覆盖。

### 3.3 RAG 知识状态

本课题把 RAG 视为只读知识检索阶段，不包含任意 Agent 工具。缓存对象包括：

```text
KnowledgeEntry {
  tenant_scope,
  document_id,
  chunk_id,
  text_or_reference,
  embedding,
  source_version,
  acl_version,
  fetched_at,
  freshness_deadline,
  retrieval_stats
}
```

知识缓存的有效条件至少包括：

- 当前请求所属租户具有访问权限；
- `source_version` 与知识源一致；
- 条目没有超过业务 freshness；
- embedding 模型与索引版本一致。

Flink State TTL 只能作为清理辅助手段。官方文档明确指出 TTL 目前以 processing time 为基准，过期清理由后端 best effort 执行；业务新鲜度仍需显式版本与事件时间判断，不能把“物理条目尚未清理”误判为“仍可使用”。

### 3.4 历史回答状态

回答缓存的复用粒度是完整响应。一个条目应包含：

```text
ResponseEntry {
  tenant_scope,
  semantic_key,
  prompt_fingerprint,
  answer,
  embedding,
  context_version,
  knowledge_dependencies[],
  model_revision,
  decode_config,
  validation_stats,
  per_entry_threshold,
  created_at,
  freshness_deadline
}
```

语义相似度只负责召回候选，不能单独决定命中。复用至少经过：

1. 租户/信任域和 ACL 检查；
2. 上下文与知识依赖版本检查；
3. 相似度或轻量 verifier 的质量门控；
4. 租户剩余质量预算检查。

vCache 已经研究逐条目阈值和用户指定错误率下的答案复用，本课题不重新发明该算法。这里把 vCache 式质量门控作为一层可插拔机制，研究其容量、管理税、漂移状态与推理配置如何进入统一控制。

### 3.5 前缀计算状态

vLLM 的 Automatic Prefix Caching 使用父块哈希、当前块 token 和附加哈希识别完整 KV block。它只复用精确相同前缀，并只减少 prefill，不减少 decode。

Flink 只维护小体量目录：

```text
PrefixResidency {
  tenant_scope,
  prompt_hash_root,
  token_length,
  block_count,
  model_revision,
  tokenizer_revision,
  cache_salt,
  worker_id,
  worker_generation,
  last_confirmed_at,
  expected_rebuild_cost
}
```

KV 张量仍由 vLLM 管理。目录只能表达“最近观测到哪个 worker 持有该前缀”，不能把驻留描述成强保证。worker 重启、vLLM 内部淘汰或显存压力都可能使目录变陈旧。

为隔离多租户，前缀复用限定在显式信任域内，并使用后端支持的 `cache_salt` 或等价隔离字段。跨租户默认不共享。

### 3.6 统一状态元数据

四类状态使用统一外壳：

```text
ReusableStateMeta {
  state_id,
  state_type,            // ctx, rag, resp, kv
  tenant_scope,
  session_scope,
  content_hash,
  source_versions[],
  dependency_ids[],
  storage_tier,
  location,
  size_bytes,
  lifecycle_state,

  last_access_time,
  decayed_frequency,
  inter_arrival_stats,
  cms_frequency,
  observed_reuse_count,

  predicted_reuse_probability,
  avoidable_latency,
  avoidable_gpu_work,
  lookup_cost,
  refresh_cost,
  rebuild_cost,

  quality_risk_upper_bound,
  freshness_deadline,
  acl_version,
  worker_generation
}
```

统一元数据不意味着四类容量可以直接相加。HBM、CPU 内存、Flink 状态和本地 ANN 索引是不同介质，必须分别受容量约束。统一的是决策信息和生命周期语义，而不是物理存储池。

### 3.7 依赖与失效传播

```text
原始 transcript ──> SummaryBlock / StateVariable ──┐
                                                    ├─> 完整 prompt ──> 前缀 KV
知识源版本 ───────> RAG chunk / embedding ──────────┤
                                                    └─> 历史回答
模型 / tokenizer / prompt 模板 ─────────────────────┘
```

典型失效规则：

| 变化 | 必须失效或重建的对象 |
| --- | --- |
| 摘要被重新生成 | 依赖旧摘要的回答条目、后续精确 KV |
| 结构化事实被 supersede | 依赖旧值的回答条目 |
| 知识版本变化 | 对应 RAG 条目、依赖该知识的回答 |
| ACL 变化 | 旧授权范围内的知识和回答复用资格 |
| 模型或 tokenizer 变化 | 回答复用资格重新验证、全部 KV |
| prompt 模板变化 | prompt fingerprint、回答依赖、KV |
| worker generation 变化 | 该 worker 的全部 KV 驻留记录 |

失效传播只处理元数据。大规模索引重建可以作为后台低优先级任务，不能阻塞主请求路径。

## 4. 总体架构与闭环

### 4.1 分层架构

```text
                          ┌─────────────────────────────┐
                          │      慢时间尺度控制环       │
                          │  StateValueEstimator        │
                          │      ↓ benefit curves       │
                          │  JointPlanner               │
                          │      ↓ config / budgets     │
                          └──────────────┬──────────────┘
                                         │ Broadcast config
                                         ▼
┌────────┐   ┌────────────────┐   ┌───────────────────┐
│ Source │ → │ Session State  │ → │ RAG Cache /       │
└────────┘   │ Assembler      │   │ Knowledge Read    │
             └────────────────┘   └────────┬──────────┘
                                           ▼
                                  ┌───────────────────┐
                                  │ Response Reuse    │── hit ──→ Sink
                                  │ Gate              │
                                  └────────┬──────────┘
                                           │ miss
                                           ▼
                                  ┌───────────────────┐
                                  │ Tenant Scheduler  │
                                  │ + Worker Router   │
                                  └────────┬──────────┘
                                           ▼
                                    ┌──────────────┐
                                    │ Batcher /    │
                                    │ vLLM Workers │
                                    └──────┬───────┘
                                           ▼
                                    ┌──────────────┐
                                    │ State Update │
                                    │ + Metrics    │
                                    └──────────────┘

Flink 管理：会话状态、知识/回答元数据、KV 驻留目录、SLO、公平计数、配置
数据面管理：ANN 索引、知识内容副本、vLLM KV 张量、模型执行
```

### 4.2 单请求处理顺序

1. Source 为请求补齐 `tenant_id/session_id/slo_class`。
2. Session State Assembler 读取原始近期对话、冻结摘要和结构化变量，校验 supersession。
3. RAG 层先检查知识版本与 ACL；命中则返回缓存条目，未命中才访问只读知识服务。
4. 构造完整 prompt 和依赖版本向量。
5. 回答缓存用语义索引召回候选，经过版本、权限和质量门控后决定是否短路。
6. 未短路的请求生成精确 prompt hash；查询 KV 驻留目录。
7. 两级调度器选择租户、复用动作和目标 worker；Batcher 在有界等待内组批。
8. 推理完成后更新回答条目、KV 驻留目录、访问统计、质量反馈和租户服务量。

将回答缓存放在完整依赖确定之后，意味着它至少要完成轻量的上下文和知识版本检查。这比“只对用户当前一句话做 embedding，命中后跳过全部上下文组装”更保守，但能避免陈旧知识或不同会话状态下复用同一回答。

### 4.3 两个控制时间尺度

| 时间尺度 | 触发方式 | 决策 | 目标 |
| --- | --- | --- | --- |
| 慢环 | 固定窗口或漂移触发 | 四层预算、阈值、fidelity、`p`、`b` | 控制资源和长期 SLO |
| 快环 | 每个请求 | 准入、复用、租户排序、worker 路由 | 应对队列与缓存状态瞬时变化 |

慢环不应逐请求运行 MILP；快环也不应擅自突破质量预算。二者通过配置版本衔接：

```text
PlannerConfig {
  config_epoch,
  p,
  batch_size,
  layer_budgets,
  quality_sub_budgets,
  response_threshold_policy,
  context_fidelity,
  min_residency_time,
  max_replacement_ratio,
  overload_policy
}
```

### 4.4 Flink 状态映射

| 状态 | 建议形式 | 分区方式 | 恢复说明 |
| --- | --- | --- | --- |
| 会话摘要、结构化变量 | Keyed State | `(tenant_id, session_id)` | checkpoint 恢复后可直接继续组装上下文 |
| 租户公平计数、SLO 观测 | Keyed State | `tenant_id` | 恢复时保持服务量和 deficit |
| RAG/回答元数据 | 分片 Keyed State | `(tenant_scope, semantic_bucket)` | ANN 索引可由元数据重建 |
| KV 驻留目录 | 分片 Keyed State | `(tenant_scope, prompt_hash)` | 恢复后先标记 uncertain，再向 worker 校验 |
| 当前全局配置 | Broadcast State | 配置流广播 | 只广播小体量配置，不广播缓存条目 |
| 本地 ANN 索引 | 可重建数据面 | 与算子分片一致 | 不宣称由 checkpoint 原样恢复 |

Flink 的 keyed state、异步 checkpoint 和重分区能力适合保存控制状态；外部 vLLM 调用和 KV 驻留仍需 `request_id/config_epoch/worker_generation` 做幂等和过期判断。

## 5. 研究点一：跨层状态价值建模与联合生命周期管理

### 5.1 研究目标

研究点一不追求一个算法同时替代 vCache、Cortex 和 vLLM 缓存管理，而是提供一个上层统一决策框架：

> 对每个派生状态，先判断它是否有资格复用，再估计继续保留的边际收益和管理税，最后在各存储介质预算内决定其生命周期动作。

输出不是单一“缓存分数”，而是每一层在不同预算下的收益曲线：

```text
LayerBenefitPoint {
  layer,
  budget,
  predicted_hit_or_reuse,
  latency_saved_distribution,
  gpu_work_saved_distribution,
  management_cost,
  quality_risk_upper_bound
}
```

### 5.2 资格门控

状态项 \(e\) 在时刻 \(t\) 可进入候选集，当且仅当：

\[
\mathrm{Eligible}(e,t)=
\mathrm{ACL}(e,t)
\land \mathrm{VersionValid}(e,t)
\land \mathrm{Fresh}(e,t)
\land \mathrm{Risk}(e,t)\le \delta_{k,c}
\]

其中 \(\delta_{k,c}\) 是租户 \(k\) 分配给状态层 \(c\) 的质量子预算。

基础版使用固定拆分：

\[
\delta_{k,ctx}+\delta_{k,rag}+\delta_{k,resp}
\le \delta_k^{quality}
\]

利用 union bound 可以得到保守的总风险上界，不需要假设三类错误独立。精确前缀 KV 在 token、模型、tokenizer、salt 和版本完全一致时不引入语义近似风险，因此不占语义错误预算；哈希碰撞和隔离错误归入系统正确性检查。

动态分配质量子预算有研究价值，但会扩大优化空间，列为增强项。

### 5.3 冷启动与暖态估计

现有方案提出“前期机器学习、后期再结合高效数据结构”。这条思路可以保留，但不应使用固定权重相加。

对状态项 \(e\)，定义：

- \(\hat p_e^{ml}\)：基于内容、会话阶段、大小、租户类别、首次访问时间等特征的冷启动预测；
- \(\hat p_e^{online}\)：基于衰减频率、访问间隔和近期趋势的在线估计；
- \(n_e\)：有效观测量；
- \(\kappa\)：从冷启动过渡到暖态的平滑系数。

使用：

\[
\alpha_e=\frac{n_e}{n_e+\kappa}
\]

\[
\hat p_e=(1-\alpha_e)\hat p_e^{ml}
+\alpha_e\hat p_e^{online}
\]

其意义是：

- few-shot 阶段缺少个体历史，依赖模型的跨条目泛化；
- 观测增多后，逐渐相信该条目的真实访问过程；
- 不是在任意时刻将两个归一化分数机械地各乘一个固定权重。

Count-Min Sketch 只用于大规模频率近似和趋势特征，不保存全部业务语义。热点条目可维护精确计数，长尾条目进入 sketch。若实测规模不大，基础版可以只使用带时间衰减的精确 MapState，避免为了数据结构而使用数据结构。

### 5.4 边际收益

对可行动作 \(a\)，定义期望资源节省：

\[
\mathrm{NetSave}_{e,a}
=\hat p_e C_{e,a}^{avoid}
-C_{e,a}^{lookup}
-C_{e,a}^{maint}
-(1-\hat p_e)C_{e,a}^{miss}
\]

其中所有 \(C\) 需统一为可解释的资源成本，例如 GPU-ms、CPU-ms、网络字节成本或按部署单价换算的货币成本。时延收益单独保留为分布 \(\Delta L_{e,a}\)，进入研究点二的 SLO 约束。

在单一容量介质内，可用价值密度排序：

\[
\mathrm{Density}_{e,a}
=\frac{\max(0,\mathrm{NetSave}_{e,a})}
{\mathrm{Size}_{e,a}}
\]

HBM、CPU 内存、Flink 状态和 ANN 索引分别排序和受限，不能用一个 `size_bytes` 把所有介质合并成一个背包。

### 5.5 四类动作

| 状态层 | 基础动作 | 触发条件 |
| --- | --- | --- |
| 会话语义状态 | 保留、冻结、压缩、降级、重建、淘汰派生表示 | 上下文增长、质量门控、摘要重建收益 |
| RAG 知识状态 | 准入、保留、刷新、淘汰 | 热度、source version、freshness、ACL |
| 历史回答状态 | 直接复用、验证后复用、回源推理、淘汰 | per-entry threshold、依赖版本、剩余质量预算 |
| 前缀计算状态 | 亲和保留、可选外部层保留、重算、目录失效 | 复用概率、worker 状态、HBM 压力 |

基础版不强制 vLLM pin 某个 KV block，因为公开 APC 能力主要提供前缀缓存和内部 LRU，而不是 Flink 可控的逐块持久驻留。Flink 的动作含义是调整路由、预算提示和目录生命周期，不虚构后端没有提供的强制 pin API。

### 5.6 摘要与 KV 的联合决策

对会话历史 chunk \(h\)，压缩动作的净效果为：

\[
\mathrm{Gain}_{compress}(h)
=\mathbb{E}[N_{future}]
\cdot \Delta C_{shorter\_prompt}
-C_{summary}
-C_{kv\_rebuild}
\]

且必须满足：

\[
\mathrm{QualityLoss}(h)\le \delta_{k,ctx}
\]

这里的关键变量是未来还会访问多少轮，以及摘要替换后 KV 重建成本。固定“每 N 轮摘要一次”可作为基线；推荐方法由会话复用概率、上下文长度和 KV 重建成本共同触发。

摘要生成后设为 frozen，只有检测到事实冲突或 fidelity 不足时才重建。这样在完成一次 KV 重建后，后续轮次仍可复用“系统提示 + 冻结摘要 + 近期历史”的稳定前缀。

### 5.7 生命周期状态机

```text
CREATED
  ↓ 通过权限/版本/质量门控
ELIGIBLE
  ↓ 准入
RESIDENT ──访问──> RESIDENT
  │ 版本变化/过期/worker generation 变化
  ▼
STALE
  ├─刷新/重建成功──> RESIDENT
  └─无法恢复──────> EVICTED

RESIDENT ──预算收缩/低价值──> EVICTED
EVICTED  ──再次访问────────> CREATED
```

稳定性机制：

- 每轮最多替换当前驻留项的一定比例，比例作为敏感性参数，不预设 25% 为通用最优值；
- 新准入项设置最短驻留时间；
- 扩容阈值和缩容阈值使用滞后区间；
- 版本/ACL/质量失效不受最短驻留保护，立即退出可复用集合。

### 5.8 算法草图

```text
Algorithm UpdateLayerState(window, current_budget):
  1. 收集访问、命中、错误、版本和管理开销观测
  2. 对每个状态项：
       a. 更新冷/暖复用概率及置信信息
       b. 检查 ACL、版本、freshness 和质量资格
       c. 为该层允许的动作估计成本向量与时延收益
  3. 按存储介质分别生成候选集
  4. 在每个候选预算下执行稳定的价值密度选择
  5. 输出 LayerBenefitCurve
  6. 只执行当前 PlannerConfig 对应的生命周期变更
```

若每层有 \(N_c\) 个候选项，排序复杂度为 \(O(N_c\log N_c)\)。Count-Min Sketch 的更新和查询为与表宽相关的常数级操作。实际瓶颈更可能是 embedding/verifier 和状态 I/O，应单独测量。

### 5.9 对照与指标

必选对照：

- LRU；
- LFU/衰减频率；
- 固定 LightGBM 分数；
- LightGBM 与 CMS 固定权重；
- 冷/暖置信融合；
- Oracle 未来访问。

指标：

- 各层命中率，但不单独作为结论；
- 可避免 GPU-ms、远端读取次数、prefill 重算 token；
- P50/P95 管理税；
- 错误复用、陈旧命中和压缩质量；
- 单位容量净收益；
- 缓存 churn 和每窗口替换量；
- benefit curve 的预测误差。

### 5.10 风险与降级

| 风险 | 影响 | 降级方案 |
| --- | --- | --- |
| 四层数据无法统一构造 | 端到端负载不真实 | 机制实验分轨，端到端使用可控合成器 |
| ML 冷启动模型收益不明显 | 点一创新不足 | 保留置信融合和依赖失效，ML 退化为轻量基线 |
| verifier 成本抵消回答复用 | 语义缓存无收益 | 只对高价值长回答启用，短回答回源 |
| 摘要质量难稳定 | 质量预算难满足 | 固定 fidelity，摘要仅作可选动作 |
| 状态规模不足以需要 CMS | 高效数据结构贡献牵强 | 改用精确衰减计数，CMS 只做规模实验 |

## 6. 研究点二：面向异构 SLO 的缓存—算力联合配置

### 6.1 研究目标

研究点二接收研究点一产生的离散收益曲线，在每个规划窗口内选择：

\[
z=(p,b,B_{ctx},B_{rag},B_{resp},B_{kv},
\theta_{resp},f_{ctx})
\]

其中：

- \(p\)：推理算子/worker 并行度；
- \(b\)：batch size；
- \(B_c\)：状态层 \(c\) 的容量预算；
- \(\theta_{resp}\)：回答复用的阈值策略或质量子预算；
- \(f_{ctx}\)：上下文压缩 fidelity 档位。

其目标不是让所有资源都尽量大，而是在满足异构 SLO 时选择成本最低的可行配置。

### 6.2 分支时延模型

单轮时延不能只写成“排队 + 推理”，应按请求实际路径拆分：

\[
T_r =
T_{state}
+T_{ctx}
+T_{rag}
+T_{resp}
+T_{queue}
+T_{prefill}
+T_{decode}
+T_{network}
\]

不同命中路径：

**回答命中：**

\[
T_r^{resp-hit}
=T_{state}+T_{ctx-version}+T_{rag-version}
+T_{ann}+T_{verify}
\]

**回答未命中、KV 命中：**

\[
T_r^{kv-hit}
=T_{state}+T_{ctx}+T_{rag}+T_{ann}
+T_{queue}+T_{prefill-remain}+T_{decode}
\]

**全部未命中：**

\[
T_r^{miss}
=T_{state}+T_{ctx}+T_{rag}+T_{ann}
+T_{queue}+T_{prefill-full}+T_{decode}
\]

缓存使时延分布变成混合分布。预测器需要显式使用命中层级和命中前缀长度，不能把命中率乘一个平均时延就当作尾时延。

### 6.3 预测特征

| 阶段 | 特征 |
| --- | --- |
| 状态访问 | state backend、条目大小、索引分片、是否恢复期 |
| 上下文 | 原始/摘要 token、fidelity、是否需重建摘要 |
| RAG | top-k、chunk 大小、缓存命中、知识服务延迟 |
| 回答验证 | ANN 候选数、相似度、是否调用 verifier |
| 排队 | worker 前序工作量、租户队列、在途 batch |
| prefill | 完整 prompt 长度、KV 命中 token、batch |
| decode | 输出长度区间、生成进度、batch |
| 系统 | `p`、`b`、负载、配置 epoch、worker generation |

队列时延应按前序“预计工作量”而不是请求数量估计。输出长度使用区间或分位数预测，并在生成过程中可选地更新剩余长度。JITServe 可作为请求级在线精化基线；本课题新增的是缓存状态、会话依赖和 Flink 管线阶段。

### 6.4 优化目标

规划窗口 \(t\) 的目标：

\[
\min_z
C_{gpu}(p)
+\sum_{c\in\mathcal{C}}C_c(B_c)
+C_{manage}(z)
+C_{reconfig}(z,z_{t-1})
\]

约束包括：

\[
\Pr(T_{r,k}^{ttft}\le D_k^{ttft})\ge 1-\epsilon_k^{lat}
\]

\[
\Pr(T_{r,k}^{e2e}\le D_k^{e2e})\ge 1-\epsilon_k^{lat}
\]

\[
\delta_{k,ctx}+\delta_{k,rag}+\delta_{k,resp}
\le \delta_k^{quality}
\]

\[
\mathrm{ServiceShare}_k \ge \rho_k^{min}
\quad \text{when tenant }k\text{ is backlogged}
\]

\[
\sum_{e\in\mathcal{E}_c}x_e \cdot size_e
\le B_c
\]

并满足 worker 显存、队列稳定和候选配置合法性。

公平性主要由研究点三逐请求执行。研究点二负责预留最低容量与租户配额，使调度器不是在一个先天不可行的配置上“努力公平”。

### 6.5 求解路径

直接把所有状态项、worker、租户和连续变量放进一个大 MILP 不适合 4 个月范围。推荐分两步：

1. 研究点一将每层压缩为有限个 `LayerBenefitPoint`；
2. 研究点二从每层选择一个 operating point，并枚举有限的 `(p,b)`。

这可复用现有 MCKP/离散搜索基础：

```text
for each (p, b):
  for each feasible combination of layer benefit points:
    estimate per-tenant latency distributions
    check quality, capacity, fairness and queue constraints
    add reconfiguration cost
choose minimum-cost feasible configuration
```

MILP 用于形式化和离线最优对照，不把“使用了求解器”本身作为创新点。

### 6.6 重配置门控

新配置只有在以下条件同时成立时才执行：

\[
\widehat{Cost}(z_{old})
-\widehat{Cost}(z_{new})
> C_{reconfig} + H
\]

其中 \(H\) 为滞后裕量。另设置：

- 最短配置保持时间；
- 扩容和缩容不同阈值；
- 漂移或持续 SLO 违约可绕过普通冷却期；
- 质量/ACL 失效立即生效，不受门控阻挡。

重配置成本至少包含：

- Flink rescale 和状态迁移；
- worker 启停或连接建立；
- KV 冷失效与重新预热；
- batch 打断和短期队列扰动；
- 索引分片重建。

### 6.7 过载处理

当不存在满足全部约束的配置时，Planner 输出：

```text
OverloadSignal {
  infeasible_tenants[],
  predicted_violation,
  bottleneck,
  allowed_degradation_actions[]
}
```

快环只能执行租户预先声明的动作：

- 在质量预算内切换较低 fidelity；
- 排队等待；
- 快速拒绝并返回可重试状态。

不允许为了保时延静默放宽质量阈值，也不能把被拒绝请求从 SLO 分母删除。

### 6.8 算法草图

```text
Algorithm JointPlan(window_stats, previous_config):
  1. 从研究点一取得四层 benefit curves
  2. 生成合法的 (p, b) 与层级 operating points
  3. 对每个候选配置：
       a. 估计各租户命中分支与时延分布
       b. 检查质量、容量、队列稳定和最低份额
       c. 计算资源成本与重配置成本
  4. 若存在可行配置：
       选择成本最低者，并通过门控判断是否切换
     否则：
       输出 OverloadSignal
  5. 广播带 config_epoch 的 PlannerConfig
```

### 6.9 对照与指标

对照：

- 固定配置；
- 只调 `(p,b)`；
- 只调四层缓存预算；
- 缓存和算力顺序独立调节；
- 不计重配置成本；
- 完整联合规划；
- 离线 oracle。

指标：

- GPU-hours 和峰值 GPU 数；
- 各类内存/状态容量；
- 各租户 TTFT/E2E SLO 达成率；
- 质量预算违约率；
- 规划时间；
- 配置切换次数与 churn；
- 重配置期间额外 SLO 违约；
- 预测配置与 oracle 成本差距。

### 6.10 风险与降级

| 风险 | 影响 | 降级方案 |
| --- | --- | --- |
| 配置空间过大 | 在线求解超时 | 固定 fidelity 和质量子预算，只调 `p,b,B_c` |
| 尾时延预测不稳 | 机会约束失真 | 使用保守分位数和安全裕量，报告 coverage |
| 2–4 GPU 难做真实扩缩容 | 结果不充分 | 真实小规模 + trace-driven replay 双轨 |
| 重配置开销无法稳定复现 | 门控结论弱 | 独立 profile 后做离线注入 |
| 四层 benefit curve 误差累积 | 配置不稳 | 定期校准并保留固定配置 fallback |

## 7. 研究点三：缓存感知的多租户公平调度

### 7.1 研究目标

研究点三在研究点二给定资源和预算下，逐请求回答：

1. 当前先服务哪个租户；
2. 请求是否允许复用、排队或拒绝；
3. 未被回答缓存短路时，应送到哪个 worker；
4. 缓存亲和性何时不再值得等待。

调度采用两级结构，避免把公平、SLO 和 worker locality 混成一个难解释的经验分数。

### 7.2 第一级：租户选择

每个调度周期为 backlogged 租户 \(k\) 增加公平 deficit \(G_k\)：

\[
G_k \leftarrow G_k + q\cdot w_k
\]

实际服务请求后，按预计或实测 token/GPU 工作量扣减：

\[
G_k \leftarrow G_k - \mathrm{ServiceCost}(r)
\]

在 deficit 允许的租户中，优先选择归一化剩余 slack 最小者：

\[
\mathrm{Slack}(r)
=D_k^{e2e}-(t_{now}-t_{arrival})
-\widehat T_{remaining}(r)
\]

这形成“公平资格 + SLO 紧迫度”的两阶段判断：

- deficit 防止某租户长期超额占用；
- slack 防止已经接近 deadline 的请求因严格轮转而违约。

服务成本按 token/GPU 工作量而非请求数计量，避免长请求与短请求都扣一次导致虚假公平。

### 7.3 第二级：worker 路由

对候选 worker \(w\)，分别估计：

\[
T_{local}(w)
=Q_w+T_{lookup}+T_{prefill-remain}+T_{decode}
\]

\[
T_{recompute}(w)
=Q_w+T_{prefill-full}+T_{decode}
\]

若未来接入外部 KV 层，再增加：

\[
T_{load}(w)
=Q_w+T_{transfer}+T_{prefill-remain}+T_{decode}
\]

基础版只比较本地命中与异地重算，不假设系统已经具备 KV 迁移能力。

worker 选择：

\[
w^*=\arg\min_w
\widehat T_{finish}(r,w)
\]

但必须满足：

- 不突破租户质量与权限约束；
- 不导致其他 backlogged 租户低于最低服务份额；
- 与当前亲和 worker 的收益差超过迁移滞后阈值；
- worker generation 与目录记录一致。

### 7.4 放弃缓存亲和性的条件

设会话当前亲和 worker 为 \(w_a\)，最优替代 worker 为 \(w_b\)。当满足任一条件时允许放弃亲和：

1. \(\widehat T_{local}(w_a) >
\widehat T_{recompute}(w_b)+H_{route}\)；
2. 等待 \(w_a\) 将使请求预测违反租户时延 SLO；
3. 持续把请求发送到 \(w_a\) 会使其他租户低于最低服务份额；
4. `worker_generation` 不匹配，原 KV 驻留记录不可信；
5. 后端确认目标前缀已经被淘汰。

其中 \(H_{route}\) 防止 worker 在相近预测值之间来回切换。

这一规则比“始终一致性哈希”多出负载和重算成本判断，比“始终最短队列”多出状态复用成本判断。

### 7.5 缓存感知组批

组批可以在公平选择后的请求集合内偏好：

- 同一目标 worker；
- 相同或相近精确前缀；
- 相近预测输出长度；
- 相同 SLO 紧迫区间。

但设置最大组批等待 \(\Delta_{batch}^{max}\)。超过该时间后，不能为了凑缓存友好 batch 继续延迟请求。这样可以测试：

> 牺牲多少局部公平顺序或等待时间，能够换取多少 prefix reuse 和 batch 效率？

DLPM/D²LPM 是必须比较的强基线。本文方法若只在 prefix locality 与公平之间做量子调节，没有跨层状态和 SLO 闭环，就没有足够差异。

### 7.6 扩缩容与故障

稳态下使用 rendezvous hashing 或一致性哈希减少会话映射变化。发生 rescale 或 worker 重启时：

1. 增加 `worker_generation`；
2. 旧 generation 的 KV 目录全部转为 `STALE/UNCERTAIN`；
3. 路由器在后端确认前按重算路径估计时延；
4. 首次请求完成后重新建立驻留记录；
5. 回答、知识和会话语义状态按 Flink checkpoint 恢复，不与 KV 一起丢失。

异步推理请求使用稳定 `request_id`。恢复后如果重试，Sink 或后端适配层必须能识别重复完成；不能将外部调用 exactly-once 归功于 Flink checkpoint。

### 7.7 准入与拒绝

当所有 worker 都预测无法满足 SLO：

1. 检查是否存在 Planner 允许的质量安全降级；
2. 若允许排队且不会破坏最低份额，则排队；
3. 否则快速拒绝，并记录租户、原因和预测违约；
4. 拒绝请求仍进入 offered-load 和 SLO 统计。

该机制的目的不是让报表更好看，而是避免一个必然违约的请求继续占用资源、拖累更多可满足请求。

### 7.8 算法草图

```text
Algorithm ScheduleOne(now, tenant_queues, worker_snapshots, config):
  1. 为 backlogged 租户增加 weighted deficit
  2. 选出 deficit 允许且不低于最低份额的租户集合
  3. 在集合内选择 normalized slack 最小的请求 r
  4. 执行跨层资格门控，确定可用 reuse actions
  5. 若回答缓存安全命中：
       直接返回并扣减实际服务成本
     否则：
       a. 对各 worker 估计 local/recompute 完成时间
       b. 应用亲和放弃和 generation 检查
       c. 若存在可行 worker，选择预计完成时间最小者
       d. 若无可行 worker，执行 config.overload_policy
  6. 更新 deficit、队列、在途工作量和状态观测
```

### 7.9 公平性定义

论文至少同时报告三种公平视角：

- **服务公平**：按 GPU/token 工作量计算的 weighted service share；
- **体验公平**：各租户 slowdown 或 SLO 达成率差距；
- **饥饿保护**：最长等待时间和最低服务份额是否被破坏。

Jain index 可以作为汇总指标，但不能单独证明没有饥饿。高 Jain index 也可能掩盖所有租户都同样差的情况，因此必须与 SLO goodput 和尾时延一起报告。

### 7.10 对照与指标

对照：

- FCFS + 最短队列；
- 一致性哈希 + FCFS；
- WDRR/VTC 类公平调度；
- 最长前缀匹配；
- DLPM/D²LPM-style locality-aware fairness；
- JITServe-style SLO 调度；
- 完整两级调度；
- 知道未来到达与真实时延的 oracle。

指标：

- 各租户 P50/P95/P99 TTFT 和 E2E；
- 整体及分租户 SLO goodput；
- Jain index、slowdown、最长等待；
- prefix/KV 命中与重算 token；
- 负载不均衡度；
- 亲和放弃次数及其正确率；
- 拒绝率、降级率；
- 路由决策开销；
- worker 故障或 rescale 后恢复时间。

### 7.11 风险与降级

| 风险 | 影响 | 降级方案 |
| --- | --- | --- |
| 两级调度参数过多 | 难解释收益来源 | 固定 deficit quantum，只扫描路由滞后 |
| 服务成本预测偏差大 | 公平计数失真 | 完成后用实测成本校正 |
| vLLM 无法确认具体前缀是否仍驻留 | 目录误判 | generation + 超时，保守按重算估计 |
| 与 DLPM 重叠较大 | 创新边界不清 | 强调四层状态、租户 SLO、质量预算和慢环配置输入 |
| 2–4 GPU 难出现明显负载差 | 调度效果弱 | 增加受控过载和 locality 扫描，报告适用区间 |

## 8. 统一形式化与模块接口

### 8.1 符号表

| 符号 | 含义 |
| --- | --- |
| \(k,s,r,w,c,e\) | 租户、会话、请求、worker、状态层、状态项 |
| \(B_c\) | 状态层 \(c\) 的容量预算 |
| \(p,b\) | 推理并行度、batch size |
| \(\hat p_e\) | 状态项未来复用概率 |
| \(\delta_k^{quality}\) | 租户总质量预算 |
| \(D_k^{ttft},D_k^{e2e}\) | 租户时延目标 |
| \(G_k\) | 调度 deficit |
| \(Q_w\) | worker 预计排队工作量 |
| \(z\) | 慢环配置向量 |

### 8.2 总体问题

\[
\min_{z,\pi}
C_{resource}(z)
+C_{manage}(z,\pi)
+C_{reconfig}(z)
\]

其中 \(\pi\) 是快环调度策略。约束为：

\[
\begin{aligned}
&\Pr(T_{r,k}^{ttft}\le D_k^{ttft})\ge 1-\epsilon_k^{lat},\\
&\Pr(T_{r,k}^{e2e}\le D_k^{e2e})\ge 1-\epsilon_k^{lat},\\
&\Pr(\mathrm{unsafe}_k)\le\delta_k^{quality},\\
&\mathrm{ServiceShare}_k\ge\rho_k^{min},\\
&\mathrm{Capacity}(z)\text{ 可行},\\
&\mathrm{Queue}(z,\pi)\text{ 稳定}.
\end{aligned}
\]

论文不必一次求出这个联合问题的全局最优。系统实现采用：

- 研究点一压缩状态决策空间；
- 研究点二求慢环离散配置；
- 研究点三用在线启发式执行。

需要通过 oracle 和消融量化这种分解造成的最优性差距。

## 9. 实验设计

### 9.1 实验原则

四层状态来自不同数据分布，强行把多个公开数据集拼成一个“真实生产 workload”并不严谨。实验采用双轨：

1. **机制验证轨**：每层使用适合该机制的公开数据集，验证复用、质量和成本；
2. **端到端控制轨**：用规则式多会话生成器和已核验 Agent trace 校准到达、会话长度、上下文增长、局部性和租户混合，验证联合控制。

主结论必须来自可重复的受控实验；公开 trace 用于验证外部有效性，不把单一 trace 的分布外推为所有 Agent 负载。

### 9.2 工作负载候选

| 目的 | 候选材料 | 用法 |
| --- | --- | --- |
| 多轮到达与前缀局部性 | 已核验的 vLLM/Mooncake Agent trace 或可获得的公开 Agent trace | 校准会话轮数、轮间隔、前缀增长和到达过程 |
| 长会话语义状态 | LoCoMo、LongMemEval 类长对话数据 | 评估摘要、结构化事实与 supersession |
| RAG 知识缓存 | HotpotQA、MuSiQue 等只读 QA/RAG 数据 | 构造释义 query、知识版本和检索命中 |
| 回答语义缓存 | vCache 的 SemCacheClassification 等公开 benchmark | 评估错误预算、阈值和漂移 |
| 前缀 KV | 端到端 trace 中的完整 prompt | 测量精确 prefix hit、prefill 与重算 |

数据冻结前执行预实验门槛：

- 可合法获得且有稳定版本；
- 能在 2–4 GPU 上完成；
- 有明确的答案或任务质量判定；
- 能记录依赖版本和租户作用域；
- 不依赖本课题明确排除的任意工具执行。

### 9.3 受控变量

端到端生成器至少提供：

| 变量 | 取值设计 |
| --- | --- |
| Offered load | 相对实测饱和吞吐的低、中、高、过载档 |
| 会话长度 | 短、中、长 |
| 上下文增长 | 每轮低、中、高 token 增量 |
| 跨轮间隔 | 短间隔、长尾间隔 |
| 复用局部性 | 低、中、高 Zipf/热点偏斜 |
| 租户混合 | 重点/普通租户不同比例 |
| SLO tightness | 基于隔离运行分位数的松、中、紧倍数 |
| 知识更新 | 无更新、周期更新、突发更新 |
| 漂移 | 热点切换、长度变化、租户比例变化 |
| 故障 | worker 重启、Flink task 恢复、rescale |

SLO 的绝对毫秒值必须在目标模型和硬件 profile 后确定；文档不预设脱离硬件的固定门槛。

### 9.4 基线分组

不是每条实验都运行所有基线。按研究问题选择：

| 组 | 基线 |
| --- | --- |
| 状态管理 | No-cache、LRU、LFU、固定 ML、固定 ML+CMS、vCache-style、Cortex-style、统一冷/暖模型、Oracle |
| 配置优化 | 固定配置、只调 `(p,b)`、只调缓存、顺序调节、联合调节、不计重配、Oracle |
| 调度 | FCFS、最短队列、一致性哈希、WDRR/VTC、LPM、DLPM/D²LPM-style、JITServe-style、完整两级调度 |
| 端到端 | 无缓存、四层独立策略、统一状态但固定资源、统一状态+联合规划、完整闭环 |

“Cortex-style”指按论文核心机制重实现 ANN+验证+TTL 的只读知识缓存，不声称复跑其官方结果；其公开 artifact 边界应在实验报告中说明。

### 9.5 核心实验矩阵

#### E0：阶段 profile

- 测量状态访问、ANN、verifier、知识读取、prefill、decode；
- 扫 prompt 长度、命中前缀长度、batch 和并行度；
- 测量 checkpoint、恢复、rescale 与索引重建；
- 输出研究点一、二使用的成本表。

#### E1：状态价值与生命周期

- 在相同容量下比较替换策略；
- 扫冷启动样本量、热点偏斜和漂移；
- 单独测摘要压缩收益与 KV 重建成本；
- 测版本/ACL 更新后的错误复用。

#### E2：缓存—算力联合配置

- 扫负载和 SLO tightness；
- 比较固定、单侧和联合调节；
- 注入预测误差；
- 测重配置门控对成本和 SLO 的影响。

#### E3：多租户调度

- 扫租户比例、权重和 locality；
- 比较亲和、负载与公平基线；
- 测何时放弃亲和；
- 报告 per-tenant 而非只有全局均值。

#### E4：端到端闭环与消融

- 完整闭环对比四层独立管理；
- 去掉统一状态价值；
- 去掉联合配置；
- 去掉公平约束；
- 去掉亲和；
- 去掉版本/质量门控；
- 去掉冷/暖过渡；
- 去掉重配置稳定机制。

#### E5：鲁棒性

- 热点漂移；
- 知识版本更新；
- worker 故障；
- Flink task 恢复；
- rescale；
- verifier 变慢或不可用；
- 状态后端延迟抖动。

### 9.6 指标

#### 时延与 SLO

- P50/P95/P99 TTFT；
- P50/P95/P99 单轮 E2E；
- 会话主动处理时间；
- 整体和分租户 SLO goodput；
- 违约率、拒绝率、降级率。

#### 质量与正确性

- 回答缓存错误复用率；
- RAG 陈旧命中与越权复用数；
- 摘要事实准确性、当前状态准确性；
- 最终任务/答案质量；
- 总质量预算和分层子预算使用。

#### 资源与缓存

- GPU-hours、峰值 GPU 数；
- HBM、CPU 内存和 Flink state 容量；
- 四层命中率及各自节省量；
- prefill 重算 token；
- 远端知识读取次数；
- ANN/verifier/刷新/checkpoint 管理税。

#### 公平与稳定

- weighted service share；
- Jain index；
- per-tenant slowdown；
- 最长等待；
- 缓存 churn；
- 亲和放弃次数；
- 配置切换次数。

#### 恢复

- checkpoint 大小和耗时；
- failover 恢复时间；
- rescale 状态迁移量；
- 恢复后首次重建时延；
- 重复外部调用和陈旧目录命中数。

### 9.7 统计口径

- 随机策略和合成 trace 使用多个随机种子；
- 报告均值和 95% 置信区间；
- 尾时延实验明确 warm-up、测量窗口和请求总量；
- 同一硬件、模型 revision、vLLM/Flink 版本下比较；
- 单独报告 cold cache、warm cache 和恢复期；
- 不只挑选收益最大的 workload；
- 没有收益的负载区间同样进入结论。

## 10. 相关工作边界

| 工作 | 已解决的问题 | 本课题不能重复主张 | 可保留的新增问题 |
| --- | --- | --- | --- |
| vCache | 答案级语义缓存的逐条目阈值与错误率约束 | “给语义缓存加错误预算” | 跨层容量、漂移状态、Flink 恢复与推理资源联合控制 |
| Cortex（知识缓存） | 只读远端知识结果的 ANN+judge、TTL、淘汰与预取 | “语义知识缓存+验证” | 与会话/回答/KV 状态统一依赖，异构 SLO 和状态语义 |
| IntentKV | 跨轮意图感知的 token-level KV pruning | QueryMemory、dead-slot、固定预算下 token 选择 | 上层动态预算、会话/租户 SLO、Flink 控制状态 |
| vLLM APC | 精确前缀 KV block 复用和内部 LRU | 前缀缓存本身 | 跨 worker 驻留目录、联合配置和亲和放弃 |
| Strata | 引擎内分层 KV I/O、delay hit 和 cache-aware scheduling | GPU-assisted I/O、HiRadixtree、引擎内 batch 机制 | 跨 worker 控制面路由与恢复 |
| JITServe | 不精确信息下的请求级 SLO goodput 调度 | 高分位长度预测、GMAX 本身 | 跨轮状态、缓存预算和 Flink pipeline 控制 |
| Continuum | Agent 工具等待期间的 KV TTL | “工具等待时保留 KV” | 本课题排除工具调用，仅研究会话状态与多租户联合控制 |
| DLPM/D²LPM | prefix locality、公平性和分布式负载均衡 | locality-aware fair scheduling 本身 | 四层状态、质量预算、Agent 会话和慢/快环协同 |
| OpScale | 模型内部 operator-level provisioning/autoscaling | 细粒度算子扩缩容本身 | 外部 Flink 管线的缓存—副本配置与状态成本 |

因此，论文的创新点应使用审慎表述：

1. **待验证的跨层状态框架**：将会话语义、RAG 知识、历史回答和前缀 KV 作为有依赖的派生状态管理，而不是四个独立缓存。
2. **待验证的联合配置方法**：在租户时延、质量与公平约束下，联合选择四层预算和推理配置。
3. **待验证的会话级调度方法**：利用跨层状态价值、租户 deficit 和预计完成时间决定亲和保持或放弃。

在完成系统性文献检索前，不使用“首个”“首次”等排他性表述。

## 11. 可行性与裁剪

### 11.1 最小可行版本

最小版本仍保留四层状态，但降低每层算法复杂度：

- 会话语义状态：固定 chunk + 单一摘要 fidelity；
- RAG：版本/ACL 门控 + LRU/LFU；
- 回答：vCache-style 或静态阈值二选一；
- KV：vLLM APC + Flink 驻留目录，不做迁移；
- 状态价值：精确衰减计数，不强制 CMS；
- 规划：离散枚举/MCKP；
- 调度：WDRR + local/recompute 完成时间比较；
- 后端：只做 vLLM；
- 恢复：验证元数据 checkpoint 和 KV 重算路径。

这个版本已经能够回答三个核心问题，不依赖引擎改造。

### 11.2 推荐完整版本

在最小版本上增加：

- 冷启动 ML 与暖态统计的置信融合；
- 摘要与 KV 重建成本联合触发；
- 回答、知识和上下文的固定质量子预算；
- 漂移检测触发重规划；
- 亲和放弃滞后；
- worker generation 校验；
- 故障和 rescale 实验；
- 一组公开真实 trace 的外部验证。

### 11.3 高风险增强项

以下内容不应同时承诺：

- 动态分配跨层质量错误预算；
- 接入 Mooncake/LMCache 等外部 KV 池并做迁移/预热；
- SGLang 后端泛化；
- 学习型强化调度；
- IntentKV 式引擎内 token pruning；
- 多模型、多硬件混合调度。

最多选择其中一项作为增强实验。

### 11.4 16 周建议安排

| 周次 | 内容 | 退出条件 |
| --- | --- | --- |
| W1–2 | 数据冻结、阶段 profile、统一状态 schema | 成本表和最小 trace 可跑 |
| W3–6 | 研究点一：四层基础策略、依赖失效、benefit curve | RQ1 核心实验完成 |
| W7–9 | 研究点二：离散联合规划、重配置门控 | RQ2 核心实验完成 |
| W10–12 | 研究点三：两级调度、亲和放弃 | RQ3 核心实验完成 |
| W13–14 | 端到端、消融、真实 trace 验证 | 闭环结果完整 |
| W15 | 故障、rescale、漂移与补实验 | RQ4 完成 |
| W16 | 论文与答辩材料 | 图表、日志、配置归档 |

若 W2 无法稳定构造四层端到端 workload，应立即采用“机制分轨 + 受控端到端生成器”，不要继续等待一个不存在的完美真实数据集。

## 12. 预期贡献、失败条件与导师决策

### 12.1 预期贡献

若实验支持假设，可形成三项贡献：

1. 提出一套面向流式 Agent 推理的跨层派生状态模型，显式表达四类状态的依赖、质量风险、版本和恢复语义；
2. 设计质量与公平约束下的缓存—算力联合配置方法，用离散收益曲线压缩在线优化空间；
3. 设计会话级两级调度机制，给出缓存亲和性放弃条件，并量化其与尾时延、公平和资源成本的关系。

### 12.2 研究仍然成立的负面结果

系统论文不应把成功预设为“所有场景都显著加速”。以下结果同样有研究价值：

- 语义 verifier 在短回答上比回源推理更贵；
- decode-bound 负载下 KV 亲和收益接近零；
- 高更新频率知识使 RAG 缓存失去净收益；
- 严格公平约束下 locality 收益明显下降；
- 摘要频繁更新导致 KV 重建成本超过上下文缩短收益；
- 小规模状态下 CMS 没有必要；
- 联合优化只在中高负载下优于固定配置。

论文应给出这些机制的适用区间，而不是只报告最有利工作负载。

### 12.3 建议导师拍板的事项

| 事项 | 推荐选择 | 影响 |
| --- | --- | --- |
| 题目宽度 | 使用题目一或题目二 | 决定论文是否突出调度或系统协同 |
| 三点贡献权重 | 状态 35%、规划 30%、调度 35% | 避免点一吞掉全部周期 |
| 质量预算 | 基础版固定分层子预算 | 动态分配列为增强项 |
| 后端泛化 | vLLM 必做，SGLang 不承诺 | 保证 4 个月可完成 |
| 外部 KV 池 | 不列入必做 | 避免数据面工程失控 |
| 理论要求 | 形式化约束 + 可审计的公平份额机制；若无法证明理论界，则只报告经验保证 | 与系统实现工作量匹配 |

## 14. 本轮细化后的最终判断

当前选题具备形成硕士毕业论文的条件，但应避免两种走法：

- 把四类缓存分别做成四套松散算法；
- 把已有的 prefix-aware fair scheduling 或语义缓存阈值换一层 Flink 包装后当作主要创新。

更稳妥的论文结构是：

> 用四层派生状态模型统一描述“可以复用什么”，用预算—收益曲线把状态管理结果交给缓存—算力联合规划，再由会话级两级调度器在异构 SLO 和公平约束下执行亲和保持或放弃。

这条主线同时保留了原项目的 Flink 状态管理、时延预测、缓存替换和推理参数调优基础，又把导师提出的三个聚焦点具体化为可实现模块、可形式化问题和可拆分实验。最需要在预实验阶段验证的不是模型效果，而是三个决定论文成败的系统事实：

1. 四类状态各自的管理税是否小于可避免成本；
2. 缓存预算变化是否足以改变最优推理配置；
3. 在 2–4 GPU 下，缓存亲和、负载均衡和租户公平的冲突是否能被稳定复现。

只要这三项中至少两项得到清晰的正向或边界性结果，论文就能形成完整证据链；若三项均不显著，应及时收缩为“跨层状态生命周期管理 + 质量约束”主线，而不是继续扩大系统范围。
