# 四类缓存对象的候选检索机制调研与设计

调研日期：2026-11-16。对应初稿的 `resp`、`rag`、`act`、`plan` 对象，以及“候选检索 → 有效性判断 → 动作价值比较”的结构。

## 1. 研究问题与结论

本调研回答三个问题：一次请求或 Agent 中间步骤出现时，用什么键找到可能复用的条目？怎样在候选数量、召回率和查询开销之间取得平衡？已有方法需要怎样适配到四种对象？范围聚焦在线候选检索；有效性和价值模型沿用第一章的设计。

建议采用**统一的检索接口、按对象定制索引**：

| 对象 | 查找时机与输入 | 缓存及索引键 | 候选检索 |
|---|---|---|---|
| `resp` | 回答生成前：当前问题与必要会话上下文 | 完整答案条目；原请求、结构字段、请求向量 | 静态层优先；精确键＋语义及关键词召回，轻量精排 |
| `rag` | 需要证据时：当前问题或拆出的信息需求 | 证据集合；块级内容、来源、版本及集合归属索引 | 从有效块的倒排和向量索引召回，按当前需求组织证据并补检 |
| `act` | Agent 发起只读工具调用时：工具名和已绑定参数 | 工具调用结果；规范化调用签名 | 工具、规范化参数和配置的哈希精确查找；版本及外部状态复核 |
| `plan` | 规划或到达子目标时：当前目标、阶段和状态 | 参数化模板或计划片段；任务、阶段、槽位及步骤结构 | 阶段/类型筛选＋关键词与语义召回，再按前置条件和结构精排 |

`resp` 面对的是“旧答案能否服务新问题”，`rag` 面对的是“旧证据能否支持新问题”，`act` 面对的是“是否为同一次语义的工具调用”，`plan` 面对的是“旧计划能否绑定当前任务并执行”。因此每种对象应当有自己的候选相关性定义。

检索器返回条目 ID、候选分数和必要元数据；后续再做权限、版本、时效、答案风险、证据充分性或可执行性检查，最后选择 `reuse`、`verify_then_reuse` 或 `recompute`。候选排序可使用历史收益作为次级特征，但是否复用由原有价值模型决定。

## 2. 共用检索框架

```text
请求或 Agent 中间步骤
        ↓
提取可信身份、对象类型与可用的结构化字段
        ↓
按租户/权限域及已知确定条件限定候选范围
        ↓
对象专属索引：精确键 / 倒排 / 向量 / 层级索引
        ↓
多路候选合并、去重、轻量重排，保留有限个候选
        ↓
权威权限、依赖版本和对象专属有效性检查
        ↓
比较复用、验证及重算的预计成本 → 执行并反馈
```

**过滤与召回。** 租户和可访问范围由认证与授权系统提供；对可确定、稳定且适合索引的字段做预过滤。必须兼容的模型、工具版本可过滤；一个尚未知晓的来源最新版本，应在读取时向版本目录检查，不能假定索引元数据自动代表实时状态。权限标签无法完整表达复杂 ACL 时，用标签缩小范围，并在访问缓存内容前进行权威权限检查。语义向量和由模型提取的字段均不能代替权限判断。

候选空间很小时，在过滤结果上精确算相似度；规模较大时使用支持条件过滤的 ANN，或先按可信租户/权限域划分索引再搜索。ACORN [4] 研究向量搜索与结构化谓词的联合执行，可作为过滤式 ANN 的实现依据。单纯对全局 ANN 取很小的 top-k 再过滤，可能因为候选被无权限条目占满而漏掉可用结果；扩大候选数或选择过滤式检索可缓解漏召回，仍需测量。

**结构化字段的置信度。** 时间、实体和用户意图可由规则或轻量模型提取；缺失或低置信度字段记为未知，不以猜测值执行硬过滤。对明确且确实影响答案语义的数值、时间和实体可作确定性筛选。自动抽取适合作为召回线索，最终仍由对象级判断核对。对于多轮指代，优先复用上游已解析的会话状态；提取失败时用更完整上下文召回，必要时回源。

**工程落地。** 一个逻辑检索接口可对接哈希表、倒排索引和向量库，无需第一版就实现自研 ANN 图。新条目的写入、索引建立、过期标记和淘汰应共享稳定 ID；依赖变更由来源→条目反向索引标记失效，读取时复核版本，异步清理旧索引。索引失效或部分不可用时走对应原始操作。内容和引用共享时，内容块可去重，权限与归属按引用分别记录。

## 3. `resp`：面向回答等价性的分层召回

### 3.1 文献依据

vCache [1] 用语义相似性识别可能复用的历史回答，并结合在线验证控制错误风险；MVR-cache [2] 通过学习式 prompt 分段和多向量 MaxSim 提升细粒度匹配。SmartCache [3] 将对话上下文纳入语义缓存组织。三者共同提示：问题文本相近只是线索，局部条件和会话背景对回答是否适用很关键。

### 3.2 建议的条目与索引

一个条目包含：原始请求、必要上下文摘要或指代解析结果、完整回答、轻量签名、请求向量、来源依赖、生成配置、权限域、时间戳及条目 ID。签名可包括意图、主题实体、时间范围、关键数值、输出格式和语言；权限及版本由可信元数据另行提供。对于可能一问多答或同键多版本的情况，同一键指向候选列表。

建议采用三路召回：

1. **精确键**：对规范化请求和相关上下文做哈希查找，用于高频重复请求。
2. **关键词倒排**：对实体、专业术语、编号及时间表达建立索引，减少重要字词被稠密向量忽略的问题。
3. **语义 ANN**：对请求及必要上下文编码，在可访问候选范围内取 top-k，召回不同表述。

候选去重后，以语义得分、意图/实体/时间等字段一致性做轻量重排。初版可用固定字段权重，参数在验证集确定；存在明确冲突的候选进入拒绝或验证流程。复杂请求可选用 MVR-cache 风格的分段多向量重排，只对小候选集计算，比较收益与额外成本。

沿用初稿的**静态层优先**：先检索静态层，满足其在线门槛时直接使用；否则检索动态层，必要时生成。灰区静态候选按 1.3 的预算进入后台验证。候选依然要经过来源依赖、版本、权限、时效和回答可接受性检查；多轮问题需检查指代所指的对象。

例：缓存“2025 年 A 产品退款期限是多少？”的回答；新请求“去年的 A 产品多久能退款？”在时间解析确认为 2025 年、权限和文档版本匹配后，可进入复用判断。“2026 年 A 产品多久能退款？”即使文本很相似，也应按时间条件区分。

### 3.3 本方案相对原文的变化

vCache 的风险控制服务于候选回答是否可复用；这里额外增加静态/动态层的候选检索、可信权限和依赖过滤及对象级价值决策。MVR-cache 的学习式分段需要训练；本方案先采用轻量字段和单向量作为基线，再在有限候选上测试多向量精排。两者的理论保证依赖各自算法及假设，改变候选产生、校准与决策后，需要重新分析，不能直接沿用保证。

## 4. `rag`：集合存储、块级召回和缺口补检

### 4.1 文献依据与对象边界

Cortex [5] 面向远程数据访问缓存知识，利用语义索引检索相近请求并判断缓存知识的适用性。RAGCache [6] 的知识树主要组织已检索文档的中间状态和 KV 前缀，其性能目标涉及生成阶段的计算复用；它可以启发依赖组织，但不能作为“已经解决证据内容召回”的证据。

本章以**一次检索产生的证据集合**为缓存管理单位；为提高复用粒度，同时对集合中的块建立辅助索引。一个块记录内容、来源、版本、获取时间、权限、块 ID 和所属集合 ID。共享块可由多个集合引用，版本和权限按来源及引用关系维护。由此既保持初稿的集合生命周期统计，又支持仅复用其中仍然有效的部分。

### 4.2 查询路径

1. 获取当前问题；在多信息需求问题中，用固定规则或轻量模型拆成少量子需求。拆分结果是召回线索，原问题始终保留。
2. 在用户可访问的块及集合范围内，按问题/子需求分别运行关键词倒排与向量召回；并行可选查找历史相似查询所关联的证据集合。合并并按块 ID 去重。
3. 检查块对应的来源版本、时效和权限；按相关性、子需求覆盖及来源去重/多样性组成候选证据。不得把来源数量当成充分性的证明。
4. 对缺失的信息需求执行后端补检；若覆盖无法确认或补检没有成本优势，则按初稿执行完整检索。使用最终证据生成新回答，并将采用的证据及集合归属回写统计。

例：问题需要“退款期限”和“申请入口”，缓存集合中的期限政策块仍有效，但入口块来自已更新来源。召回期限块，丢弃失效入口块并补检入口；仅当最终证据覆盖问题时生成回答。

### 4.3 适配与优化

相对 Cortex 的相似请求→缓存知识思路，本方案为一个集合建立块级辅助入口，以来源版本检查和缺口补检实现部分复用，并用集合归属支持初稿的长期价值统计。可同时保留“相似查询→证据集合”的快捷路径，在检索实验中比较集合级与块级入口。结果块被访问不等于已经用于回答，应区分“召回”“通过验证”和“实际采用”三种事件。

## 5. `act`：调用签名精确索引与状态校验

### 5.1 文献依据

TVCACHE [7] 研究 Agent 后训练中的工具值缓存，Cortex [5] 研究远程数据访问与知识缓存。它们支持复用工具或远程访问结果的方向。本方案的在线工具可能读取动态外部状态，复用时需接入数据版本或业务时效判断；这一点是针对当前场景的扩展。

### 5.2 检索流程

只为允许缓存的**只读**调用建立候选。键可以表示为：

```text
key = hash(租户/权限域, 工具 ID, 工具/算法版本,
           规范化参数, 影响输出的配置与语义上下文)
```

规范化只做工具契约明确允许的等价变换，例如参数顺序、显式默认值、单位换算和时区统一；数组顺序、精度、区域、分页和排序等影响输出的参数必须保留。键命中后核对原始规范化字段，读取权威权限信息及数据版本/状态；稳定纯计算可按工具版本和完整输入复用，动态数据依业务要求检查版本或有效期。

例：`get_order(order_id=123)` 与相同工具、同一权限域、同一规范化参数的历史调用可定位到同一候选；订单来源版本已更新时重新调用。`order_id=124` 与 `123` 虽然语义接近，仍是不同键。

如工具定义了可证明的范围包含关系，辅助的范围或参数字段索引可找到候选，再由工具专属规则提取结果并验证；首版优先采用精确键。带副作用操作不进入普通结果复用；业务重试按操作 ID 和外部执行记录处理。

### 5.3 适配与优化

精确签名＋版本校验是针对在线只读工具提出的工程设计，并非声称 TVCACHE 实现了在线动态数据一致性。把昂贵的外部状态检查与重新调用的预计成本比较：若验证后预期总成本不低于重调，可直接调用。检查失败的代价和后续回源开销按实际路径计入。

## 6. `plan`：阶段筛选、目标检索和模板适配

### 6.1 文献依据

APC [8] 从已有执行中形成可复用计划，使用关键词检索并由轻量模型适配。MetaFlowLLM [9] 从经验形成层次化的 MetaFlow，支持检索相关经验。这里借鉴关键词和层级组织，面向在线 Agent 增加计划片段、槽位及前置条件信息。

### 6.2 索引与路径

每个条目保存：任务目标描述、任务类型、适用阶段、参数槽位及类型、前置条件、步骤/依赖、所需工具、权限约束、版本和历史适配结果。将任务类型→子目标/阶段组织为层级索引；同一模板允许出现在多个合适的检索入口，使用模板 ID 去重。

当前目标到达后，先用已知阶段、工具类型和明确不兼容条件缩小搜索范围；阶段未知时保留更广候选，避免提取错误导致漏召回。关键词索引按 APC 的思路提供快速候选，并行用目标描述向量召回表述不同的相似任务。对合并的候选按目标一致性、阶段、槽位类型及必要步骤/依赖进行重排。随后绑定当前参数，检查前置条件和工具授权，必要时验证或局部修复；不通过则重新规划。

例：针对“查询订单并处理退款”，可召回“查询订单→检查退款资格→告知处理渠道”的模板。需要当前订单号、可用工具和退款政策版本；若订单已退款或工具不存在，模板必须经适配或重新规划。模板检索不执行有副作用的步骤。

### 6.3 适配与优化

APC 的关键词入口保留为基线；本方案叠加阶段/前置条件索引、语义补充召回、参数槽位绑定及价值模型。相对 MetaFlowLLM 的层次经验组织，本方案将可检索单位设计为可参数化的计划模板或片段，并对在线工具和状态进行校验。这些组合是待实验验证的设计，不预设效果优于原方法。

## 7. 检索成本与动作价值的衔接

端到端时间按实际时间线记录：

```text
T_prepare：解析、规范化、编码
T_search：元数据过滤、哈希/倒排/ANN 查询与候选合并
T_rank：候选精排
T_check：权限、版本、风险/覆盖/可执行性检查
T_adapt：模板绑定、修复或证据补检
T_fallback：验证失败后的生成、检索、工具调用或规划
```

一次请求的实际耗时为实际执行各阶段之和；并行阶段按墙钟时间测量，不能简单把各线程耗时相加。另记录 CPU/GPU 时间、模型 token 和索引内存/维护资源。对是否启动缓存检索的上游决策，比较含 `T_prepare + T_search + T_rank` 的完整路径与直接重算；当候选已经检索出来，比较后续 `reuse / verify_then_reuse / recompute` 时，上述共同沉没成本不重复加入各动作。失败后的已发生检查、适配和回退成本需完整记录。

可选优化是先用极低成本的精确键或可用性统计预测能否命中，再决定是否发起向量搜索。初版勿强制每次调用生成式 LLM 抽取签名：复用可信 Agent 上下文与规则、轻量编码器，并实测提取准确率和延迟。对象多次被调用时，每次检索都应归因到相应的 Agent 步骤。

## 8. 评估设计

建议在固定数据流、缓存容量、权限和版本序列下，先固定检索器比较 1.2/1.3 的价值与生命周期策略；另设独立检索实验，控制同样的缓存内容、有效性判断和预算，比较不同候选索引。这样可区分检索器与缓存策略的收益。

**候选质量。** 抽样请求构建与在线索引独立的参考候选池：在小规模快照上遍历所有缓存项，人工或可信标注器结合真实权限、版本、答案适用性、证据支持/覆盖、工具语义、计划可执行性给出对象专属标签；大规模可将多路高召回检索、随机抽样和人工复核组成池，并报告池不完整。分别计算：

- `Hit@k`：参考池中存在至少一个合格候选时，top-k 找到至少一个的请求比例。对于最终只需一个答案/计划的场景尤其直观。
- `Recall@k`：top-k 召回的合格条目数除以参考池中合格条目总数；`rag` 还需报告证据需求覆盖和补检后覆盖。没有合格候选的请求单列，避免分母歧义。
- ANN 索引召回率：相同过滤条件下，相对精确向量 top-k 的重合比例。这个指标衡量 ANN 近似损失，不等于语义可复用召回率。
- 权限越界读取、过期复用和错误复用次数；检索 p50/p95、端到端 p50/p95、吞吐、索引内存、建索引及增删改开销、embedding/判官开销。

**对照和消融。** `resp` 比较精确键、单向量 ANN、混合检索及可选多向量精排；`rag` 比较查询→集合、块级混合召回及块级召回＋补检；`act` 比较规范化精确键与无缓存调用，必要时评估经工具契约授权的范围复用；`plan` 比较 APC 式关键词入口、关键词＋语义和再加结构重排。按时间划分训练/参数选择/测试集，测试不同缓存规模、热点、更新率、过滤选择率和 k 值。对照使用相同有效性门与资源预算；只评估召回路径时固定快照，以免索引内容变化干扰结果。

1. Schroeder et al. **vCache: Verified Semantic Prompt Caching.** ICLR 2026. [会议页面](https://iclr.cc/virtual/2026/poster/10006471)；[论文](https://openreview.net/pdf?id=zF0A0xw3HZ)。用于回答相似候选的验证与风险控制。
2. Noshad, Zheng, Wu. **MVR-cache: Optimizing Semantic Caching via Multi-Vector Retrieval and Learned Prompt Segmentation.** ICML 2026, PMLR 306: 93883–93907. [论文页面](https://proceedings.mlr.press/v306/noshad26a.html)。用于细粒度 prompt 匹配与候选精排。
3. **SmartCache.** NeurIPS 2025. [会议论文](https://proceedings.neurips.cc/paper_files/paper/2025/hash/fb74b63d225f846e6032bf3e3ab0f4ec-Abstract-Conference.html)。用于参考多轮对话上下文与语义缓存组织。
4. Patel et al. **ACORN: Performant and Predicate-Agnostic Search Over Vector Embeddings and Structured Data.** SIGMOD 2024. [DOI](https://doi.org/10.1145/3654923)。用于带结构化过滤条件的 ANN。
5. Ruan et al. **Cortex: Achieving Low-Latency, Cost-Efficient Remote Data Access for LLM via Semantic-Aware Knowledge Caching.** NSDI 2026. [论文](https://www.usenix.org/system/files/nsdi26-ruan-cortex.pdf)。用于远程知识缓存和语义候选检索。
6. Jin et al. **RAGCache: Efficient Knowledge Caching for Retrieval-Augmented Generation.** ACM Transactions on Computer Systems, 44(1), 2026. [DOI](https://doi.org/10.1145/3768628)。用于参考知识树及 KV 前缀依赖。
7. Kumar et al. **TVCACHE: A Tool-Value Cache for Post-Training LLM Agents.** ICML 2026, PMLR 306: 61539–61558. [论文页面](https://proceedings.mlr.press/v306/kumar26d.html)。用于参考工具调用结果复用。
8. Zhang, Wornow, Olukotun. **Agentic Plan Caching: Test-Time Memory for Fast and Cost-Efficient LLM Agents.** NeurIPS 2025. [会议页面](https://proceedings.neurips.cc/paper_files/paper/2025/hash/9549f7d06700f0966d5f938f1d11022a-Abstract-Conference.html)。用于计划模板检索与适配。
9. Fan et al. **Generalizing Experience for Language Agents with Hierarchical MetaFlows.** NeurIPS 2025. [会议页面](https://proceedings.neurips.cc/paper_files/paper/2025/hash/5c882988ce5fac487974ee4f415b96a9-Abstract-Conference.html)。用于参考层次化经验检索。

检索范围为本章已有参考文献以及近期语义缓存、过滤 ANN、Agent 计划/工具复用相关工作；以会议、期刊页面和论文摘要/正文中的可核对信息为依据，属于针对方案设计的定向调研。
