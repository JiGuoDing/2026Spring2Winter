# 第一章异质缓存设计方案 v4 审阅意见

评审日期：2026-11-27。评审对象：[方案设计 v4](/Q:/workspace/2026Spring2Winter/MasterGraduationProject/方案设计_v4_gemini.md)，对照[上一轮 v3 复审](/Q:/workspace/2026Spring2Winter/MasterGraduationProject/第一章_设计方案_v3复审_交给Gemini迭代.md)和[第一章现稿](/Q:/workspace/2026Spring2Winter/MasterGraduationProject/第一章_改后初稿_第二版.md)。下文行号均指 v4 文档的物理行号。P0 为会改变准入结果或破坏版本语义的问题；P1 为实验前需要补齐的机制定义。

## 1. 总体判断与建议保留的范围

**有条件通过架构评审，可据此启动小规模原型。暂不据 v4 改定 §1.2–§1.4。** 这一轮确实重写了三段伪代码。冻结当前已知版本进行估值、先纳入候选再逐轮选择淘汰项、把替换规划与原子提交分开，以及将主动维护与修复路线拆成两组对照，都是实质进步。剩余问题集中在三个地方：**准入比较的基准不一致、下游评分的快照没有绑定、更新屏障的解除规则不完整。**

**建议保留“四类固定分池 + 路径联动”。** v4 第 9–14、22 行将容量选择收敛为：给定四个活跃逻辑预算，各池只做类内准入与淘汰；`resp` 短路改变下游需求，其他池仍参与整条请求路径的估值。分池省去了不同逻辑容量单位之间的换算；时间净节省仍统一用毫秒表示。正文应写清**预算向量预先给定，本文不优化池间配额**，不应再用“跨类型容量分配”概括算法。§1.1 的两个研究问题可以保留，研究范围、§1.3.1 的容量表述和 C2 对照条件要与四池设定对齐。

## 2. P0：原型需优先修正的三项问题

### P0-1｜准入收益应与“不接纳候选”的同条件状态比较

**位置：**Alg.2 第 144–179 行；Alg.3 第 237–249 行。

**问题与理由。** Alg.2 先清理 `E_dead`，在清理后的集合里规划；最终却用清理前的原集合比较。其拒绝分支也会尝试清理 `E_dead`，所以当前差值可能把清理收益记给候选。取一个允许失效条目仍产生探测开销的构造例：

| 状态 | 单请求耗时 |
| --- | ---: |
| 原集合，尚未清理 | 105 ms |
| 只清理旧条目，不接纳候选 | 100 ms |
| 清理旧条目并接纳候选 | 102 ms |

现算法看到 `105 − 102 = 3 ms` 会接纳；但清理本来就能做，候选实际贡献是 `100 − 102 = −2 ms`，应拒绝。若实现保证失效条目完全不参与探测和排序，这个清理反例不会触发，但 Alg.3 的另一个问题仍在：它在规划结束后把旧条目追加到 `remove`。若规划没有把旧条目当作必移除项，可能先为腾出容量淘汰一个仍有价值的条目，最终实际提交的集合和打分时的集合也不同。

**修改建议。** 让 `PlanReplacement` 返回两个明确状态：

- `M_no`：不接纳候选时的实际可达状态。若已确认失效的条目无论准入结果如何都要清理，就将其从基准中移除。若旧条目只在成功替换时才移除，则保留在 `M_no` 中。
- `M_yes`：接纳候选时的实际状态。先纳入新候选并处理所有必移除项，再对仍需腾出的空间做候选感知淘汰。修复写回应传入旧条目的 ID 和代次，不在评分后另加删除项。
- 使用 `EvalDelta(M_yes, M_no)` 判断正收益，用 `M_yes` 对应的操作集提交；原子校验失效时重算或放弃。若清理可单独提交，明确它是独立操作，不把它记成准入成功。

**验收。** 105／100／102 ms 的用例应只清理、拒绝候选；原 18→19 直接替代用例仍应通过；容量已被待替换的旧条目释放时，新候选不得再误淘汰有效邻居。

### P0-2｜把残余需求绑定到快照，先实现全量的 `EvalDelta`

**位置：**§2.2–2.3 第 37–62 行；Alg.2 第 134–175 行；T-1、T-3。

**问题与理由。** 文中定义了单请求 `EvalPath`，却没有展开 `EvalDelta` 怎样选样本、怎样配对和如何处理未执行分支。`Q_rep_k` 从外部传入，未规定它来自哪个缓存快照。例：规划 `rag` 准入时，某批请求仍会进入检索；规划完成、提交前，`resp` 池新增回答，把这批请求全部短路。此时 `rag` 池修订号未必变化，原计划仍可提交，却已不代表当前需求。这是**估值过时**，不等于缓存超预算或回答失效。此外，“实际到达阶段”受复用门控和整条执行路径影响，不能直接把历史到达过该阶段的请求名单当成固定残余集。

**修改建议。** 首版用完整代表集作为参照，残余集先作为路径结果或诊断指标：

1. **冻结共同输入。** 一次成对比较使用同一批 `Q_rep`、权重 `w_q(H)`、其余三个池的状态、已知版本和屏障、反馈、策略及成本参数。修改目标池集合后，在对应临时视图重跑召回、校验、短路和回退。前后复用相同决策位置的随机抽样，避免分支跳过后随机序列错位。评估过程不向在线状态写入。
2. **约定差值符号。** `EvalDelta(after, before)` 返回各请求「变更前前台耗时 − 变更后前台耗时」的加权期望，正数表示节省。按同一约定，`EvalDelta(M_work, M_work − {j})` 就是移除 `j` 的损失。窗口 `H` 只用于预测请求量，未来版本的有效概率不混入冻结版本的主评分。
3. **约定提交时的评分新鲜度。** 若首版要求结果与提交时状态一致，校验会改变评分的池修订号或统一快照修订号；估值输入可在一个回放批次内冻结。若为吞吐允许依赖较旧的评分，明确是近似调度，记录版本差、准入分歧和重算成本。无论选哪一种，版本、代次和容量的安全约束都必须独立满足。
4. **明确成本来源。** 20→35 ms 与 20→100 ms 需要真实的备选路径信息和相应阶段成本，不能从单条 20 ms 命中日志反推。列出关键阶段采用配对标定、实际重放还是估计；缺数按 `UNRESOLVABLE` 或明确的估计规则处理。全量只表示在当前求值模型下不漏求和，不代表真机时延已验证。要剪枝时，只有在能证明集外请求的成对时差为零的前提下才使用完备残余集。

**计账边界。** 各池比较都包含其他池参与的整条路径。池内边际用于决策，不是可相加的独立贡献；C4 的系统总收益按每个请求的整条实际路径只计一次。

**验收。** 测试替换暴露中间阶段、缺数回退及 `resp` 在规划和提交之间改变三种情形。严格模式中第三种应触发重算；近似模式应能记录使用了哪版需求估计，而非将其标为当前精确得分。

### P0-3｜定义屏障从发布到解除的状态转换

**位置：**§2.1–2.2 第 30–52 行；Alg.1 第 93–123 行；Alg.3 第 192–216、233–249 行。

**问题与理由。** “新版本和屏障同时发布”的方向正确，但 `scope` 在发布前就计算。若窄查返回的是已经枚举好的条目列表，计算和发布之间新写入的条目可能漏筛。恢复、标记和清理的调用参数也不一致：例如 `MARK_INVALID` 与 `DROP_INVALID` 只传条目代次。**条目代次识别的是哪份缓存内容，不能区分哪次更新有权结束待判定。** 同一份内容可能连续被两次更新标记；只比较 `entry_gen` 会让早一轮任务错误解除新一轮屏障，或误处置仍需重检的条目。反过来，若恢复冲突后直接退出又无人接管，条目可能一直暂停。

**修改建议。** 用两种标识分别追踪「哪份内容」和「哪次更新待处理」，例如 `(entry_id, entry_gen, update_epoch)`。把以下规则写进伪代码，而不只写在接口注释里：

| 环节 | 需要明确的规则 |
| --- | --- |
| 发布 | 原子发布新版本与作用域屏障。目标列表若需枚举，要从与发布一致的状态取得，或先发布域级屏障再枚举；若无法证明不影响其他候选的排名，保守查域或全池。明确作用域内新写入条目何时可凭新版证据通过、否则如何进入筛查。 |
| 在线使用 | `ReCheckBeforeUse` 在同一份当前发布状态上看版本、屏障及候选代次等硬条件，明确判定时点。若允许已通过临用判定的请求在随后有更新时继续完成，写清这个边界；不要写成“响应送达时必为外部最新”。下游阶段也沿用同一有效性规则。 |
| 恢复、失效、清理、写回 | 业务处置必须针对相同条目代次和当前适用的更新代次，必要时验证所依据的池修订号。旧任务不应清掉新屏障。重检后恢复与依赖元数据更新同一提交；命中冲突后明确由新任务接管还是重试。说明最后一条待判定记录结束后如何关闭域屏障。 |
| 提交与失败 | 统一 `AtomicCommit` 的必填参数、返回码与分支处理。目前接口列 `CONFLICT/STALE/OVER_BUDGET`，调用却判断 `REV_CONFLICT/STALE_VERSION`，并有调用省略校验字段。明确每类冲突是重读再规划、重新重检还是放弃；版本过期的修复结果不能以普通重规划绕过核验。任何失败都不得执行拟议淘汰。 |

**验收。** 至少补三种交错：① 算出窄范围后、发布前插入可能受影响条目，不能漏筛；② 更新 `v2` 已发布，`v1` 的任务随后完成，即使条目代次没变也不能解除 `v2` 屏障；③ 同 key 已写入新代次，旧任务的恢复、失效或清理不能改变新条目。仍需保留“已知失效后复用”和“通知前过期误用”的区别。

## 3. P1：实验前补齐的机制定义

### P1-1｜主动维护应受可执行的预算约束，按需对照要按事件回放

**位置：**Alg.3 第 214–234 行；T-6；§5.2 的 C3。

**问题与理由。** `bg_budget.exhausted()` 只检查是否已耗尽，没有占用和结算步骤；并发任务可能同时看到有余额，或者局部改写失败后再发起未纳入预算的完整重生成。T-6 也把“第一条请求后可以再准入”写得近似等同于“第二条请求一定命中”。第一条若仍在生成、异步准入还未提交或候选被拒，第二条都可能不命中。

**修改建议。** 热度门槛继续用独立验证流标定；预算明确单位、窗口、预留和结算。首版可用每窗模型调用及 Token 限额，按允许的调用次数和 Token 上限，在启动前预留改写、核验与回退额度，完成后据实结算；额度不足时停在安全分支，留待按需处理。记录请求到达、生成结束、准入提交与下一次使用的时点。只有**首次生成已经完成且准入成功、后续请求相容并仍然有效**时，才把第二次计作缓存命中。同一串行用例下，主动维护可能把第一次生成移出前台关键路径，不能记成省掉两次生成；实际前台收益和后台成本分开报告。

### P1-2｜`DualVerify` 要给出在线可执行的必答检查

**位置：**Alg.3 第 219–231 行。

**问题与理由。** “全部主张有依据”可排除无据陈述，却检查不了必要内容遗漏；v4 加了完整性检查是正确的，但没有说明必答项从哪里来。若用题库金标、评测标签或 `gold_fact_spans` 来列必答项，就破坏了在线与评测信息隔离。

**修改建议。** 首版选定可复现的必答项来源，例如请求显式要求的实体、字段和时间范围，再按当前可见证据判断哪些项有据可答。无法可靠确定必答项或校验不通过时，按既定规则回退或不写入；不要因无法判定而自动通过。局部路线与完整路线使用同一校验口径，局部失败后的重生成和二次核验都计入成本。

### P1-3｜补全异步任务的输入与前台计时边界

**位置：**Alg.1 第 86、107–124 行。

**问题与理由。** 判官任务只有 ID、代次和版本时，若旧内容已被淘汰，未必还能取到当时的候选。异步后台执行不等于前台零开销：如果构造任务、取证据快照或入队发生在 `return` 前，这些操作仍占请求时间。

**修改建议。** 任务绑定可追溯的候选和证据快照引用或不可变载荷；二次复核遇到版本冲突不要直接记为语义误判，无兼容反馈时明确走不复用或既定冷启动分支。准入对象记录其实际使用的数据版本，不能只凭请求进入时的 `G_snap.ver` 推断其所有依赖。前台记录实际发生的入队等开销，后台单独记调度、判官与维护成本。保留“经验门控不提供风险上界”及全流、已复用样本各自的错误率分母。

## 4. 实验对照与证据状态

| 项目 | 欠缺与建议 |
| --- | --- |
| **C2：分开验证池内集合估值与跨池需求联动** | “独立估值 vs. 集合估值”检验池内边际建模，不能单独归因于 `resp` 短路对下游估值的作用。另做一组消融：固定预算向量、候选规则、线上复用、池内替换算法及输入流，仅切换下游**调度估值**是否纳入 `resp` 短路。关闭联动的一组仍应在实际回放中执行同样的上游复用规则。报告下游准入变化、整体时延和质量。 |
| **C2：补写容量百分比的分母** | 明确每个池 10%／25%／50% 相对何种参考规模、去重及取整规则。可在独立校准流上确定各池参考逻辑规模；`rag` 按证据块、其他池按条目。所有比较方法共用相同的绝对配额向量，且不允许池间借用容量。 |
| **C3：保留两组配对对照** | 主动完整重生成 vs. 按需完整重生成，用于检验提前执行；局部修复 vs. 完整重生成，在相同更新、待修对象、证据和核验标准下比较。记录核验失败、回退和未再被访问的预修复对象。避免把同一更新下的多条回答当成独立样本。 |
| **C1／C4：指标与结论范围** | C1 保留借用、平滑的独立开关和实际可借比例。C4 用相同容量约束和硬检查的强组合基线，分别报前台净节省、P95、正确率、后台开销与总费用。未建模资源争用时，不把回放 goodput 解释为系统吞吐极限；未覆盖通知延迟时，不从零违规推断无风险。 |

**标定状态。** 两份 `real_calibration_300.csv` 的 SHA-256 一致，均为 300 条阶段计时与 Token 记录，无需再同步；这些记录不能单独提供全部反事实路径耗时。[成本表的局部改写行](/Q:/workspace/2026Spring2Winter/MasterGraduationProject/dataset/costs/path_costs.csv#L196)仍引用 `plan` P50 代理值。应另做局部改写、完整重生成、双检及失败回退的配对实测。约 73% 的低主张影响比例仍只是构造数据统计，不能写成修复成功率。
