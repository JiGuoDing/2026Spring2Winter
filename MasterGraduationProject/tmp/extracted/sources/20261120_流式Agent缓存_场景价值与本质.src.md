缓存不是提速开关。它是 Agent 与时间签的一份契约：记什么、记多久、何时忘。

## 适用边界：四条同时成立才值得用

它把 Agent 变成流里的一个有状态算子。不是给 Flink 加一个函数调用。

| 要素 | 含义 | 不满足时 |
| --- | --- | --- |
| 事件驱动 | 没有人在提问，事件在推系统 | 单次问答 |
| 长时程 | 判断跨分钟到天 | 一次请求内出结果 |
| 有状态 | 按实体累积上下文 | 无状态工具 |
| 高并发 | 要背压、扩缩容、自愈 | 内部低 QPS 工具 |

只中一两条时，普通服务更省事。

## 交互场景：异步可行，同步聊天不行

| 形态 | 匹配度 | 原因 |
| --- | --- | --- |
| 人工审批回流 | ok 高 | 人也是事件源 |
| 系统主动对话 | ok 高 | 交互由事件触发 |
| 慢通道客服 | warn 中 | 秒到小时可接受 |
| 同步多轮聊天 | no 低 | 缺 token 流与请求亲和 |

Agent 不会阻塞等一个人。案件留在 keyed state，人批完，结论作为事件回流。

## 深例：风控案件侦查的两层架构

关键判断：Agent 不进支付主链路。授权有 100ms 预算。

```flow LR
交易事件 -> 规则与模型层
规则与模型层 -> 放行
规则与模型层 -> 开案件
开案件 -> 侦查Agent
侦查Agent -> 并行取证
并行取证 -> 侦查Agent
侦查Agent -> 策略判定
策略判定 -> 冻结处置
策略判定 -> 持续跟踪
持续跟踪 -> 侦查Agent: 新事件回流
```

第一层毫秒级，确定性可回滚。第二层秒到小时级，负责侦查与跟踪。

## 缓存分四层，风险完全不同

| 层 | 缓存什么 | 落在哪 | 风险 |
| --- | --- | --- | --- |
| 参考数据 | 名单、商户档案 | 广播状态 | ok 低 |
| 实体画像 | 设备与账户特征 | Flink State 加 TTL | warn 中 |
| 证据 | 图扩线结果 | 带版本的状态 | warn 中高 |
| 推理 | 前缀与分类结果 | 模型侧与应用侧 | no 高 |

框架自带两层缓存。短期记忆由 Flink State 支撑，可以过期。Action State Store 只在恢复时复用。

## 风控里该缓存什么

一条铁律：缓存事实，不缓存判断。

| 动作 | 重复度 | 能缓存 | 说明 |
| --- | --- | --- | --- |
| 名单筛查 | 每案必查 | no | 改用广播状态 |
| 商户档案 | 极高 | ok | 长 TTL 加 CDC 失效 |
| 实体画像 | 高 | ok | 优先放 Flink State |
| 图扩线 | 中高 | ok | 键带版本号 |
| 相似案件 | 中 | ok | 这是长期记忆 |
| 处置动作 | 低 | no | 绝不缓存 |

漏放比误杀贵。「放行」类结论只能用短 TTL。

## 价值分三层

第一层省钱，第二层决定能不能做，第三层决定敢不敢上线。

| 层 | 价值 | 度量 | 不做会怎样 |
| --- | --- | --- | --- |
| 省资源 | token、下游 QPS | 账单对比 | 贵，但能跑 |
| 撑形态 | 长时程与突发 | 峰值下的 P99 | 形态不成立 |
| 定语义 | 新鲜度与回放 | 回放一致性 | 不敢上线 |

案件跨 72 小时，就要反复取证。事件越多，成本越上涨。缓存把它压成常数。

## 量级：高端模型下必须做

按日 3 万案件估算，仅用于说明量级。

```chart bar unit=万元
| 缓存前 | 缓存后
中档模型 | 120 | 60
高档模型 | 750 | 375
```

中档模型下 ROI 约 2.4 倍，可做但要控人力。高档模型下约 15 倍，属于一期需求。

## 本质三层

经济层。缓存的本质是把成本单位从「事件」换成「变化」。同一商户被 2000 个案件查询，只算一次变化。

认识层。失效策略就是你对世界如何变化的建模。TTL 假设世界按时钟均匀变化，这是最粗的假设。

系统层。判断要可复现，但模型和外部系统都不可复现。唯一出路是把观察记下来。

```callout info 一个反转
缓存与审计不是对立面。缓存是短命的记录，审计日志是长命的记录。真正对立的是「记录」与「不记录」。
```

## 收尾：三个参数即是世界观

```callout ok 一句话
缓存的价值上限，等于业务里慢变量的占比。
```

设计缓存只回答三个问题：记什么、记多久、何时忘。技术选型只是这三个答案的写法。

真正的难点不是怎么缓存。是你敢在多长时间里相信一个旧事实。这个答案不在框架文档里，在业务对错误的容忍度里。
