顶层形式化：把全章收束为一个约束集合优化问题

导师觉得方案“像代码文档”，首要原因就是缺少一个统领全局的数学目标函数。在 1.2 节开头建立如下形式化问题定义后，后续所有模块不再是拍脑袋加的规则，而是该 NP-hard 问题的 principled 近似分解。

maxM, π U(M, π; H) = Eq ~ QH [ ΔT(q | M, π, Gt) / Tref ] + Σi ∈ M ψstruct(i) s.t. (1) 容量约束：Σi ∈ M ci ≤ B (2) 硬有效约束：∀ i ∈ M, Valid(i, Gt, perm(q)) = 1 (3) 质量风险约束：P(Err(q, i) | Reuse(q, i; π)) ≤ δ （针对语义回答候选）

为什么这个问题不 trivial（理论难点点题）？ 即使在静态离线设定下，该问题同时包含：① 背包容量约束（条目占用空间 ci 异质）；② 同类覆盖次模性（语义相近的 resp 边际增益递减）；③ 跨类型路径替代耦合（复用 resp 会短路下游 rag/act，目标函数非简单线性可加）；④ 流式非平稳漂移（更新流 ut 动态破坏约束 (2)）。因此精确求解为 NP-hard，必须将其解耦为在线风险门控（满足约束 2–3）、增量集合边际调度（近似求解约束 1 下的集合优化）与价值门控流式维护（应对状态漂移）三个子问题。

1.2.1 重构：消除数学套娃，用路径去重公式定义效用

原稿在 1.2.1(3) 中先算 Vbase，再对 resp 与 rag 加上 (Vresp − Vbase) / Tref，数学上直接把 Vbase 减掉了，显得像形式化拼凑。

重构后直接从单次请求的路径执行节省 ΔT(q | M) 出发：若 resp 命中则短路整条路径，下游阶段不再重复计省；若 resp 未命中，则累加实际命中的 plan、rag、act 净节省并扣除检查/回退额外开销。随后统一写成无冗余的两项效用：

U(i, H) = Ṽtime(i, H) / Tref + ψstruct(i) • 基础时间净节省：Vbase(i, H) = λ̂i · min(H, τirem) · Δt̄i − F̂i(H) • 校正时间项 Ṽtime：resp 取路径边际增量 Vresp；rag 取来源有效时长加权 Vrag；act/plan 取 Vbase • 结构质量偏好 ψstruct(i)：act 取 wact·min(di/Dref, 1)；plan 取 wplan·qi；resp/rag 为 0

注：通过将 Tref 标定为验证集上单条缓存时间净节省的参考分位（如 P90），保证时间分项与 ψstruct ∈ [0, w] 处于同一无量纲量级，彻底回应答辩评委对量纲对齐的质询。

1.2.2 重构：将零散步骤收敛为 Algorithm 1（级联短路与保守经验贝叶斯门控）

原稿 1.2.2 存在两个薄弱点：一是四类对象的查询顺序未形式化为级联状态机；二是风险估计直接采用点估计 p̂i = (ei + m·pc) / (ni + m)，在小样本且 ei = 0, pc = 0 时会过于乐观地以 1 − ε 概率直接放行。重构后引入保守先验平滑（α0, β0）与显式冷启动门槛 Nmin，使风险门控在样本稀疏期具备统计稳健性。

Algorithm 1: 在线级联检索与版本感知经验贝叶斯风险门控（CascadeReuse）
输入：当前请求 q_t，缓存集合 M，版本依赖图 G_t，风险目标 δ，最低抽样率 ε，冷启动门槛 N_min，先验 (α_0, β_0)　|　输出：回答 y_t
1: cand ← RetrieveResp(M, q_t)                                      // 优先精确键，其次按相似度分桶 B_k 语义召回
2: if cand ≠ ∅ and HardValid(cand, q_t, G_t) then
3:     if cand.is_exact then return CommitCheck(cand, G_t)          // 精确命中直接复核版本后返回
4:     (e_i, n_i, p_c, m) ← FetchClusterStats(cand, B_k, G_t)       // 仅借用同簇、同桶、版本一致标注
5:     if n_i + m ≥ N_min then
6:         p̃_i ← (e_i + m·p_c + α_0) / (n_i + m + α_0 + β_0)       // 保守经验贝叶斯风险估计
7:         r ← ε if p̃_i ≤ δ else max(ε, 1 − δ / p̃_i)
8:         if Uniform(0,1) > r and CommitCheck(cand, G_t) then return cand.resp
9: y_t ← CascadeExecute(q_t, M, G_t)                                // 依次尝试复用 plan → rag → act 并补全生成
10: AsyncUpdateJudgeAndAdmit(q_t, cand, y_t, M, G_t)                // 异步判官更新统计，调用 Alg.2 评估准入
11: return y_t

1.3 重构：增量受影响子集剪枝（Alg.2）与两级价值门控修复（Alg.3）

这是整篇论文最能体现算法深度与系统原创性的部分。我们同时解决原稿两处最易被审稿人击穿的硬伤：① 用受影响请求子集剪枝 Qaff(i, E) 把集合边际增益 ΔS 的在线计算从全量重放降至局部增量计算；② 在更新修复前焊入 1.2.1 价值门控与主张变更比例 ρi 期望代价路由，避免对 600 条冷门回答白做重检和 LLM 修复。

Algorithm 2: 增量集合边际准入淘汰（IncSetSchedule）
1: if ¬HardValid(i, G_t) then return Reject
2: E ← CleanExpired(M, G_t)
3: while Cost(M \ E) + c_i > B do
4:     j* ← argminj ∈ M\E  LossQ_aff(j)(j) / c_j
5:     E ← E ∪ {j*}
6: Q_aff ← InvertLookup(Q_rep, i, E)      // 局部剪枝
7: ΔS ← EvalDelta(Q_aff, M, i, E)
8: if ΔS > 0 then M ← (M \ E) ∪ {i}
Algorithm 3: 价值门控修复与条件提交（ValueGatedRepair）
1: A ← ReverseIndex(G_t, u_t); Suspend(A)
2: for each i ∈ A do
3:     if U(i, H)·T_ref ≤ C_rep then Drop(i); continue
4:     v_snap ← G_t.ver; ΔE ← ReRetrieve(i, v_snap)
5:     if ΔE = ∅ and G_t.ver == v_snap then Resume(i)
6:     ρ_i ← |C_aff(i, ΔE)| / |C_all(i)|
7:     y' ← LocalRepair if (ρ_i ≤ θ ∧ E[C_loc] < C_full) else FullRegen
8:     if Verify(y') then CAS_Admit(y', v_snap, Alg2)
