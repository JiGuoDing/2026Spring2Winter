## A 怎么用这组材料

- `paper_source/` 存原文 PDF，文件名与解读页 A 面板一致。
- `paper_ interpretation/` 存每篇的 `*_解读.html` 与 `*_解读.md`。
- 每篇解读的 A 面板给出完整出处；F 面板给出证据边界。
- 预印本与正式版分开标注；引用前先核对版本。

```kv
* 论文数: 31
* 正式发表: 22
* 预印本 / workshop: 9
* 覆盖类型: resp、ctx、rag、plan、风险与评测
```

## B 三类缓存地图

```flow
resp 回答缓存 -> 质量预算: vCache / Krites / SISO / GenCache
ctx 上下文缓存 -> 保留与驱逐: KVFlow / Continuum / Marconi / Pie
rag 知识缓存 -> 新鲜度与依赖: RAGCache / Cache-Craft / FreshCache / FinCacheServe
```

三层共享同一组决策：是否准入、保留多久、先删谁、何时刷新、是否预取。差别在收益与风险的度量方式。

## D 阅读顺序与证据边界

**先读 5 篇。** vCache → Cortex → RAGCache → KVFlow → Continuum。

- vCache 给回答缓存的质量约束。
- Cortex 给知识缓存的语义命中。
- RAGCache 给 RAG 缓存的价值密度。
- KVFlow 给上下文缓存的未来复用概率。
- Continuum 给工具暂停期的 TTL。

**按主题补读。**

- 价值建模：Marconi、AdaptCache、KV Cache Cost Model、FinCacheServe。
- 生命周期：CacheTTL/Continuum、KVFlow、FreshCache、MemoryOS。
- 多租户与安全：PromptPeek、KVShare、Cortex。
- 评测：SCBench。
- 计划缓存：APC、AWM、GenCache。

**证据边界。**

- 22 篇有正式会议/期刊版本；9 篇是预印本或 workshop。
- 预印本的数字可能随版本变化。引用时写 arXiv 编号与版本号。
- 论文没有给出代码或 trace 时，解读页会明确写“未发现”，不把复现当成事实。
- 论文的 headline 数字通常有特定负载条件；解读页 D 面板给出设置，F 面板给出边界。
