Pensieve 的缓存逻辑可以概括为：请求结束后不释放 KV，按 32 token 分块放进 GPU/CPU 两级缓存；GPU 紧张时按 `V = Cost / T` 把块换到 CPU，CPU 满时按同一分数丢弃；下次请求按“丢弃段重算、CPU 段换入、GPU 段复用、新 prompt 计算”四段恢复。

## A 缓存对象：不是整段会话，而是 32-token 的 KV 块

- 对象：每一层 Transformer 的 K/V 张量，按 token 位置切块。
- 块大小：实验取 32 token，可配置。块太大，换入换出粒度粗；太小，决策和 PCIe 传输开销高。
- 为什么按块：整段会话换出浪费空间、延迟大；按单 token 换出又太碎。
- 规模：13B GPT-3，40 层、hidden 5120、FP16，每个 token 的 KV 约 0.78MB。2K token 的会话约 1.6GB；GPU 40GB KV 只能放几十到几百段会话。
- 结论：GPU 只能做一级缓存，必须有 CPU 二级缓存；磁盘太慢，论文不做。

```flow
会话历史 -> 32-token KV 块
32-token KV 块 -> GPU 一级缓存
GPU 一级缓存 -> CPU 二级缓存: 容量压力
CPU 二级缓存 -> 丢弃: CPU 满
丢弃 -> 重算: 取回原文
```

## B 一次请求的上下文有四种段落

Pensieve 的命中不是“整段上下文命中/不命中”，而是把请求拆成四段，分别处理。

| 段 | 位置 | 恢复方式 | 相对成本 |
|:--|:--|:--|:--|
| 最早段 | 已丢弃 | 从持久化历史取原文，重算 | 低：因果注意力下前部上下文短 |
| 中段 | CPU 二级缓存 | 换入 GPU | PCIe 传输 |
| 近段 | GPU 一级缓存 | 直接复用 | 近零 |
| 新 prompt | 未处理 | 正常 prefill | 正常 |

这解释了为什么 Pensieve 可以只缓存“部分上下文”。它不要求整段会话都在 GPU；缺哪段，就用换入或重算补哪段。

## C 写入与保留：请求结束不释放 KV

传统 serving 把 GPU KV 缓存当“请求工作区”：请求结束，槽位立即释放。Pensieve 把它同时当“已完成会话的存储”。

- 请求结束后，KV-token 继续留在 GPU。
- 调度器持续跟踪空闲 GPU 槽位。
- 当空闲槽位低于阈值（例如 25%），调度器让 worker 把选中的块提前复制到 CPU。
- GPU 槽位是惰性回收：直到这些槽位真的要分配给别的会话，才真正释放。
- CPU 也满时，用同一套 `V` 策略决定丢弃哪些块。
- 没有准入过滤：所有块先留在 GPU，生命周期从“保留”开始，而不是从“是否缓存”开始。

这实际上是一个带惰性失效的写回缓存：换出时先复制到 CPU，GPU 副本在槽位被重新分配前仍然存在。

## D 驱逐：`V = Cost / T` 把两种偏好放进同一个分数

Pensieve 给每个块算一个保留价值：

$$
V=\frac{\mathrm{Cost}(s,l)}{T}
$$

其中 `Cost(s,l)` 是块大小 `s`、上下文长度 `l` 时的重算成本；`T` 是会话最后一次活跃至今的时间。`V` 越小，越先被驱逐。

重算成本拆成注意力部分和非注意力部分：

$$
\mathrm{Cost}(s,l)=\mathrm{Cost}_{attention}(s,l)+\mathrm{Cost}_{other}(s)
$$

非注意力部分与上下文长度无关。块大小固定为 32 后，公式简化为：

$$
\mathrm{Cost}(l)=\mathrm{Cost}_{attention}(l)+c
$$

`c` 是非注意力操作的常数。论文离线剖析 2 的幂次上下文长度，再用插值估计其他长度。

这个分数同时表达两种偏好：

- **会话级**：`T` 越大，整段会话的所有块 `V` 越小。越久没活跃，越先被换出或丢弃。这是 LRU 假设。
- **会话内位置级**：越靠前的块，注意力上下文越短，`Cost(l)` 越小，`V` 越小。所以同一会话里，头部块先被淘汰。
- **为什么头部便宜**：因果注意力下，前部 token 只 attend 更短的历史；后部 token 要 attend 更长的历史。论文实测注意力成本随上下文长度线性增长。
- **块大小固定时**：所有块大小相同，`V` 不需要再除以 `Size`；如果块大小可变，应改为 `V = Cost / (T × Size)`。

关键数字：在 3 req/s 以下，Pensieve 与 LRU 接近；超过后 Pensieve 更好。CPU 命中率高最多 4.4 个百分点，平均减少重算 KV-token 最多 14.6%。

## E 换入与重算：把恢复过程藏进计算

命中后，Pensieve 不是等所有层都换入再开始，而是按层流水：

- 第 `i` 层的 KV 到齐，就开始第 `i` 层的自注意力；用 GPU event 保证依赖。
- 换入的 KV 与原 KV 在 GPU 中不连续。Pensieve 扩展 PagedAttention 内核，支持多 token Query 和非连续 KV。
- 如果头部块已被丢弃，Query 张量会对应两段不连续的上下文。Pensieve 把它们当成两个共享同一 KV 上下文的子请求；只更新辅助元数据，不做内存拷贝。
- 这个内核也让 prefill 和 generation 可以放在同一个 batch 里，减少小内核调用，提高 GPU 利用率。

生成阶段仍可能缺 GPU 槽位，因为生成长度事先未知。Pensieve 的对策是：

- 保守预留 10% 的 GPU 槽位给正在生成的请求。
- 如果仍然不够，按到达时间从晚到早挂起请求，把它们的 KV 换到 CPU，再放回等待队列。
- 挂起会增加延迟，所以 10% 预留是避免频繁挂起的保护带。

## F 一个具体例子

假设会话 C 有 8 个块（0–7），每块 32 token。当前 GPU 存 5–7，CPU 存 2–4，0–1 已丢弃。新请求带 20 个新 token。

| 步骤 | 发生什么 |
|:--|:--|
| 1 | 调度器发现请求缺 3 个 CPU 块、2 个丢弃块，还要放新 prompt。 |
| 2 | 如果 GPU 空闲低于 25%，先按 `V` 从其他会话选最低的块换到 CPU。 |
| 3 | 如果 CPU 也满，按同一 `V` 丢弃最低的块；通常是更老会话的头部块。 |
| 4 | 2–4 从 CPU 按层换入；0–1 从持久化历史取原文重算。 |
| 5 | Query 张量分成“重算的 0–1”和“新 prompt”两段，作为两个子请求处理。 |
| 6 | 生成的新 KV 追加到会话；GPU 保留最近块，CPU 保留中段，最早的可能再次被丢弃。 |

这个例子说明：Pensieve 的缓存命中是“分段命中”，驱逐是“块级驱逐”，恢复是“换入 + 重算”混合。

## G 对第一章的用法与边界

| 维度 | Pensieve 的做法 | 对第一章的启示 | 缺口 |
|:--|:--|:--|:--|
| 缓存对象 | `ctx`：32-token KV 块 | 块级对象，适合做价值密度 | 无语义复用，只认精确前缀 |
| 价值建模 | `V = Cost / T` | 收益=重算成本，时间=复用概率代理 | 无质量风险、无验证成本、存储/传输成本未显式进入目标 |
| 生命周期 | GPU → CPU → 丢弃；无准入；无 TTL | 容量压力驱动的状态机 | 没有“写入/不写入”的准入，没有刷新/失效 |
| 多租户 | 单会话、单机 | 精确复用安全，可作为质量基线 | 无租户隔离、公平性、跨会话共享 |
| Flink 映射 | 单机 scheduler 管理槽位 | `MapState<chunkId, meta>` 存层、成本、最后活跃；timer 推进 `T`；KV 张量外置 | 跨 worker 的一致性、checkpoint 与扩缩容未覆盖 |

```callout info 最值得借鉴的点
不是 32 这个数字，而是把“物理位置、重算成本、空闲时间”放进同一个优先级。它让缓存驱逐从“最近有没有用”变成“保留它值不值”。
```

一句话总结：Pensieve 用块级 KV 把会话缓存做成了一个两级、可部分命中的生命周期系统；它的价值函数简单但完整，正好可以作为第一章 `ctx` 缓存的“精确复用基线”。
