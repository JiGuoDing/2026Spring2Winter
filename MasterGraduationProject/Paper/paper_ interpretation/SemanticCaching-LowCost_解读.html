B

系统模型

系统有 m 个不同查询：

𝒬={q1,…,qm}.

每个查询有两个未知量：

  • p(q)：到达概率，且 ∑qp(q)=1。
  • c(q)：调用 LLM 的期望成本，归一化到 [0,1]。

缓存集合为：

ℳ⊆𝒬,|ℳ|≤k.

查询 q 到达后，系统有两种动作：

  • 调用 LLM：支付 c(q)。
  • 复用最近缓存项：支付失配成本 d(q,ℳ)。

其中：

d(q,ℳ)=minu∈ℳ⁡d(q,u).

系统采用最优即时动作：

min⁡{c(q),d(q,ℳ)}.

期望损失是：

ℓ(ℳ;𝒑,𝒄,d)=∑q∈𝒬p(q)min⁡{c(q),d(q,ℳ)}.

优化目标是：

ℳ∗=arg⁡minℳ⊆𝒬,|ℳ|≤k⁡ℓ(ℳ;𝒑,𝒄,d).

关键区别： d 是“复用旧回答的效用损失”，不是“回答正确的概率”。论文默认距离可以代表失配代价。

B.1 两个特例

设定 距离定义 退化结果
Exact-match cache 只有同一查询距离为 0 传统精确匹配缓存
Bipartite coverage 阈值内距离为 0，否则为 1 查询覆盖问题
一般语义缓存 任意度量 d(q,u) 带软失配代价的集合优化

Bipartite coverage 特例用于证明 NP-hardness。

C

已知参数：Reverse Greedy

即使 p 和 c 全部已知，最优缓存仍很难求。

论文证明：

该优化问题是 NP-hard。

原因可从阈值距离特例看出：它等价于二部图上的最大顶点覆盖类问题。

C.1 损失函数性质

论文证明 ℓ(ℳ)：

  • 对集合 ℳ 单调不增。
  • 对集合 ℳ 超模（supermodular）。

直观含义：

  • 加入更多缓存项，损失不会上升。
  • 缓存越大，新增一项带来的边际损失下降越小。

这适合反向贪心，而不是普通前向贪心。

C.2 算法过程

算法从 𝒬 开始。每轮删除一个查询：

qi=arg⁡minq∈ℳi−1⁡ℓ(ℳi−1∖{q}).

直到剩余 k 项。

C.3 近似保证

设曲率为：

c=1−minq∈𝒬⁡ℓ(𝒬∖{q})−ℓ(𝒬)ℓ(⌀)−ℓ({q}).

令：

β=c1−c.

Reverse Greedy 返回的 ℳ 满足：

ℓ(ℳ)≤eβ−1βℓ(ℳ∗).

当曲率 c=0 时，损失近似可加，比值为 1。曲率越大，保证越松。

注意：这里不是常见的 1−1/e 子模最大化保证。目标函数是超模最小化，界依赖曲率。

D

离线学习：CUCB-SC

离线场景有一批历史数据：

𝒟={(ℳt,qt,Ct)}t=1n.

反馈是不完整的：

  • 每次查询都会观察 qt，因此可估计 p(q)。
  • 只有调用 LLM 时才观察 Ct(q)。
  • 缓存命中时没有真实服务成本。

论文定义成本反馈概率：

ν(q)=Pr⁡[Ct≠⌀|qt=q].

若某查询总被缓存，它的 c(q) 就缺少样本。ν(q) 很小会放大估计误差。

D.1 为什么用 UCB

CUCB-SC 用成本上置信界：

c‾(q)=cˆ(q)+log⁡(6mn/δ)2Nc(q).

这里是“悲观”估计：

  • 成本估高。
  • 不确定查询会被视为更贵。
  • 可避免因低估成本而错误缓存。

注意：成本越高，越不值得缓存；所以上界在损失最小化语境下是保守选择。

D.3 离线子最优界

定理给出近似误差：

SubOpt⁡(ℳˆ)≤42∑q∈𝒬1ν(q)log⁡(6mnδ)n.

因此：

  • 随样本量 n 增加，误差按 O~(m/n) 下降。
  • 成本反馈越稀缺，即 ν(q) 越小，误差越大。
  • 查询种类 m 越多，估计难度越高。
E

在线学习：CLCB-SC-LS

在线场景中，系统边服务边学习。缓存更新有切换成本。

E.1 在线遗憾

令每轮缓存为 ℳt。新增缓存项需要调用 LLM 填充答案。

带切换成本的遗憾为：

Reg⁡(T)=𝔼[∑t=1Tℓ(ℳt)+∑q∈ℳt∖ℳt−1c(q)]−∑t=1Tαℓ(ℳ∗).

α 是 Reverse Greedy 的近似因子。

不能每轮重建缓存。否则切换成本会线性增长。

E.2 低切换机制

CLCB-SC-LS 为成本估计和到达概率估计分别设置阶段。

只有观测数跨过阈值才触发缓存更新：

  1. 1查询到达记录 q_t
  2. 2判断阶段成本反馈或到达样本是否足够
  3. 3触发切换用当前估计重建缓存
  4. 4填充新项对新缓存项调用 LLM
  5. 5LCB 比较判断调用 LLM 还是复用
  6. 6更新统计观察到成本时才更新 c 估计
  7. 7进入下一轮保持缓存直到下次阶段切换

阶段阈值随累计观测增长。这样切换次数被压到次线性规模。

E.3 为什么用 LCB

在线算法使用成本下置信界：

ct(q)=cˆt(q)−2log⁡(4mT/δ)Nc,t(q).

这是“乐观”估计：

  • 成本估低。
  • LLM 调用看起来更便宜。
  • 不确定查询更可能被真实查询，从而获得成本反馈。

当：

ct(qt)<d(qt,ℳt)

时调用 LLM。否则复用缓存。

E.4 切换次数

论文证明：

𝔼[∑q∈𝒬τq(T)]=O(mlog⁡log⁡T),
𝔼[τp(T)]=O(log⁡log⁡T).

τq 是查询成本阶段数。τp 是全局到达概率阶段数。

阶段式更新让缓存切换为 O(mlog⁡log⁡T)，而不是每轮都切换。

G.2 主要结果

实验 结果
Reverse Greedy vs Brute Force m=20 时几乎完全重合
Offline CUCB-SC 和 CLCB-SC 优于 Epsilon Greedy
Online regret 相比最强 Epsilon Greedy 至少改善 11.75%

G.3 如何读这些数字

结果支持：

  • Reverse Greedy 在小规模合成缓存上非常有竞争力。
  • 低切换设计没有明显破坏在线遗憾。
  • 阶段更新降低运行和切换开销。

结果不支持：

  • 在真实 LLM 生产流量上同样有效。
  • 在倾斜分布、无限查询集或多模态查询上同样有效。
  • 在 freshness、权限和事实正确性约束下同样安全。
实验边界

实验只有 m=20 个合成查询，成本用查询 token 数近似，查询均匀到达。它验证了算法方向，不是生产 trace 复现。

评价、边界与第一章用法

H.1 主要贡献

  • 把语义缓存写成统一的集合优化问题。
  • 显式加入失配成本，连接语义复用和回源成本。
  • 同时覆盖 Oracle、Offline、Online 三种信息设定。
  • 给出近似、子最优和 regret 三类保证。
  • 在线算法显式控制缓存切换成本。

H.4 对第一章最有价值的连接

这篇论文可以直接支撑第一章的“集合层价值优化”：

  1. 把缓存选择写成预算问题：目标不是单条命中率，而是整组缓存的期望损失。
  2. 显式分离收益和风险：回源成本 c(q) 与失配损失 d(q,ℳ) 竞争。
  3. 把未观测反馈计入学习成本：缓存命中时不观察真实成本，会形成反馈偏差。
  4. 把切换成本纳入控制器：扩容、驱逐和重建不是免费的。
  5. 提供离线到在线的过渡模板：历史日志先冷启动，线上再用低切换算法校准。

H.5 论文尚未解决、适合扩展的地方

  • 用校准后的 q_wrong × L_answer 替换原始 embedding 距离。
  • 把固定 k 扩展为多级别、异构字节预算。
  • 把平稳分布扩展为负载漂移和概念漂移。
  • 把有限查询集扩展到连续 embedding 或开放世界。
  • 把成本 c(q) 从 token 数扩展为 GPU-ms、检索调用和 SLO 违约损失。
  • 把 TTL、文档版本、ACL 和依赖失效纳入集合优化。
  • 把离线日志估计和在线反馈组合成混合控制策略。
tip 第一章建议

把这篇论文当作“缓存集合层”的理论基线。MVR/vCache 负责判断单条缓存是否可信。Reverse Greedy 负责在容量 k 下选择保留对象。Flink 生命周期研究再补足版本、新鲜度、迁移和负载价格。

H.6 最终判断

这篇论文是语义缓存理论化的重要基线。它的优点是把语义复用写成可证明的集合优化和在线学习问题。

它的局限也很清楚：距离代理、有限查询空间、平稳假设和合成实验。这些局限正好为第一章的“校准风险 + 依赖感知生命周期 + 流式状态”留下空间。
